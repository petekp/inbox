# Releasing: the Herdr app live pass

Part of [Releasing](release.md), step 4. Run it after the other looks, with the same sample project and test machine.

The Herdr app draws the inbox in a panel beside a terminal, for a host that runs in one of the app's terminals: Claude Code, the Codex CLI or omp. An app terminal has `HC_TERMINAL_ID` set, and a host outside one publishes nothing for the panel. So does a host whose terminal also has `HERDR_PANE_ID` set, since the multiplexer's report wins. Start each host with that variable unset. Note the Herdr version. The panel draws the Status tab in every build, with or without a `.next-build` file in the mod's folder. Run the Install and Update rows below first. Then run the Question, Task, Finding, Status, Collapse, Empty tabs, PR order, Reply while closing, PRs, Resume and Agent replies rows once with each host, and read the results in the panel. Run the other rows last.

| Check | Do | Expect |
| --- | --- | --- |
| Mod check | From the checkout, run `herdr-app check herdr/mods/inbox` with the newest Herdr. | It exits 0 and reports nothing wrong. |
| Install | With no `mods/inbox` and no `<app home>/inbox/herdr-mod.json`, start a host in an app terminal and run `/inbox`. Press Install. Claude Code asks in its inbox pane. omp asks in a row at the top of its Asks tab. The ChatGPT app asks in its Inbox tab. The Codex CLI never asks, and installs only after another host or the Inbox tab saved a yes. Delete `mods/inbox` and `herdr-mod.json` before the next host. | `/inbox` opens the host's own inbox pane and says why. The question "Install the inbox's Herdr mod?" shows once. Install shows "Installing the inbox mod in Herdr…", then "✓ Installed the inbox mod in Herdr." `mods/inbox/` holds `main.js` and `mod.json`, and `herdr-mod.json` reads `installed`. Once one host installed, no other asks. |
| Decline | Press Don't install, then run `/inbox herdr`. | The answer reads "Run /inbox herdr to install it later." Nothing is written to `mods/`, and `/inbox herdr` asks again. |
| Update | With the panel open, copy `main.js` and `mod.json` from an older commit that changed `main.js` in `herdr/mods/inbox` into `mods/inbox/`. Start Claude Code, then omp. Then reinstall the Codex plugin with `codex plugin add inbox@inbox`. Put the old copy back before each. | Each host puts the shipped build back. The run decides whether the open panel redraws it with no Herdr restart. A `mods/inbox` that is a link is left alone. |
| Sweep | Copy a live session's file to `<app home>/inbox/sessions/old.json`, set its `sessionId` to `old` and set its `writtenAt` to two days ago. The sweep keeps a file whose `sessionId` does not match its name. Add a `presses/old/` folder. Start a host. A second step: add `presses/orphan/` with no session file. | `old.json` and `presses/old/` are gone, since no terminal's label names `old`, its `writtenAt` is over 24 hours old and another terminal published it. `presses/orphan/` stays. The files of a live session stay. |
| Open | Run `/inbox` in Claude Code or omp, and press Open inbox on Claude Code's band. The Codex CLI has no command. Split a pane for it with `herdr-app do pane.split '{"direction":"right","pane":"<pane id>","mod":"inbox"}'`, taking the id from `herdr-app ls`. Then run `/inbox` again, close the panel and run it once more. | The panel opens to the right of the terminal and the host's own pane stays closed. The replies read "Opened the inbox in Herdr, to the right of this terminal.", then "The inbox is already open in Herdr. Focused it.", and the last run opens a new panel. |
| Following | Start two sessions in two terminals of one tab and focus each. Then focus the panel, focus a shell terminal, and end a session. | The panel shows the focused terminal's session and keeps the last one while it has focus itself. A shell reads "No inbox in this terminal" and names its program. An ended session reads as ended. |
| Tabs | Open each tab with a click and with ← →. | Status, Asks, Finds and PRs show in words. Asks, Finds and PRs show their counts, and Status shows none. |
| Presses | Press an answer on a question and a task's copy step. On a finding, press Explain, then Dismiss and Undo. Capture right after each press. | Every button on the pressed row draws out and the row reads "Sending…". Then the row shows its ✓, and the agent gets the answer as your message. Copy reads "✓ Copied" and Undo brings the row back. |
| Undo fill | Dismiss a row, and capture its Undo about 1, 2.5 and 4 seconds after the press. Dismiss a PR on the PRs tab and leave it alone. | Each capture shows Undo's fill at the share of its time that is left, about 80%, 50% and 20% of its width. The PR's Undo goes when its time runs out, with nothing else redrawn. |
| Delegate through hc | In an app terminal, have the agent start a second agent as a child terminal with `hc run --bg`, with a task that takes a minute. Start a plain shell the same way. Open the Status while they run, and again after they finish. | The agent shows under its work as working, and as finished once it is ready. A blocked or errored agent reads blocked. The shell shows no row. |
| Press nobody takes | Stop the host with `kill -STOP <pid>`, press Done on a row, wait 20 seconds, and resume it with `kill -CONT <pid>`. | After 15 seconds the row reads as not applied and its press file is gone from `<app home>/inbox/presses/<session id>/`, so nothing applies it on resume. |
| Reply field | Press Reply on an Asks row, type, and press Send. Open it again, type, press Escape, then switch tabs and back. | The typing goes into the field. Send sends it as your message and closes the field. Escape and a tab change close the field and keep the draft. |
| Keys | Click a row, then press `j`, `k`, `z`, one of its hotkeys and ← →. Press `j` on the last row, `k` on the first, and `j` and `k` with nothing selected. Dismiss a row, select another, and press `u`. Press Escape. | `j` and `k` select the next and previous row and wrap from the last row to the first and back. With nothing selected, `j` picks the first row and `k` the last. `z` collapses the selected row and expands it again. A hotkey presses its button, and ← → switch tabs. `u` presses the Undo of the row that closed last on the tab, whichever row is selected. Escape closes an open field first, then gives focus back to the agent's terminal. |
| Help | Press Help at the right end of the tab row on each tab. | Help replaces the tab and lists its keys and marks. The Help tab is selected and the four tabs are not. The page is the same on every tab: ← →, `j` `k`, `z`, the fold-all key, `u`, the PRs tab's `g` and `m`, and Escape. It lists no row hotkeys. A second press on Help, or a press on any tab, brings the tab back. |
| PRs tab | Open the tab with `gh` signed in and a merged PR, other than the branch's own, on it. Press Clear merged and closed. Then rename `gh`, reopen the tab, and press Refresh PRs. | Your PRs show, and the merged one clears. With `gh` renamed and PRs on the tab, a banner says the inbox could not find `gh`, with Refresh PRs at its right end. With no PRs on the tab, that text is the empty tab's hint, centred, with Refresh PRs under it and no banner. |
| Themes and width | Open the panel in Herdr's light and dark themes, at a pane under 280 px and at about 420 px. Capture a Dismiss and its Undo mid-move. | No text is cut off. No button shifts while its press is out. A row fades in and out while its height, the space around it and a closing title's wrap glide on springs with no jump, a running mark fades, and nothing flickers. The run decides whether any text is cut off, whether anything flickers, and whether both themes read. |
| Scroll edges | With more blocks than the panel is tall, scroll the list to its middle, then to its end. Click a button that sits under the bottom fade, and one under the top fade. | The list fades toward the tab row at its top and toward the panel's bottom edge, never the other way. Each click presses its button. At the end of the scroll, the last block sits clear of the bottom fade. The run decides all three: no check has seen them in the app. |
| Reload omp | In an app terminal, open the panel for an omp session, reload the inbox extension in that omp session, then press Done in the panel. Read `herdr.log`. | The run decides whether omp reloads without a shutdown. If it does, the press must apply once and the panel must redraw. If the panel does not redraw, or an Answer fails, the old extension still watches the press folder. |
| Ended Codex thread | End a Codex CLI session in an app terminal and start another. Press Answer on the first session's row before the second writes. Then press Answer on a running Codex CLI session's row. | The run decides what `codex queue` does for an ended thread. With Codex 0.166.0 or later, the message may resume the thread and reach it. Record which happens. The row must not read as sent when the message reaches no one. The second message reaches the running session. |
| Status seen | Waiting on PR #400, so this cannot pass on `next`, where nothing in the panel reports a look at the Status. Once it merges, give a session finished work on its Status. Show the Status with every row on screen for 5 seconds, then leave it. | Finished rows fold into "N done", or "N more done" while new finished rows show above it, and "was" lines clear. A look shorter than 5 seconds counts nothing, and a row that was never on screen stays unfolded. |
