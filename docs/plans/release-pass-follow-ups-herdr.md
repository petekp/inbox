# Scripted release pass: Herdr frame harness follow-ups

Part of [Scripted release pass: follow-ups](release-pass-follow-ups.md).

Status: building. Each item stays until the change that does it lands.

The Herdr frame harness, `herdr/tests/frames.ts`, draws the Herdr pane frame by frame with a stand-in for gpui-kit. These are the ways it passes while the app fails, and the ways a capture of the real app shows a failure the app does not have.

- **The Herdr frame harness read a tree row's mark as its title.** Until the title fade change, the harness took `node.kids[1]` as a row's title text. In a tree row that node is the row's mark, so the title tests in `herdr/tests/glide.spec.ts` checked the mark and passed while every wrapped title was cut. The harness now finds the title by its text and its layer's id. No check fails when the harness reads the wrong node: a spec that asserts the title text it read is the row's title would catch it.
- **The Herdr frame harness draws only every 16 ms.** `framesOf` in `herdr/tests/frames.ts` draws on a fixed grid, but the app also draws at each time the mod schedules, such as a closing panel's `panelHeldUntil`. Drawing at those times too would have caught a row reopened 150 ms into its close: the box lets go at 136 ms in the app and keeps its speed, so the panel shows nothing at full height for about 300 ms. The harness let go at 156 ms instead, where the reopen came first and passed.
- **The Herdr frame harness finds gaps in tree lines that have faded out.** `gapsOf` in `herdr/tests/frames.ts` reads where each line starts and ends, but not its opacity. As a Status subject's fold shuts, its nested rows' lines fade to 0 before their space closes. The harness then reports a gap in the depth-1 column, in the space of the first nested row, where nothing shows. So the fold test in `herdr/tests/glide.spec.ts` checks jumps but not gaps. A gap check that skips a line whose shown opacity is 0 would let that test check gaps too. It would then catch a tree line that breaks while a fold shuts. The harness now keeps each tree line's fade in `StrokeFades` (`herdr/tests/stroke-fades.ts`), and `framesOf` returns it as `strokes`, but `gapsOf` does not read it yet.
- **No fuzz rule compares a tree column's fade with the blocks it joins.** `framesOf` returns each tree line's fade as `strokes`, and only `herdr/tests/status-undo.spec.ts` reads it. So a column that shows a frame after both of its blocks passes every fuzz run, as the path above a milestone does after Undo 150 ms after Remove (#1053). A rule that a column that joins two blocks shows at least as much as the fainter of them, less a small margin, would catch it. The same rule would catch a column that shows before either block.
- **Herdr frame bursts at 30 ms fake a squash or a one-frame close on a slower host.** Each `Herdr shot` costs the Herdr app about 20 to 25 ms. A burst that takes a shot every 30 ms can stall Herdr on a slower Mac. Its frames then show a row entering squashed, or closing in one frame, while the app draws the move right. A diagnosis on a second Mac showed it on 11-22. Capture every 45 ms instead. Reject a run when the fold starts more than about 450 ms after the click. Also reject it when the median shot lag passes about 35 ms, counting a shot's lag from its launch to its file's last write. A burst tool that logs each shot's lag and checks both limits would catch it.
- **The Herdr frame harness does not know how gpui-kit takes back a fade after its delay or a delayed slide.** A VM probe showed that gpui-kit starts a fade taken back during its delay from where the fade would be with no delay, and `retargetedFrom` in `herdr/tests/frames.ts` models that. It applies the same rule after the delay has ended, which no probe checked. No Herdr fade hands gpui-kit a delay now, so no test depends on it. A box's slide on `top` still has a delay, and the harness does not model taking it back. A VM probe of each case, as for the fade, would show whether a slide taken back during its delay jumps.
- **The Herdr frame harness reads a cut line's opacity from the nearest fade it knows.** `cuts` in `herdr/tests/frames.ts` takes the opacity of the nearest box whose id starts with a prefix in `FADE_PREFIXES` (`herdr/tests/fade-boxes.ts`). A line with its own fade under another id reads as its panel's opacity. `checkFadeIds` passes it, since the panel's id is listed. Until `warning ` was added, a stopped warning hidden at opacity 0 read as cut at 0.21 while its row closed. The same rule would miss a real cut of a line that shows while its panel is faint. Multiplying every fade above the line, as `shown` does, would catch both.
- **No Herdr frame test measures late.** `framesOf` takes `measureLagMs`, but no Herdr test sets it. A review of the stopped warning drew it with a 32 ms lag: the line faded in before its box opened, and was cut by up to 85%, since `enterDelayMs` got no height yet. This probably affects every line that comes under a row's buttons. It is not seen in the app: VM captures on 11-26 showed the warning's box open before its line. A come-and-go test at a lag of one or two frames would catch a line that shows before its box has room.
- **No check fails when a Status row's mark column goes blank.** #1030 was a mark that faded out and the new one faded in, so the column showed nothing for a moment. The `vanish` rule in `fuzz/rules-herdr-vanish.ts` counts a mark that turns into another as changed, and the settle test in `herdr/tests/glide-forms.spec.ts` drops every pop of a row's own marks. A rule that a row with a mark before and after a draw shows some mark at `CUT_OPACITY` or more in every frame between would catch #1030 coming back.
- **No Herdr check reads a sideways move.** `offSpringBy` in `herdr/tests/off-spring.ts` compares each box's `top` and `height` only. So a Status subject that jumps one nesting step sideways in one frame (#1056) passes the `jump` rule. Status lines, notes, done folds and their connectors now spring their left edge (`nestedEl` in `herdr/src/paint-parts.ts`, and the strokes in `herdr/src/paint-strokes.ts`), and nothing checks that spring. `segmentsOf` and `armsOf` in `herdr/tests/connector-gaps.ts` read each stroke's target `left`, so a stroke mid-slide beside one that stays counts as joined or apart only by where each will end. Comparing each box's left edge too, frame by frame, would catch a jump or a parted connector.
- The fuzz presses a button whose block is still moving, and the Herdr app ignores that click. In the VM, every Undo clicked earlier than about 220 ms after Remove was lost, so the #1034 seed's Undo 25 ms after Remove cannot happen live. Its fix still matters, since a host's answer can move the same lines. A fuzz click that skips buttons in a moving block would keep its seeds to what a person can do.
