# Live pass in the VM: follow-ups

Part of [Scripted release pass: follow-ups](release-pass-follow-ups.md). These are gaps in step 4 of `docs/release.md`, the live pass in the `inbox-ui` VM. Each item stays until the change that does it lands.

## Setting up the guest

- **Check the guest's Claude sign-ins before the pass starts.** In the 0.3.0 pass on b23bb169, both Claude sign-ins in the `inbox-ui` VM had expired. `claude auth status` read `loggedIn: false`, and the Claude app showed "Claude Code needs a new sign-in". Every Claude Code and desktop row then waited for the owner to sign in through Screen Sharing. A step in "3. Get the VM ready" that runs `claude auth status` in the guest and looks at the Claude app before the first row would catch an expired sign-in while the owner is still at hand.
- **Install Herdr in the VM when it is set up.** The `inbox-ui` VM had no Herdr app. The 0.3.0 pass copied the host's Herdr.app and herdr-core into the guest by hand, and the pass names no Herdr version to test. A setup step that installs the newest Herdr in the guest, with the version recorded, would catch a Herdr look that cannot be run at all, or one run on an old Herdr.
- **Hold the Claude app's version for the pass.** The Claude app updated itself from 4.4212.0 to 5.11492.5 at its restart during the 0.3.0 pass, so the desktop rows ran on two app versions, and the first issue report named the wrong one. The pass should record the app version at each desktop row, or turn off the app's updates for the pass.
- **Free the guest's disk.** The guest had 2.9 to 4.4 GB free during the 0.3.0 pass, and macOS showed "Your disk is almost full". A pass that copies builds and keeps captures can fill it mid-row. Setup should check `df -h ~` in the guest and clear old builds and caches first.
- **Give the guest a Claude sign-in with the plugin guard.** On Team and Enterprise sign-ins, and with a managed settings file, a guard runs ahead of user mods and skips the mod's `classic.*` hooks. In the 0.3.0 pass the guest was signed in to a personal plan and had no `/Library/Application Support/ClaudeCode/` folder, so the guard never loaded. A notice the owner saw on a guarded Mac when opening the pane from `/inbox` could not be reproduced, on the build under test or on v0.3.0. Setup should add a managed settings file that turns the guard on, or sign in to a Team account, so the desktop and terminal rows also run the guarded path.
- **Herdr themes need `appearance` in settings.json.** In the 0.3.0 pass, `herdr-app do app.theme` changed the drawn theme only after the app's `settings.json` named an `appearance`. The Themes and width row should say so, or a run reads one theme twice.

## Rows whose steps miss what they check

- **One question per turn in the Codex dialog step.** Asked for two questions, Codex put both in one two-page dialog. The step then cannot answer one question and close the other with its ✕, and the 0.2.14 pass needed an extra turn to check that a dialog closed unanswered leaves an Asks row. Asking for one question per turn would keep that check in the step. In the 0.3.0 pass on b23bb169, asked to "use your question tool", Codex recorded the question with the inbox's `record` tool and asked it in plain text, so no dialog opened. Naming the tool, `request_user_input_async`, opened one. The step should name it, or the run checks the Asks row of a recorded question instead of a dialog's.
- **The PRs row needs an open PR of yours.** A PR that is merged or closed when the inbox first reads it stays off the tab (`isLeftOut` in `hooks/pr-fetch.ts`), and so does one someone else wrote. In the 0.3.0 pass, linking two merged PRs left the Codex PRs tab empty, and the sample project has no remote, so the tab read "Could not read the PRs: no git remotes found". The row should say to link an open PR you wrote. Its `gh` step should also wait out `PR_SHARED_MS` (2 minutes) before reopening the tab, since a fetch no press asked for reuses a view read within that time. Without both, the row passes on an empty tab or fails on a cached view. The same sample project kept the Herdr PRs tab row from showing a PR's two forms and from running Clear merged and closed.
- **Press Undo before the capture.** The Finding row's Undo lasts `SETTLED_MS` (5.12 s). In the 0.3.0 pass, a capture between Dismiss and Undo took about 6 s, so the row folded before Undo was pressed, and the next try clicked during the short "Sending…" before Undo showed. The row should say to press Undo between 1 and 4 seconds after Dismiss and capture after it. That would stop a run's own timing from reading as a broken Undo.
- **The Herdr PRs tab row's empty-tab result is wrong.** It says that with no PRs on the tab and `gh` renamed, the hint shows "with no banner and no Refresh PRs". The shared plan in `hooks/pr-refresh.ts` draws Refresh PRs there, and so do the terminal and Herdr looks. The row should expect Refresh PRs, or a run fails a look that matches the shared plan.
- **The Herdr Update row needs a Codex session start.** `codex plugin add inbox@inbox` alone did not put the shipped mod back in `mods/inbox/`. Starting the Codex CLI in a Herdr terminal did. The row should say to start a Codex session after the reinstall, or a run reports a broken Codex update that is only an unfinished step.
- **The Ended Codex thread row cannot run in the Herdr panel.** The panel drops an ended session's rows and reads "The session ended. This terminal is back at its shell.", so no Answer press is left to send. In Codex 0.169, `/quit` also only disconnects: the thread runs in `app-server-daemon`, which outlives the CLI. The row should name a way to reach an ended thread's row, such as the terminal look, or be dropped from the Herdr table.
- **The Codex CLI rows need `codex` on PATH.** The ChatGPT app's bundled CLI run by its full path gets ENOENT on every ledger and Status call ([#423](https://github.com/petekp/inbox/issues/423)). Until that is fixed, a run should put the bundled CLI's folder first on PATH before the first Codex CLI session, since the daemon keeps the environment it started with.
- **The #359 check needs more than 40 ended sessions.** The 0.3.0 pass had 39 ended sessions in the store, under the limit of 40, so opening a second session pruned nothing and the prune path did not run. The row should first make sure the store holds 40 or more ended sessions.
- **The desktop Saved state row needs a session the signed-in account lists.** The guest's account listed none of the guest's earlier desktop sessions, so no session the old build saved could be opened. Setup should save one under the account the pass signs in with.
- **The desktop reopen rows need a way to reach an older conversation.** In Claude app 5.11492.5, the back arrow did nothing after an app restart, the `/resume` picker listed only conversations started in the terminal, and search listed only conversations the signed-in account knows. Search also shows private session titles, so its captures had to be deleted. The rows that reopen a conversation should name the path: start the conversation in the terminal in the sample project, then reopen it from `/resume` with "This folder" selected.

## Driving and capturing

- **Capture moves with a frame burst.** A capture per click, about 350 ms apart, missed an answer press's "Sending…" and every fade in the Herdr panel. One VNC connection that captures about every 55 ms and tiles the frames into a grid caught a row's buttons moving 24 pt ([#420](https://github.com/petekp/inbox/issues/420)). The pass should ship such a tool and name it in the Presses and Themes and width rows.
- **Name how each look takes keys.** In the terminal look, Ctrl+X Tab missed once and `j` went to the agent as a message. `/inbox` moves focus into the pane every time. In Herdr, `u` did nothing right after a click on the Finds tab, and Tab and Shift+Tab reach the pane's buttons. The Keys rows should say how to give each look focus.
- **Resume a stopped host with `fg`.** For Press nobody takes, `kill -STOP` on a host in a shell's foreground leaves it in the background after `kill -CONT`. `fg` brings it back, and Claude Code may then take the terminal's next reply as typed text. The row should say so.
- **`omp -p` waits on stdin.** A scripted omp turn hangs until stdin closes. Run it with `< /dev/null`.
- **Loading a debug copy in the Claude app.** `CLAUDE_CODE_PLUGIN_DIRS` in `settings.json`'s `env` did not load a folder in Claude app 5.11492.5. Replacing the installed folder in place did. Run `claude plugin validate <folder>` on a debug copy first: the engine refuses a mod that spells `$` other than `$.noun.event(…)`, and then sends `/inbox` to the model as a prompt.
