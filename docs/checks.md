# Checks

What the repo's automated checks cover. [The look map](looks.md) lists owners and differences.

`./scripts/test-files.sh tests/pr-fetch.test.ts tests/status-idle.test.ts` runs only the named mod test files with `claude plugin test` and exits with its status, so a session need not run the whole suite or build its own test folder.

`scripts/check-structure.mjs` checks the parity record in `core/domain/clients.ts` against "Differences on purpose", as described there. It also parses imports and resolves their targets. It follows local import chains, including type bridges. Code in `core/` imports only `core/` and `types/` through those chains, and Codex, omp and the Herdr look cannot reach the mod's own code in `hooks/` through another local module. It includes build-shared tones and type imports. Within `core/`, a file loads code only from its own layer folder and the layers before it, in the order `core/domain/`, `core/view/`, `core/runtime/`, `core/remote/`. A type-only import may name a type from any layer. A file directly in `core/`, outside a layer folder, fails. Shared modules and Codex reject computed targets. The only exception is a direct `import(url)` in the top-level `codex/src/server-main.ts:load` function. Nested functions do not inherit that exception. That function selects installed or dev handler URLs for hot reload.

The script also checks that omp's and Exact's files import only `core/` of the inbox's code, that `exact/` never imports `hooks/`, `codex/`, `omp/` or `herdr/`, and that only `omp/src/host.ts` imports omp's packages. It checks plan status lines, file references and links. Its owner-symbol check only verifies that a word occurs in the referenced file. It does not establish a definition or semantic freshness.

The script also fails when value imports in `core/`, `hooks/`, `codex/src`, `omp/src`, `herdr/src`, `exact/*.ts` or `exact/bridge` form a cycle, with `scripts/structure/cycles.mjs`. It counts static imports and re-exports, including those that resolve through a `paths` alias. An `import type` is erased, and an `import()` call loads its module later, so neither counts. An import written without `type` counts even when it brings only types, so write those as `import type`. In a cycle, one module can read another before that module is set up. Break a real one by moving the shared piece into the module that owns it.

The script also fails on a tool description over 4,096 characters, with `scripts/structure/tool-descriptions.mjs`. Claude Code passes a registered tool's description to the model only up to that many characters, so text past that point never reaches the model. The check bundles each host's tool list and measures every description: the mod's, with the guidance `close` carries, the Codex server's `TOOLS`, and omp's `agentTools(OMP)`.

The look map check in `scripts/structure/docs.mjs` also fails on a `path:on('event')` reference, such as `hooks/register.tsx:on('ui.render')`, when that file never calls `on`, or a method named `on`, with that event.

The script also checks the class names Codex builds from variables, with `scripts/structure/class-names.mjs`. It fails on a `class` value in `codex/src` whose variable part has no literal prefix ending in `-`, as in `tint-${tone}`, unless the value is looked up in an object of strings or chosen between strings, or is the component's own `class` prop passed through, since each caller's value is checked where the caller writes it. It also fails on a rule in `codex/src/tab-css` that selects a tone word, such as `.done`, with no other class beside it. A tone `key` once matched the global `.key` button rule and drew each new row's title as a button. It does not follow a function call that returns a class, so a helper such as `markClassOf` is checked at its own join or template.

The script also fails on `cursor: pointer` in `codex/src/tab-css` and on `cursor_pointer()` in `herdr/src`, with `scripts/structure/cursors.mjs`. Every inbox control keeps the default cursor, and hover states show what is clickable. The check leaves out `hooks/compare-page`, which is a separate browser page and not one of the looks.

The script also fails on a disclosure glyph other than the fold chevron (`▸ ▾ ▴ ▿ ▹ ⌄ ˅`) in a `.ts` or `.tsx` file under `hooks`, `herdr/src`, `omp/src` or `codex/src`, with `scripts/structure/chevrons.mjs`. Every fold draws the same chevron: `foldGlyph` in the text looks, and the chevron icon in the Codex tab and the Herdr look.

`codex/tests/structure.spec.ts` and `codex/tests/structure-graph.spec.ts` check the command against disposable fixtures, which `codex/tests/structure-fixtures.ts` builds. Mounted row-action tests check Codex controls and outcomes. The mod demo test checks terminal and desktop titles and actions, with settled rows and PRs outside that test. Full-page behavior, native painting, clipboard, focus and measured motion still need their own checks.

`omp/tests/session.spec.ts` runs the shared session script from `tests/session-script.ts` against omp's `SessionHost`. `omp/tests/panel.spec.ts` checks that the panel draws buttons in the shared plan order, in place of the demo test in `tests/hooks.test.ts`.

`herdr/tests/mod-load.spec.ts` loads the built Herdr mod, `main.js` in `herdr/mods/inbox`, in a `node:vm` context that holds only the globals Herdr's mod runtime has, as [the Herdr app reference](reference/herdr-app.md#the-globals-a-mod-gets) lists them. It draws the demo session through the stand-ins in `herdr/tests/gpui-stand-in.ts`. A global the runtime lacks, such as `Intl`, fails it where the mod first uses it, at load or at the first draw. Before the Herdr tests, `check.sh` and CI build the mod, and CI on `main` checks that the committed mod matches its sources, so the spec always runs on the bundle the sources build. It does not lay out or paint, and does not reach code that runs only after a press or a later read. When the Herdr app is installed, `check.sh` also runs `herdr-app check` on a copy of `herdr/mods/inbox`, which loads the mod once in the app's own runtime and builds its first draw. It runs under `env -i`, so it gets no `HC_TERMINAL_ID` or `HERDR_` variable from the shell, and `HOME` and `HERDR_APP_HOME` both name a scratch folder that `check.sh` deletes afterward. Without `herdr-app`, the step prints that it was skipped.

`checkMotionIds` in `herdr/tests/gpui-stand-in.ts` checks every draw the Herdr tests make through `openPanel` there or `framesOf` in `herdr/tests/frames.ts`. gpui-kit's types say an element with no id is known by its place in the tree, which shifts as rows above it come and go. In the app, a `.transition()` on such an element never ran, and neither did one whose id changed between draws: the element popped ([#743](https://github.com/petekp/inbox/issues/743)). The check assumes `.spring()` keeps its state the same way. It throws on an element with a transition or spring and no id. It also throws when such an element's id changes between two draws while it draws the same thing under the same nearest parent with an id: the same text, or a line in the same column.

`scripts/check-exports.mjs` fails on an export that no other file imports. It reads the source files Git lists as tracked, or untracked and not ignored (`git ls-files --cached --others --exclude-standard`), so untracked files `.gitignore` covers, such as installed tools in `node_modules`, are left out. It also skips the committed bundles and `types/parts`. It counts named, default, namespace, type and dynamic imports (an awaited `import()` that destructures counts only the names it lists), re-exports, and a `module="./x-client.tsx"` attribute as importers. The hooks modules that `hooks/hooks.json` names are entry points. `ENTRY_POINTS` in `scripts/structure/exports.mjs` lists the other exports whose consumer is outside the repo's imports, each with that consumer. `codex/tests/structure-exports.spec.ts` checks it against disposable fixtures.

`scripts/check-versions.mjs` checks that `.claude-plugin/plugin.json`, `codex/plugin/.codex-plugin/plugin.json` and `omp/package.json` give the same version. `codex/tests/versions.spec.ts` checks it against disposable manifests.

`scripts/check-tick-waits.mjs` fails a test that waits for a host's background work with a loop, or a run, of `setImmediate`, `setTimeout` or `Bun.sleep` awaits. It reads the Codex tests that start the server, which await the server's `settled()` (`codex/src/background.ts`), and the omp host tests, which await `settle()` in `omp/tests/host-harness.ts`. The Herdr look and the omp controller have no such tracker, so it leaves them out. It does not read a tick await broken across lines, `process.nextTick`, or a tick from `node:timers/promises`. `ALLOWED` in the script lists the waits that are not that work, each with its reason.

`scripts/check-sizes.mjs` fails on a tracked file over 5,000 tokens, counted as bytes / 4. It skips the files the token-limit pre-commit hook skips: lockfiles, built and generated files, binaries, and files marked `linguist-generated` in `.gitattributes`. Where that hook is installed, the check also runs the hook's `--scan` and fails when the two find different files.

`./scripts/check.sh` runs formatting, file sizes, plugin validation, structure, unused exports, the version check, the type checks, the test suites (including `exact tests`), a short fixed-seed fuzz run of the Herdr look, the omp panel and the row stepper ([UI fuzz](plans/ui-fuzz.md)), and that the Codex bundles and `omp/dist/host.js` match their sources. Run it after every change. Model evaluations run separately when model-facing text changes. CI runs `exact tests` alongside `mod`, `codex`, `omp` and `herdr`, while `build:web` and `build:ios` run locally where the Exact framework checkout lives.
