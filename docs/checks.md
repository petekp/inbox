# Checks

What the repo's automated checks cover. [The look map](looks.md) lists owners and differences.

`scripts/check-structure.mjs` checks the parity record in `hooks/clients.ts` against "Differences on purpose", as described there. It also parses imports and resolves their targets. It follows local import chains, including type bridges. Shared modules retain their shared-only restriction through those chains, and Codex cannot reach nonshared hooks through another local module. It includes build-shared tones and type imports. Shared modules and Codex reject computed targets. The only exception is a direct `import(url)` in the top-level `codex/src/server-main.ts:load` function. Nested functions do not inherit that exception. That function selects installed or dev handler URLs for hot reload.

The script also checks that omp's files import only shared modules, and that only `omp/src/host.ts` imports omp's packages. It checks plan status lines, file references and links. Its owner-symbol check only verifies that a word occurs in the referenced file. It does not establish a definition or semantic freshness.

The script also checks the class names Codex builds from variables, with `scripts/structure/class-names.mjs`. It fails on a `class` value in `codex/src` whose variable part has no literal prefix ending in `-`, as in `tint-${tone}`, unless the value is looked up in an object of strings or chosen between strings, or is the component's own `class` prop passed through, since each caller's value is checked where the caller writes it. It also fails on a rule in `codex/src/tab-css` that selects a tone word, such as `.done`, with no other class beside it. A tone `key` once matched the global `.key` button rule and drew each new row's title as a button. It does not follow a function call that returns a class, so a helper such as `markClassOf` is checked at its own join or template.

The script also fails on `cursor: pointer` in `codex/src/tab-css` and on `cursor_pointer()` in `herdr/src`, with `scripts/structure/cursors.mjs`. Every inbox control keeps the default cursor, and hover states show what is clickable. The check leaves out `hooks/compare-page`, which is a separate browser page and not one of the looks.

The script also fails on a disclosure glyph other than the fold chevron (`▸ ▾ ▴ ▿ ▹ ⌄ ˅`) in a `.ts` or `.tsx` file under `hooks`, `herdr/src`, `omp/src` or `codex/src`, with `scripts/structure/chevrons.mjs`. Every fold draws the same chevron: `foldGlyph` in the text looks, and the chevron icon in the Codex tab and the Herdr look.

`codex/tests/structure.spec.ts` checks the command against disposable fixtures. Mounted row-action tests check Codex controls and outcomes. The mod demo test checks terminal and desktop titles and actions, with settled rows and PRs outside that test. Full-page behavior, native painting, clipboard, focus and measured motion still need their own checks.

`omp/tests/session.spec.ts` runs the shared session script from `tests/session-script.ts` against omp's `SessionHost`. `omp/tests/panel.spec.ts` checks that the panel draws buttons in the shared plan order, in place of the demo test in `tests/hooks.test.ts`.

`herdr/tests/mod-load.spec.ts` loads the built Herdr mod, `herdr/mod/inbox/main.js`, in a `node:vm` context that holds only the globals Herdr's mod runtime has, as [the Herdr app reference](reference/herdr-app.md#the-globals-a-mod-gets) lists them. It draws the demo session through the stand-ins in `herdr/tests/gpui-stand-in.ts`. A global the runtime lacks, such as `Intl`, fails it where the mod first uses it, at load or at the first draw. The `herdr mod` check fails when the committed bundle does not match its sources, so the spec always runs on the bundle the sources build. It does not lay out or paint, and does not reach code that runs only after a press or a later read. `herdr-app check` on the mod folder also loads it in the real runtime, and needs the Herdr app.

`scripts/check-exports.mjs` fails on an export that no other file imports. It reads the source files Git lists as tracked, or untracked and not ignored (`git ls-files --cached --others --exclude-standard`), so untracked files `.gitignore` covers, such as installed tools in `node_modules`, are left out. It also skips the committed bundles and `types/parts`. It counts named, default, namespace, type and dynamic imports (an awaited `import()` that destructures counts only the names it lists), re-exports, and a `module="./x-client.tsx"` attribute as importers. The hooks modules that `hooks/hooks.json` names are entry points. `ENTRY_POINTS` in `scripts/structure/exports.mjs` lists the other exports whose consumer is outside the repo's imports, each with that consumer. `codex/tests/structure-exports.spec.ts` checks it against disposable fixtures.

`scripts/check-versions.mjs` checks that `.claude-plugin/plugin.json`, `codex/plugin/.codex-plugin/plugin.json` and `omp/package.json` give the same version. `codex/tests/versions.spec.ts` checks it against disposable manifests.

`scripts/check-sizes.mjs` fails on a tracked file over 5,000 tokens, counted as bytes / 4. `.token-ceilings` lists the files allowed over that limit, one `path ceiling` entry per line, and the check fails on a listed file past its ceiling. It also fails on an entry that names no tracked file, or a file now at or under 5,000 tokens. It skips the files the token-limit pre-commit hook skips: lockfiles, built and generated files, binaries, and files marked `linguist-generated` in `.gitattributes`. Where that hook is installed, the check also runs the hook's `--scan` and fails when the two find different files.

`./scripts/check.sh` runs formatting, file sizes, plugin validation, structure, unused exports, the version check, the type checks, the test suites, and that the Codex bundles and `omp/dist/host.js` match their sources. Run it after every change. Model evaluations run separately when model-facing text changes.
