# Owners: tabs, lists, banners and the footer

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| Asks order and count | `hooks/view.ts:needsYouOrder`, `hooks/view.ts:inboxView` | All four looks, the band and the status line |
| Tab names: the words where they fit, else the symbols | `hooks/view.ts:shownTabs`, `hooks/view.ts:fitTabs`, `hooks/text.ts:cellWidth` | The terminal, desktop and omp looks. The Codex tab switches with a container query (see Differences on purpose). The band and the inbox model read only the words. |
| Which tabs a build draws, and their number keys: a release build leaves out the Status, a next build draws it first, and each tab's key is its place. A saved or sent tab the build does not draw shows the build's first tab. | `hooks/view.ts:shownTabs`, `hooks/view.ts:drawnTabOf` | All four looks, from the next-build mark. The mod reads a saved Status page through `hooks/register.tsx:readPage`, which leaves it saved. The Codex tab draws from `TabView.isNextBuild`. The Codex server saves the tab its build draws at each view request. Until the first request after a switch from a next build, the hook and update processes still read a saved Status for the screen note. omp's panel reads `PanelScreen.isNextBuild`, and saves no tab. |
| The `/inbox` command's description: what the build's tabs show. A release build names the questions, tasks, findings and PRs. A next build names where the session stands, from the Status. | `hooks/view.ts:inboxCommandText` | The terminal and omp looks. Codex has no command. |
| Question numbers | `hooks/model-text.ts:questionNumbers`, read by `hooks/view.ts:inboxView` into `RowView.number`. `hooks/view.ts:rowTitle` starts the title with it, and `hooks/view.ts:rowHandle` writes it as `1)` or `•` for text the agent reads. | The terminal and omp looks start a numbered question's title with its number, as `1) Dismiss a glance…`. A settled question has left the numbered batch, so its title starts without it. Desktop and Codex draw no number. The Codex tool texts read `rowHandle`. |
| Asks groups | `hooks/view.ts:NEEDS_YOU_GROUPS` | The mod and omp. The Codex tab names the groups in `codex/src/tab.tsx`. |
| A group title's count: its rows that wait on the person | `hooks/view.ts:waitingCount` | All four looks. A PR group counts its rows. Every look draws no count, on a group title or a tab, at 0. |
| Finding groups and their marks | `hooks/view.ts:FINDING_GROUPS`, `hooks/view.ts:drawnLists` | All four looks. Each lists findings under an Issues and an Opportunities title, and draws the kind's mark, ▲ or ✦ in its tone, on the title, not on each row. The terminal and omp draw it before the title's words. Desktop and Codex hang it in the mark column, so the words line up with the rows. |
| The status line under the inbox: Updating…, Refreshing PRs…, a failed update and a failed Status call | `hooks/view.ts:footerStatus` | All four looks. The status shows in the footer. A failed update or Status call shows as a banner under the tab bar. Codex shows its own failed-read line in the footer before the status. |
| Banners: each banner's tone, its bold lead, and the order under the tab bar | `hooks/view.ts:bannerOf`, `hooks/view.ts:stopBanner`, `hooks/view.ts:tabBarBanners`, `hooks/view.ts:BANNER_TONES` | All four looks. Under the tab bar, the host's own banners come first, then a failed update, then the result of a press whose row the tab no longer shows. The demo banner sits above the tabs, a failed read and the stop at the top of Asks, and gh not found or not signed in at the top of PRs. Each look adds the button a banner has: Try again, Resume, Hide demo, Reload. |
| Which row opens: by default, when rows arrive above it, and after a press closes the open row | `hooks/view.ts:firstWaiting`, `hooks/view.ts:keptOpen`, `hooks/view.ts:rowAfterClose` | All four looks. omp uses `firstWaiting` and `rowAfterClose` to pick the selected row, and `keptOpen` to keep it when rows arrive above it. |
| The Help page: what it lists, and that it takes the tab's place | `hooks/view.ts:helpKeys` gives each look's keys, with j and k on the Status while a row there has a View button, in the terminal and omp, `hooks/view.ts:HELP_COPY` the words, and `hooks/view.ts:MARK_LEGEND` the marks. | All four looks. Help replaces the shown tab's body, under the tab bar, with Keys and then Marks. Desktop lists no keys. A row's keys and j and k do nothing while it shows. Switching tabs closes it, and so does closing the pane or panel. The terminal draws Keys and Marks side by side in the inline pane at 80 columns and wider. How each look opens and closes it: see `help-page` in Differences on purpose. |
| Closed fold size | `hooks/view.ts:CLOSED_SHOWN`, `hooks/view.ts:closedShown` | All four looks. |
| New rows, empty tabs and where a look moves | `hooks/arrivals.ts:recordRows`, `hooks/arrivals.ts:listedRowIds`, `hooks/arrivals.ts:openRowIds`, `hooks/arrivals.ts:closedGroups`, `hooks/arrivals.ts:isTabEmpty`, `hooks/arrivals.ts:prRowIds`, `hooks/arrivals.ts:isPrsTabEmpty`, `hooks/arrivals.ts:followTo` | The pane, the Codex tab and the omp panel, in `omp/src/panel-tabs.ts:followRows`. |
| Stop texts, and which stops offer Resume | `hooks/view.ts:stopText`, `hooks/view.ts:stopFix`, `hooks/view.ts:RESUME_TEXT`, `hooks/view.ts:isResumable` | The mod and omp. Codex shows no stops. |
| Banner padding and the space between banners | `hooks/layout.ts:BANNER_PAD_Y_PT`, `hooks/layout.ts:BANNER_GAP_PT` | Desktop and Codex |
| Demo data | `hooks/demo.ts:demoView`, `hooks/demo.ts:demoSession` | The mod's `/inbox demo`, `codex/src/demo.ts:demoState` and `omp/src/demo.ts:demoState` |
| Version label text, and the next-build mark | `hooks/view.ts:versionLabel`, `hooks/view.ts:NEXT_BUILD_MARK` | All four looks, for the version label and the tabs. A checkout that follows the `next` branch can hold the mark, a file Git ignores, in the root, `codex/plugin` and `omp`. Claude Code loads the root, and the Codex and omp installs each copy their own folder, the mark included. Each host checks the folder it runs from once, as it starts: the mod in `$.plugin.root` (`hooks/register.tsx:readVersion`, before its first draw), the Codex handler in the plugin folder that holds its bundle (`codex/src/server-handler.ts:createHandler`, sent to the tab as `TabView.isNextBuild`), and omp's host in its extension folder (`omp/src/host.ts:defaultDeps`). A Codex handler that `npm --prefix codex run dev` builds runs from `codex/.dev`, so it finds no mark. |
