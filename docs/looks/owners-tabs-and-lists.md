# Owners: tabs, lists, banners and the footer

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| Asks order and count | `hooks/view.ts:needsYouOrder`, `hooks/view.ts:inboxView` | All four looks, the band and the status line |
| The band's counts and its text with none: "Nothing needed", or "May be out of date" while rows may be missing. An empty Asks or Finds tab takes the same title then. | `hooks/band.ts:bandCounts`, `hooks/band.ts:isMaybeStale`, `hooks/band.ts:noCountsText`, `hooks/banners.ts:NOTHING_NEEDED_TEXT` | The terminal and desktop band, omp's band, the Herdr line (`hooks/herdr.ts:herdrTokens`), and the empty Asks and Finds tabs in all four looks. Each passes its own read failure: the mod's saved inbox it could not read (`UNREADABLE`), and omp's screen whose last read failed (`PanelScreen.isReadFailed`). The Codex tab draws only its read-failed banner while it cannot read, so its empty tabs never show then. A failed Status call does not count: it shows on the Status page alone, since the band and these tabs speak for asks and findings. |
| When a tab is empty, and what its empty state says and holds: the title, the hint, and what sits under them, either Refresh PRs or the goal's buttons and field. A look passes only what the shared view cannot know, such as how many rows it draws, whether it draws a blocker such as a stop, and its own Asks text. | `hooks/empty-tab.ts:emptyTab` | Every look, each through one empty drawer: `hooks/pane-asks.tsx:emptyState` for the terminal and desktop, `codex/src/tab-parts.tsx:EmptyState`, `omp/src/panel-entries.ts:emptyEntries` and `herdr/src/blocks.ts:emptyBlock`. `scripts/structure/empty-tab.mjs` fails when a look imports the empty texts, holds an empty title as literal text, adds a second drawer, or gives a drawer anything but an `emptyTab` result. |
| Tab names: the words where they fit, else the symbols | `hooks/tabs.ts:shownTabs`, `hooks/tabs.ts:fitTabs`, `hooks/text.ts:cellWidth` | The terminal, desktop and omp looks. The Codex tab switches with a container query (see Differences on purpose). The band and the inbox model read only the words. |
| The tabs and their number keys: Status, Asks, Finds and PRs, each keyed by its place. | `hooks/tabs.ts:shownTabs` | All four looks. The mod reads its saved row tab and page through `hooks/register.tsx:readPage`. The Codex server saves the shown tab at each view request, and the Codex tab draws Asks for a saved Status while its view has no Status page, as from an older server (`codex/src/tab-selection.ts:drawnTab`). omp saves no tab. |
| The `/inbox` command's description: where the session stands and what waits on the person. | `hooks/tabs.ts:INBOX_COMMAND_TEXT` | The terminal and omp looks. Codex has no command. |
| Question numbers | `hooks/inbox-text.ts:questionNumbers`, read by `hooks/view.ts:inboxView` into `RowView.number`. `hooks/rows.ts:rowTitle` starts the title with it, and `hooks/rows.ts:rowHandle` writes it as `1)` or `•` for text the agent reads. | The terminal and omp looks start a numbered question's title with its number, as `1) Dismiss a glance…`. A settled question has left the numbered batch, so its title starts without it. Desktop and Codex draw no number. The Codex tool texts read `rowHandle`. |
| Asks groups | `hooks/rows.ts:NEEDS_YOU_GROUPS` | The mod and omp. The Codex tab names the groups in `codex/src/tab-groups.tsx`. |
| A group title's count: its rows that wait on the person | `hooks/rows.ts:waitingCount` | All four looks. A PR group counts its rows. Every look draws no count, on a group title or a tab, at 0. |
| Finding groups and their marks | `hooks/help.ts:FINDING_GROUPS`, `hooks/action-plan.ts:drawnLists` | All four looks. Each lists findings under an Issues and an Opportunities title, and draws the kind's mark, ▲ or ✦ in its tone, on the title, not on each row. The terminal and omp draw it before the title's words. Desktop and Codex hang it in the mark column, so the words line up with the rows. |
| The failure text under the tabs: a failed update and a failed Status call | `hooks/view.ts:footerError` | All five looks. It shows as a banner under the tab bar. No look's footer or tab row shows that an update or a PR refresh is under way. Codex shows its own failed-read line in the footer. |
| Banners: each banner's tone, its bold lead, and the order under the tab bar | `hooks/banners.ts:bannerOf`, `hooks/banners.ts:stopBanner`, `hooks/banners.ts:tabBarBanners`, `hooks/banners.ts:BANNER_TONES` | All four looks. Under the tab bar, the host's own banners come first, then a failed update, then the result of a press whose row the tab no longer shows. The demo banner sits above the tabs, a failed read and the stop at the top of Asks, and gh not found or not signed in at the top of PRs. Each look adds the button a banner has: Try again, Resume, Hide demo, Reload. |
| Which row opens: by default, when rows arrive, and after a press closes the open row. A row the person collapsed never opens on its own, and stays collapsed until something new arrives on it. | `hooks/action-plan.ts:firstWaiting`, `hooks/action-plan.ts:keptOpen`, `hooks/action-plan.ts:openOnArrival`, `hooks/action-plan.ts:rowAfterClose`, `hooks/collapse.ts:collapsedRows` | All five looks. The mod applies them through `hooks/pane-open-row.ts`, the Codex tab in `codex/src/tab-read.ts`, omp in `omp/src/panel-tabs.ts`, and the Herdr panel in `herdr/src/keys.ts:withArrivals`. omp uses `firstWaiting` and `rowAfterClose` to pick the selected row, and `openOnArrival` to keep it when rows arrive above it. The Herdr panel uses `firstWaiting` and `rowAfterClose`, and `openOnArrival` when rows arrive while the selected row is collapsed. It moves the selection when a publish shows the selected row stopped waiting, and reopens a row its Undo restores, as the terminal does. |
| Stepping with keys, wrapping at either end: `j` and `k` move the selection one row at a time, from the last row to the first and back. omp also steps button focus with ← and → and tabs with Tab and Shift+Tab. With nothing selected, `j` selects the first row and `k` the last. | `hooks/action-plan.ts:steppedIndex` | The terminal, Codex, omp and Herdr. The terminal's rows and Status page (`hooks/register.tsx:move`, `moveStatus`). The Codex tab's rows, with ↑ and ↓ as well (`codex/src/tab.tsx`). omp's rows and Status page, with ↑ and ↓ as well, and its button focus and tab switching (`omp/src/panel-keys.ts:handleKey`). The Herdr panel's rows (`herdr/src/keys.ts:keyMove`). Desktop takes no keys. |
| The Help page: what it lists, and that it takes the tab's place | `hooks/help.ts:helpKeys` gives each look's keys. Help is one page that does not change with the tab it opened over, and every look closes it when a tab is chosen, including the tab already shown, `hooks/help.ts:HELP_COPY` the words, with the Help control drawn as a question mark named Help, in a tab at the right end of the tab row that is selected while Help shows, `hooks/help.ts:MARK_LEGEND` the indicators. | All four looks. Help replaces the shown tab's body, under the tab bar, with Keys, then Indicators, then the inbox version. Every look draws each key and each indicator in a left column and its words beside it, and every section, the version line included, shares that one pair of columns. Each list starts one indicator column in under its section's title, and the words start a small gap after the widest key. Desktop lists no keys. A row's keys and j and k do nothing while it shows. Switching tabs closes it, and so does closing the pane or panel. The terminal draws Keys and Indicators side by side in the inline pane at 80 columns and wider. How each look opens and closes it: see `help-page` in Differences on purpose. |
| Closed fold size | `hooks/rows.ts:CLOSED_SHOWN`, `hooks/rows.ts:closedShown` | All four looks. |
| New rows, empty tabs and where a look moves | `hooks/arrivals.ts:recordRows`, `hooks/arrivals.ts:listedRowIds`, `hooks/arrivals.ts:openRowIds`, `hooks/arrivals.ts:closedGroups`, `hooks/arrivals.ts:isTabEmpty`, `hooks/arrivals.ts:prRowIds`, `hooks/arrivals.ts:isPrsTabEmpty`, `hooks/arrivals.ts:followTo` | The pane, the Codex tab and the omp panel, in `omp/src/panel-tabs.ts:followRows`. |
| A row's title tint: which rows count as new, when each one's clock starts, which tab draws it, how strong its tint is, and when a closed row's clock starts. A closed row's tint starts when a look first draws the row closed, so no look starts it mid-fade, and a row closed longer ago than the tint lasts takes none. Only a row that arrives while the look is shown gets a tint as new. Its clock starts the first time its tab shows with Help closed. | `hooks/arrivals.ts:addNewRows`, `hooks/arrivals.ts:showNewRows`, `hooks/arrivals.ts:newRowIn`, `hooks/arrivals.ts:newRowShare`, `hooks/arrivals.ts:steppedTitleTint`, `hooks/arrivals.ts:closedTitleClock`, `hooks/arrivals.ts:titleTintEndsAt`, `hooks/arrivals.ts:TITLE_TINT` | The pane, in `hooks/pane-selection.ts:rowRecorder`, which adds rows only while the pane is shown, and skips a record whose view was read before a conversation loaded. The Codex tab, which adds rows only when its page was visible at this read and the last one. The omp panel, which starts a fresh record each time it opens. The Herdr look counts the rows that arrive between two of its draws of a tab, in `herdr/src/keys.ts:withDrawnRows`. |
| Stop texts, and which stops offer Resume | `hooks/banners.ts:stopText`, `hooks/banners.ts:stopFix`, `hooks/banners.ts:RESUME_TEXT`, `hooks/banners.ts:isResumable` | The mod and omp. Codex shows no stops. |
| Banner padding and the space between banners | `hooks/layout.ts:BANNER_PAD_Y_PT`, `hooks/layout.ts:BANNER_GAP_PT` | Desktop and Codex |
| Demo data | `hooks/demo.ts:demoView`, `hooks/demo.ts:demoSession` | The mod's `/inbox demo`, `codex/src/demo.ts:demoState` and `omp/src/demo.ts:demoState` |
| Version label text, and the next-build mark | `hooks/banners.ts:versionLabel`, `hooks/help.ts:helpVersionText`, `hooks/banners.ts:NEXT_BUILD_MARK` | All five looks draw it at the right end of the title of Help's Keys section, and the Herdr look reads it from the published file's `version` and `isNextBuild`, and every host for its Status call records. A checkout that follows the `next` branch can hold the mark, a file Git ignores, in the root, `codex/plugin` and `omp`. Claude Code loads the root, and the Codex and omp installs each copy their own folder, the mark included. Each host checks the folder it runs from once, as it starts: the mod in `$.plugin.root` (`hooks/register.tsx:readVersion`, before its first draw), the Codex handler in the plugin folder that holds its bundle (`codex/src/server-handler.ts:createHandler`, sent to the tab as `TabView.isNextBuild`), and omp's host in its extension folder (`omp/src/host.ts:defaultDeps`). A Codex handler that `npm --prefix codex run dev` builds runs from `codex/.dev`, so it finds no mark. |
