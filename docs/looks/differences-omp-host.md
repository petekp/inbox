# Differences on purpose: how omp runs

Part of [the look map](../looks.md#omp).

| Topic | omp | Why | Where |
| --- | --- | --- | --- |
| Answering a dialog's copy (`dialog-answer`) | An inbox answer is sent as `Re "…": answer`. | The ask dialog blocks the turn, and the inbox copies a dialog only once it ended. | `omp/src/host-activity.ts`, `hooks/press-messages.ts:messages` |
| Stop rows (`band-and-stop-rows`) | The band shows the stop and its fix under the counts, and takes no key. Resume is a button on the stop row in the panel. A stop is a sign-in, usage-limit or API-error stop, never a billing stop, and a usage-limit stop names no reset time. It clears when the next turn starts. | omp's band cannot take keys. omp reports a failed request's HTTP status and message, and the inbox classes the stop from those with omp's own usage-limit rule. The mod reads Claude Code's error words, which name billing and the reset time. | `omp/src/omp-messages.ts:stopOf`, `omp/src/panel-entries.ts:stopEntries`, `omp/src/panel.ts:bandLines` |
| Inbox model | The model of the person's `@inbox` role if omp can resolve it, else the newest Sonnet from their providers, `anthropic` first, else omp's `@smol` role. An `@inbox` that omp cannot resolve falls through. A resolved model that fails when called fails that update. The panel footer names the model used, or says "no inbox model: set @inbox". | omp's providers come from each person's setup, so the inbox cannot assume one. | `omp/src/host.ts:inboxModel`, `omp/src/panel-tabs.ts:footer` |
| Version label (`version-label`) | `v<version>`, read from `omp/package.json`, with ` · next` after it on a next build, follows the inbox model's text in the panel footer. It sits on the hints' line when the model text fits there, and ends the model's own line when it does not. | The footer already ends with the inbox model's text, and the model's text has its own line when it does not fit. | `omp/src/panel-tabs.ts:footer` |
| Hooks need trust (`hooks-need-trust`) | None. The panel has no trust state. | omp runs an installed extension's events without asking anyone to trust them. | `hooks/clients.ts:CLIENTS` |
| Children on the Status (`status-children`) | Subagents from `task:subagent:lifecycle` frames, with activity from `task:subagent:progress`, and Herdr delegates from bash calls. A delegate ends when a wait on it returns. `herdr agent list` sets its state at the turn's end, and each `HERDR_CHECK_MS` while the panel shows the Status (`omp/src/controller.ts:createPanel`). No background jobs or workflow runs. | omp's reference names no event for a background job or a workflow run. | `omp/src/host-activity.ts`, `omp/src/host-turns.ts` |
| Sessions with no screen | A subagent, and a session run without a UI such as print mode, get no inbox. Their `session_start` takes `record` and `close` out of the active tools, and a call that still arrives answers "The inbox is not shown in this session." | Nobody looks at those sessions. `ctx.agent.kind` marks a subagent and `ctx.hasUI` a session with no screen. omp 18.1.17 gives an extension no `ctx.agent`, and starts a subagent with no UI, so `hasUI` alone covers it there. | `omp/src/host-context.ts:isUnattended` |
| Storage | One JSON file per session under omp's agent folder, in `inbox/sessions/`, with a lock held in the process. | The state is rewritten after every tool run and press. omp's custom session entries only append, so keeping it in the session file would grow that file with each change. | `omp/src/state.ts:statePath`, `omp/src/state.ts:updateState` |
| How a press sends, opens and copies | Sends with `sendUserMessage`, which queues as a follow-up while a turn runs. omp runs a follow-up in the same run, after the agent's reply, and fires `agent_end` once for the whole run. So when a follow-up reaches the agent, whether a press sent it or the person typed it, the host ends the running turn with the reply the agent gave before it. The follow-up then starts its own turn and gets its own update, as in the other looks. A message that reaches the agent after a tool call, before the agent replies, stays in the running turn. Opens with `open` and copies with the system clipboard command, both in omp's process. | omp's extension API sends and runs commands in process. omp marks no end for the reply to one prompt inside a run, and fires `agent_end` once, when the run ends. | `omp/src/host.ts:createInbox`, `omp/src/commands.ts:openTarget` |
| Install | The marketplace copies only `omp/`, so the extension is a bundle with the shared modules inside. | An omp plugin cannot import `../hooks` once installed. | `omp/build.ts`, `.omp-plugin/marketplace.json` |
| Catch-up and a behind ledger (`catch-up`, `ledger-behind-state`, `failed-update-recovery`) | The same rule as the mod. `session_start`, `session_switch` and `session_branch` mark the ledger `behind` when the branch has turns and the inbox has recorded none, and start an update that reads the branch from the last `/clear`. | `ctx.sessionManager.getBranch()` returns the whole stored conversation, so the update reads that. A fork, a `/btw` promotion or a branch into a new session copies its parent's saved ledger when there is one, and does not catch up. | `hooks/session-host.ts:runUpdates`, `omp/src/omp-messages.ts:conversationOf`, `omp/src/host.ts:createInbox` |
| Turn with no prompt (`exchange-trigger`) | Every turn has the prompt's words, so no exchange reads "unknown". | `before_agent_start` carries only the prompt text. | `hooks/session-turns.ts:endTurn` |
