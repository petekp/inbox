# Differences on purpose: how omp runs

Part of [the look map](../looks.md#omp).

| Topic | omp | Why | Where |
| --- | --- | --- | --- |
| Text width | The panel and band count a line's cells with omp's `visibleWidth`. The other terminal looks count one cell per grapheme, two for a wide one. | omp's TUI cuts the end of any line wider than its own count, which differs for some scripts, such as Devanagari, and for tabs. omp supplies the count at runtime. | `omp/src/panel-view.ts:countCellsAsOmp`, `core/domain/text.ts:countCellsWith` |
| Held-act sentences in the guidance | The guidance adds, after its held-act line: "Marking a PR ready is such an act, since reviewers see it. Leave out a step outside the task, such as a commit nobody asked for, and say in your reply that you have not taken it." Claude Code and Codex get no such sentences. | omp's own system prompt does not tell the agent to commit only when asked. Without these sentences, omp asked to commit in every run of `uncommitted-change-not-asked`, with the rest of the guidance and without it. With only the commit sentence, omp 19.2.1 ran `gh pr ready` without asking in `no-task-for-own-step`, so the PR sentence keeps that a question. Claude Code's system prompt says "Only create commits when requested by the user", and Codex passes both cases without the sentences. In Claude Code the guidance rides in `close`'s description, which is at the 4096 characters Claude Code sends. | `omp/src/texts.ts:OMP`, `core/domain/model-text.ts:guidanceText` |
| Tool fields after an update | Always this build's. | omp registers the tools again in each session, so its agent always has this build's tools. | `omp/src/host.ts`, `core/domain/question-checks.ts:missingText` |
| Answering a dialog's copy (`dialog-answer`) | An inbox answer is sent as `Re "…": answer`. | The ask dialog blocks the turn, and the inbox copies a dialog only once it ended. | `omp/src/host-activity.ts`, `core/domain/press-messages.ts:messages` |
| Stop rows (`band-and-stop-rows`) | The band shows the stop and its fix under the counts, and takes no key. Resume is a button on the stop row in the panel. A stop is a sign-in, usage-limit or API-error stop, never a billing stop, and a usage-limit stop names no reset time. It clears when the next turn starts. | omp's band cannot take keys. omp reports a failed request's HTTP status and message, and the inbox classes the stop from those with omp's own usage-limit rule. The mod reads Claude Code's error words, which name billing and the reset time. | `omp/src/omp-messages.ts:stopOf`, `omp/src/panel-entries.ts:stopEntries`, `omp/src/panel.ts:bandLines` |
| Inbox model | The model of the person's `@inbox` role if omp can resolve it, else the newest Sonnet from their providers, `anthropic` first, else omp's `@smol` role. An `@inbox` that omp cannot resolve falls through. A resolved model that fails when called fails that update. The panel footer names the model used, or says "no inbox model: set @inbox". | omp's providers come from each person's setup, so the inbox cannot assume one. | `omp/src/inbox-model.ts:inboxModel`, `omp/src/panel-tabs.ts:footer` |
| Hooks need trust (`hooks-need-trust`) | None. The panel has no trust state. | omp runs an installed extension's events without asking anyone to trust them. | `core/domain/clients.ts:CLIENTS` |
| Children on the Status (`status-children`) | Subagents from `task:subagent:lifecycle` frames, with activity from `task:subagent:progress`, and Herdr delegates from bash calls. A delegate ends when a wait on it returns. `herdr agent list` sets its state at the turn's end (in a Herdr app terminal, `hc ls --json` sets it and starts a delegate for each child terminal that works), and each `HERDR_CHECK_MS` while the panel shows the Status (`omp/src/controller.ts:createPanel`). No workflow runs. | omp's reference names no event for a workflow run. | `omp/src/host-activity.ts`, `omp/src/host-turns.ts` |
| Sessions with no screen | A subagent, and a session run without a UI such as print mode, get no inbox. Their `session_start` takes `record` and `close` out of the active tools, and a call that still arrives answers "The inbox is not shown in this session." | Nobody looks at those sessions. `ctx.agent.kind` marks a subagent and `ctx.hasUI` a session with no screen. omp 18.1.17 gives an extension no `ctx.agent`, and starts a subagent with no UI, so `hasUI` alone covers it there. | `omp/src/host-context.ts:isUnattended` |
| Storage | One JSON file per session under omp's agent folder, in `inbox/sessions/`, with a lock held in the process. Its command log goes in a second file beside it. | The state is rewritten after every tool run and press. omp's custom session entries only append, so keeping it in the session file would grow that file with each change. | `omp/src/state.ts:statePath`, `omp/src/state.ts:updateState` |
| How a press sends, opens and copies | Sends with `sendUserMessage`, which queues as a follow-up while a turn runs. omp runs a follow-up in the same run, after the agent's reply, and fires `agent_end` once for the whole run. So when a follow-up reaches the agent, whether a press sent it or the person typed it, the host ends the running turn with the reply the agent gave before it. The follow-up then starts its own turn and gets its own update, as in the other looks. A message that reaches the agent after a tool call, before the agent replies, stays in the running turn. Opens with `open` and copies with the system clipboard command, both in omp's process. | omp's extension API sends and runs commands in process. omp marks no end for the reply to one prompt inside a run, and fires `agent_end` once, when the run ends. | `omp/src/host.ts:createInbox`, `omp/src/commands.ts:openTarget` |
| Install | The marketplace copies only `omp/`, so the extension is a bundle with the shared modules inside. | An omp plugin cannot import `../core` once installed. | `omp/build.ts`, `.omp-plugin/marketplace.json` |
| Catch-up and a behind ledger (`catch-up`, `ledger-behind-state`, `failed-update-recovery`) | The same rule as the mod. `session_start`, `session_switch` and `session_branch` mark the ledger `behind` when the branch has turns and the inbox has recorded none, and start an update that reads the branch from the last `/clear`. | `ctx.sessionManager.getBranch()` returns the whole stored conversation, so the update reads that. A fork, a `/btw` promotion or a branch into a new session copies its parent's saved ledger when there is one, and does not catch up. | `core/runtime/session-host.ts:runUpdates`, `omp/src/omp-messages.ts:conversationOf`, `omp/src/host.ts:createInbox` |
| Turn with no prompt (`exchange-trigger`) | A turn the person starts has the prompt's words. A turn that a background job's result starts has none and reads "unknown". | `before_agent_start` carries only the prompt text, and omp names no source for a turn it starts itself. | `core/runtime/session-turns.ts:endTurn`, `omp/src/host-turns.ts:onAgentEnd` |
| `/clear` | From omp 18.20.1, `/clear` drops the cleared conversation's rows, Status and tasks, as in the other looks, and the question history keeps the answers. On older omp, the rows stay. | omp sends `session_clear` from 18.20.1, and older omp sends no event at `/clear`. | `omp/src/host-turns.ts:onSessionClear` |
| Show explanation (`show-explanation`) | Never drawn. | omp's conversation is the terminal's own scrollback, which no extension can scroll. | `core/view/session-view.ts:sessionView` |
| Desktop Codex connection (`codex-desktop-companion`) | Unsupported; omp publishes its sessions through Herdr. | The connection targets Codex's saved chats and MCP host, which omp does not use. | `codex/src/companion-listener.ts` |
| A message sent after a stop (`stopped-session-send`) | Never refused for a stop. | omp holds no message after the person stops a turn. | `omp/src/host.ts` |
