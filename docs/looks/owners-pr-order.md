# Owners: the PR order

Part of [the look map](../looks.md#who-owns-each-rule). The other PR rules are in [PRs](owners-prs.md).

| Rule | Owner | Read by |
| --- | --- | --- |
| The agent's PR order. An `order_prs` call ranks PRs first to last. Each call replaces the order, and an empty list clears it. A new order keeps off the tab each PR it ranks whose last press is a Dismiss, by the person or by a fetch, or that the order it replaces had dismissed. The call links each PR it names that the session does not track yet. Ranked PRs do not count toward `MAX_PRS`, and an order ranks at most `MAX_ORDERED_PRS`. Open ranked PRs draw first, in rank order, and the rest follow in status order. A ranked PR that merges or closes leaves the ranking and joins its status group. Dismiss keeps a PR in the order, so Undo puts it back in place. The call needs `label`, what the person does with the order, and `why`, the agent's reason for it, and answers that it set nothing when either is missing. The tab draws the order's lines above the PR blocks: its title, as "Merge in this order · set by Claude 2m ago", and the reason, muted, under it. No block draws a rank number: the ranked blocks' place shows the order. A muted "Other PRs" line draws above the first unranked block when a ranked block draws before it, so it draws only when the tab draws both ranked and unranked blocks. The line is not a row: it takes no selection, key or click. A dismissed ranked block settles in its place among the ranked blocks. While it settles it still counts as ranked, so when it is the only ranked block left, the order's lines and the "Other PRs" line stay until it finishes settling, and Undo puts it back above the line. A fetch reads `PRS_PER_QUERY` PRs per query, one at a time. | `core/runtime/order-prs-tool.ts:orderPrs`, `core/domain/prs.ts:inPrOrder`, `core/domain/pr-fetch.ts:splitLinked`, `core/view/pr-views.ts:drawnPrs`, `core/view/pr-order.ts:prOrderText`, `core/view/pr-order.ts:prOrderView`, `core/view/pr-order.ts:otherPrsStart`, `core/view/pr-order.ts:OTHER_PRS_TEXT`, `core/domain/pr-fetch.ts:fetchTracked` | Every look. The terminal and desktop draw the order's lines in `hooks/pane/pane-prs.tsx:prOrderLines` and the "Other PRs" line in `otherPrsLine`, the Codex tab in `codex/src/tab-prs.tsx:PrOrderLines` and as a muted group title before the matching `PrEntry`, omp in `omp/src/panel-entries.ts:orderEntries` and as a dim note in `prEntries`, and Herdr in `herdr/src/draw-prs.ts:prTabBlocks` as a `caption` block under the rule between the two PRs, spaced as a group title is. The Codex tab places the line among the blocks it draws, which include a block that is leaving. Each host answers the call through `core/runtime/tools.ts:toolAnswer`. |
| The PR order's changed line and Rank again. The order records each ranked open PR's status, waiting thread ids and the `checkKey` of each failing check when it is set, from the views the tab has, and at each PR's first fetch after. It never replaces a recorded status, and a new `order_prs` call starts a new record. A ranked open PR changed when its status differs, or it has a waiting thread or failing check the record lacks. A merged or closed PR leaves the ranking, so it does not count. The line under the reason reads "2 PRs changed since" while one has, with Rank again, a Talk press that sends the agent `prompts.rankAgain`. It reads "Ranking…" until the reply, then "✓ Ranked". Its label stays "Rank again" after a press, since it already says "again". The line stays while the press is out or was made since the tab was shown. It draws the press's status while the press is out, when the press came after the order was set, or, once the agent's new order replaced that one, until a ranked PR changes again. An order saved before the inbox kept statuses has none, and never draws the line. Its key is `g`, from any row of the tab. | `core/view/pr-order.ts:withOrderStatuses`, which `core/runtime/session-presses.ts:recorded` and `withFetchedPrs` call, `core/view/pr-order.ts:changedRankedPrs`, `core/view/pr-order.ts:prOrderView`, `core/view/pr-order.ts:prOrderActions`, `core/view/pr-tab.ts:applyPrPress`, `core/view/pr-rows.ts:RANK_AGAIN_ID`, `core/domain/prs.ts:prompts`, `core/view/help.ts:helpKeys` | All four looks. Rank again's plan is `prOrderActions`, since it draws on the changed line above the PR blocks. The terminal draws it with `keyRow` and binds `g` with the row keys (`hooks/pane/pane-prs.tsx:prOrderLines`). Desktop draws the native Button, which takes clicks only. The Codex tab draws it in `codex/src/tab-prs.tsx:PrOrderLines`, and its keydown handler takes `g` before the selected row's keys. omp draws the changed line as a row the selection reaches, where Enter presses Rank again, and `handleKey` takes `g` from any row (`omp/src/panel-entries.ts:orderEntries`). Help lists `g` and `m` on every tab. |
