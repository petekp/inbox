# Differences on purpose: the agent and its turns

Part of [the look map](../looks.md#differences-on-purpose).

| Topic | Terminal | Desktop | Codex | Why | Where |
| --- | --- | --- | --- | --- | --- |
| Children on the Status (`status-children`) | Subagents from `agent.spawn`, background commands and Monitor tasks from their tool results, Workflow runs, and Herdr delegates from the `herdr agent` commands Bash runs. A task notification ends a background child. A delegate ends when a wait on it returns. `herdr agent list` also sets its state, at a turn's end and each `HERDR_CHECK_MS` while the Status shows (`hooks/register.tsx:followDelegates`). Herdr's `working` and `blocked` keep it running. `idle` and `done` end it, finished when it had been prompted or seen working. A delegate Herdr no longer lists ends with no word. That check runs only while a delegate runs, and skips one prompted in the last 15 seconds. A subagent's own calls, and a workflow agent's, move its activity. | Same as terminal. | Subagents from the `SubagentStart` and `SubagentStop` hooks, with activity from their `PreToolUse` hooks, and Herdr delegates from `PreToolUse` on Bash. A wait on a delegate ends it at Stop. `herdr agent list` sets its state at Stop, and on the tab's view requests at most each `HERDR_CHECK_MS` while the tab shows the Status (`codex/src/server.ts:checkDelegatesWhenDue`), since a hook process holds no timer. No background commands or workflows. | Codex's hooks report nothing else that runs apart from the turn, and the inbox registers no `PostToolUse` hook. | `hooks/children.ts`, `hooks/register.tsx`, `codex/src/hook.ts` |
| The line under a tool call (`tool-result-line`) | The result under a `record` or `close` call reads the person's line, such as "Question: Which cache should the API use?". A call that changed nothing draws no result. So does a call made before this Claude Code process started, because the mod keeps the lines in memory. The ctrl+o transcript and `--verbose` draw the text the agent read. | Checked live only in a reopened session. The app draws each call as its own card, such as "Used inbox: close i1", with no result until the card is opened. An opened card shows the call's arguments and the text the agent read. The mod's `ToolResult` hook changed neither, even one that drew its own text. A call made after the session opened is not checked, because that takes a model call. | The result shows the text the agent reads, such as "Recorded. The user sees it in the Inbox tab." | Codex draws an MCP tool call's result from its `content`, which is the text the model reads. `structuredContent` reaches the model too, and `_meta` reaches only an MCP App view. A view on `record` would draw a frame in the chat for each call. Claude Code lets a mod redraw a result without changing the stored one. Its docs ask a mod that draws its own compact row to pass when the view is expanded. The desktop app draws a reopened session's tool cards without the mod's `ToolResult` hook. | `hooks/register.tsx:on('ui.render')` for `ToolResult`, `codex/src/server.ts:makeServer` |
| Catch-up and a behind ledger (`catch-up`, `ledger-behind-state`, `failed-update-recovery`) | After a failed update, a reload that cut one off, or when a session starts with earlier turns, the next update reads the whole conversation into the ledger. The mod forks the conversation, or reads Claude Code's transcript when there is nothing to fork. With neither, it runs the pending exchanges. | Same as terminal. | Same rule. The first view of a chat the inbox has never heard from does what the chat's first hook would. The Inbox tab's first `inbox_view` finds the rollout by thread id (`rolloutFor`) and the first hook reads it from `transcript_path`. When the rollout has earlier turns, either one marks the ledger `behind` and starts an update that reads it. A resumed chat shows its rows when its tab opens. If the tab stays closed, the hook of the chat's next message does it. Each Stop saves its turn as `coveredTurn`. A later hook that finds turns in the rollout that ended after `coveredTurn` without a Stop, as while Codex did not run the hooks after an update or after the person interrupted a turn, marks the ledger `behind` too. A prompt it recorded for one of those turns is dropped, so it does not join the next turn's exchange. A clear start covers the turns before it instead. The "not heard from this chat's hooks" message stays until a hook runs. A thread with no readable rollout runs its pending exchanges, and a "may be missing" warning from a dropped reply stays until `/clear`. | Codex runs no hook when a chat is opened, so the only signal that a chat opened is its tab, and a chat whose tab stays closed waits for its next message. Its update runs in a separate `codex exec` process with no conversation to fork, so it reads the rollout. | `hooks/session-host.ts:runUpdates`, `hooks/session.ts:needsCatchUp`, `hooks/session.ts:appliedCatchUp`, `hooks/register.tsx:catchUpReply`, `codex/src/transcript.ts:readRollout`, `codex/src/transcript.ts:rolloutFor`, `codex/src/history.ts:withEarlierHistory`, `codex/src/history.ts:withMissedTurns`, `codex/src/transcript.ts:rolloutReads`, `codex/src/hook.ts:handleHook`, `codex/src/server-catch-up.ts:catchUpOnOpen` |
| Forked conversations (`fork-ledger`) | A fork takes the parent's saved ledger when it loads. | Same as terminal. | A fork takes the parent's saved ledger when its tab opens, or at its first hook if the tab stays closed, from `forked_from_id` in its first `session_meta` row. | Codex runs no hook when a chat is opened, so a fork whose tab stays closed waits for its first message. | `hooks/session.ts:forkedFrom`, `codex/src/history.ts:withEarlierHistory`, `codex/src/rollout-rows.ts:forkedFromId` |
| A running turn (`turn-working`) | A turn runs from the main agent's `turn.start` to its `turn.complete`. While it runs, a Done message waits, and a working subject's mark moves on the Status. A subagent's turn does not count. Loading a conversation clears it, since a reload or a quit can cut off `turn.complete`. Known gap: when the mod turns on during a running turn, as when the desktop app attaches mid-turn, the turn reads as ended and Done messages are not held until the next turn starts. | Same as terminal. | Set at a main-agent UserPromptSubmit. Cleared at Stop and at a SessionStart that is not a compact. Stop does not run for an interrupted turn, and another plugin's Stop can continue a turn after the inbox's Stop ran, so each view request and each press first reads the rollout's tail and sets the flag from its last turn row: running after `task_started`, ended after `task_complete` or `turn_aborted`. A manual `/compact` runs as a turn. Quitting the app, even with SIGKILL, writes `turn_aborted`. After Codex's app-server dies during a turn, the turn reads as running and Done messages wait until the next message. | Stop does not run for an interrupted turn, and another plugin's Stop can continue a turn after the inbox's Stop ran. Codex runs no hook when a chat is opened, and a turn whose app-server dies has no end row in the rollout. The abort row reaches the file within a poll, so the inbox adds no Interrupt hook. | `hooks/session.ts:turnStarted`, `hooks/session.ts:turnEnded`, `hooks/session.ts:cutOffTurn`, `codex/src/hook.ts:handleHook`, `codex/src/transcript.ts:newestTurnEvent`, `codex/src/server-host.ts:syncTurn` |
| A look at the Status | A look starts when the Status shows in the pane and ends when the tab changes, the pane closes, or the band opens the inbox. `syncLook` in `hooks/register.tsx` does both, and the sample leaves the real session alone. | Same as terminal. | Starts when an `inbox_view` request names the Status. Ends when one names another tab. Requests stop when the pane closes, so the next request ends the look at the last request's time. | Codex tells the server only the tab it shows, not that a pane closed. | `hooks/status.ts:lookStarted`, `hooks/status.ts:lookEnded`, `hooks/session.ts:lookStartedOn`, `hooks/session.ts:withLook`, `codex/src/core.ts:lookOnView` |
| Agent task list (`host-task-list`) | `TaskCreate`, `TaskUpdate` and `TodoWrite` calls are read as they run, in `hooks/register.tsx`. Claude Code offers them only when the person turns them on, so the list is usually empty. | Same as terminal. | `update_plan` rows are read from the rollout when the turn stops, so a plan shows from the next Status call and not during the turn. Codex offers the tool by default in neither `codex exec` nor, as far as checked, the app. | Codex runs no hook for `update_plan`, and widening the tool matcher makes every person trust the hook again. | `hooks/host-tasks.ts`, `codex/src/transcript.ts:turnIn`, `codex/src/hook.ts`, `omp/src/host.ts` (reads the newest `todo` result or `/todo` edit on the branch, at each reply and session start) |
| Dialog outcome (`dialog-outcome`) | The activity line says whether the person answered or dismissed the dialog. | Same as terminal. | The line says the dialog is open. | Codex's dialog tool returns at once, and the answer arrives later as a user message. | `hooks/claude.ts:dialogOutcome`, `codex/src/transcript.ts:turnIn` |
| Answering a dialog's copy (`dialog-answer`) | The inbox copies a dialog only once it ended, so an inbox answer is sent as `Re "…": answer`. | Same as terminal. | An inbox question linked to an open dialog question sends its answer in the dialog's reply form, which closes the dialog when the message runs. | Claude Code's dialog blocks the turn. Codex's stays open after its tool returns, until a reply in its form names it. | `hooks/dialogs.ts:linkDialogs`, `codex/src/dialogs.ts:answerMessage` |
| Activity and delegate rows from calls that ran (`ran-call-activity`, `ran-call-delegates`) | A tool call adds its activity line, such as "ran: npm test", when the call ends, and only if a `classic.PostToolUse` or `classic.PostToolUseFailure` hook reported it. A call that a deny rule, the person or a hook blocked adds none. A call counts as run until a call from its source has raised a Post hook since the mod loaded. A source is one MCP server, or Claude Code's own tools. A tool another mod registers and answers in its own `tool.call` hook raises no Post hook, so its calls always add their line. The guard on Team and Enterprise sign-ins skips a mod's `classic.*` hooks, so no Post hook runs there. A `herdr agent` command adds its delegate rows by the same rule. A command that waits for a delegate's turn to end adds its rows as it starts, so they show during the wait. The mod takes them back if the call was blocked. Any other `herdr agent` command adds its rows once it ran. | Same as terminal. | The line is added in `PreToolUse`, before the call is approved. A call the person declines or a hook blocks still adds its line. A blocked `herdr agent` command's delegate rows stay too. | `PreToolUse` fires before `PermissionRequest`. `PostToolUse` cannot show which calls ran, because code mode skips it for a command that runs longer than its wait. How the rollout records a declined command is unverified. GitHub issue #213 tracks a fix. | `hooks/register.tsx:on('tool.call')`, `hooks/mod-records.ts:endedCallRan`, `codex/src/hook.ts`, `hooks/children.ts:delegatesTakenBack` |
| Shell output (`tool-output-urls`, `pr-link-from-output`) | A local URL in a command's output becomes a "URL in output:" activity line. The output of `gh pr create` links the PR it names, as the command finishes. | Same as terminal. | Same lines and links, read from the rollout at Stop. The PR is linked when the turn ends. | Codex runs no hook for a long command's output, so the Stop hook reads the turn's `CommandExecution` rows from the rollout, or older shell calls and their outputs. | `hooks/session.ts:commandFindings`, `hooks/session.ts:noteCommandOutput`, `codex/src/transcript.ts:turnIn` |
| Compare in the background (`compare-in-background`) | The Compare message asks the agent to hand the comparison to a background subagent. The agent's turn ends, and the subagent reports in a later turn. The row reads "Comparing…" until the agent records the question again. After 30 minutes with no report, it reads "No comparison came back". | Same as terminal. | The comparison runs in the agent's turn. The row reads "Comparing…" through the turn, then until the agent records the question again or 30 minutes have passed since the press. | Codex's subagents are experimental and off by default, and no source says one can report after the agent's turn ends. Claude Code's background subagents report in a later turn. Not checked live. | `hooks/presses.ts:messages.compare`, `hooks/view.ts:feedbackOf`, `hooks/ledger.ts:addAgentItem` |
| Turn with no prompt (`exchange-trigger`) | The exchange names the prompt's origin for a turn the person did not start. | Same as terminal. | The exchange reads "unknown". | A Codex hook names no source for a turn that has no prompt. | `hooks/session.ts:endTurn` |
