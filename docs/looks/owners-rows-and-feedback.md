# Owners: rows, presses and feedback

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| Row state | `hooks/rows.ts:RowState`, `hooks/last-actions.ts:isHandedOff` | All four looks |
| A PR hand-off press (Resolve conflicts, Fix, Address, Address all, Merge): its row reads "Resolving conflicts…", "Fixing…", "Addressing…" or "Merging…" with its button out and without "again" until the turn that followed it ends, answered or not. The button then stays out, and ignores presses, until a fetch has read the PR after that turn, or `PR_READ_WAIT_MS` has passed. Every look redraws when the wait ends. It then reads "… again" if the PR still shows the problem. A hand-off pressed while the saved PR predates that turn reads the PR first, and sends nothing once the problem is gone. A hand-off in progress does not hold the PRs tab's other rows in place. | `hooks/feedback.ts:feedbackOf`, `hooks/feedback.ts:prTabHoldSince`, `hooks/last-actions.ts:repliedAtTurnEnd`, `hooks/pr-press.ts:lastPressOf`, `hooks/session-presses.ts:isRepeatWhileOut`, `hooks/pr-press.ts:isViewBeforeReply`, `hooks/timing.ts:timedChangeAt` | Every look, through the shared plans. Every host ends a turn through `hooks/session-turns.ts:turnEnded`, and fetches PRs through `hooks/host-prs.ts:isPrFetchDue`. |
| Row motion: how a row enters, opens, closes, settles and leaves, and how long each move lasts | `hooks/row-motion.ts:stepRow`, `hooks/row-motion.ts:ROW_STATE_MS` | The Codex tab. The other looks don't animate rows: see "Motion and bars" in Differences on purpose. |
| An open question's or task's tree (`asks-tree`): a ◆ in the row's mark column, and one connector from it through the Holds up line, directly under the title, then the context line and the answer options. Each shown answer option is a branch: its button, recommended filled, then its note. The connector ends at the last branch. A note is the description, ending "Recommended: <reason>" on the recommended one. Steps and follow-ups stay below. | The record tool's `why` argument, kept as `Item.recReason` by `hooks/tools.ts:recordItem` and `hooks/ledger-update.ts:addAgentItem`, and dropped when the recommendation moves to another answer (`withRec`). `hooks/rows.ts:optionDescriptionsOf` pairs each option with its description and reason, `hooks/rows.ts:optionNote` writes each note, `rowKeyPlan` lists the options apart from the steps, and `hooks/rows.ts:rowMark` gives an open question or task the ◆ (`ASK_MARK`) while no result mark replaces it. | The terminal draws the connector with ├─, └─ and │ in `hooks/pane-ask-tree.tsx`. Codex draws it with CSS lines in `codex/src/tab-ask-tree.tsx` and `codex/src/tab-css/rows.css`, omp with ├─, └─ and │ in `omp/src/panel-ask-tree.ts`, and the Herdr pane with drawn strokes in `herdr/src/paint-blocks.ts:bodyLineEl`. Desktop draws the connector with 1 pt lines in one frame per option, `hooks/pane-desktop-tree.tsx` and `hooks/pane-desktop-card.tsx`, as the Status tree is drawn. The frames sit inside one Box that holds the card's fill, so the app rounds the card once. |
| A question's answers side by side (`answers-side-by-side`): when two or more answers show and none has a description of its own, a look whose buttons fit one line of the tree draws them on that line, as the tree's last branch. The recommendation's reason, "Recommended: <reason>", goes on one line under them, starting at the first button's label. The recommended answer keeps "(recommended)" and its fill. Otherwise the answers stack as in `asks-tree`. | `hooks/action-plan.ts:rowKeyPlan` offers `answerRow` (`answerRowOf`), with the reason from `hooks/rows.ts:optionReasonLine`. `hooks/action-plan.ts:answersFitLine` is the fit test, which each look runs on its own widths. | The terminal and desktop measure in `hooks/pane-row-keys.tsx:answersFit`, the terminal in cells and desktop by its button estimate (`desktopButtonPt`), and draw one line of buttons in `hooks/pane-ask-tree.tsx:sideBySide` and `hooks/pane-desktop-card.tsx`. Codex measures the drawn buttons before the page paints and when the tree's width changes, in `codex/src/tab-ask-tree.tsx:Answers`. omp measures the button cells in `omp/src/panel-ask-tree.ts:askTreeLines`. The Herdr pane gets `RowBlock.sideBySide` from `herdr/src/draw.ts:sideBySideOf`, and `herdr/src/paint-tree.ts:isSideBySide` measures the buttons. |
| A question's context line (`asks-context-line`): why the agent asked, drawn whole, muted, under the title and after any Holds up line, on the selected row only. Collapsed rows draw no context. | The record tool's `context` argument, kept as `Item.context` by `hooks/question-checks.ts:withBody`, which a record of the open question replaces. `hooks/view.ts:inboxView` sets it as `RowView.contextLine` on an open row. | All five looks, in the row's tree (`asks-tree`) after the Holds up line and before the option lines. The terminal and desktop draw it in `hooks/pane-ask-tree.tsx`, which only the selected row draws, so the desktop row Client does not change. Codex draws it in the panel's `.tree` after any Holds up line (`codex/src/tab-ask-tree.tsx`), so a closing row keeps it until its panel goes. omp draws it in `omp/src/panel-ask-tree.ts`, with no line limit, since the record cuts it at 200 characters. The Herdr pane draws it in the selected row's body after any Holds up line, in `herdr/src/draw.ts:rowBody`, muted like the option lines. |
| A question's earlier answer (`earlier-answers`): one line on the open row, after the context, as "You answered Flick 3 days ago, in glasses-app, to “Which gesture…”", with the answer drawn as an option's label and the rest muted. A folded row and a closed one draw no line. | `hooks/history-store.ts:historyStep`, which each host runs on a session it is about to save, stores the best match on the item as `Item.earlier`, once. `hooks/earlier-answers.ts:earlierLineOf` writes the line, and `hooks/view.ts:inboxView` sets it as `RowView.earlierLine` on an open row. | All five looks, in the row's tree after the context line. The terminal and desktop draw it in `hooks/pane-ask-tree.tsx`, Codex as a `.context-line` paragraph with the answer in `<strong>` (`codex/src/tab-ask-tree.tsx`), and omp in `omp/src/panel-ask-tree.ts`, dim with the answer bold. The Herdr pane draws it as one muted body line in `herdr/src/draw.ts`. |
| A row's result mark: a closed or settled row's, a handed-off row's, and an open row's while the agent works on its Talk press. Its refused-notification Undo, and a settled label's tone | `hooks/help.ts:CLOSED_MARKS`, `hooks/rows.ts:closedMark`, `hooks/rows.ts:settledMark`, `hooks/rows.ts:rowResultMark`, `hooks/rows.ts:ResultMark`, `hooks/rows.ts:canUndoRefused`, `hooks/rows.ts:settledTone`, `hooks/rows.ts:closedTitleTone`, `hooks/arrivals.ts:closedTitleClock`, `hooks/marks.ts:mutedMarkShape` | All four looks. A closed row draws ✓ when handled, ✕ when the person dismissed it, and ✗ when it lapsed: the agent or the inbox model closed it because the work overtook it, or the list was full. Desktop and Codex draw ✗ as a ballot X shape, and the terminal and omp draw ⊘ in its place, so it reads apart from ✕ (see "The cancelled and waiting marks" in Differences on purpose). A settled row draws the mark its Closed line will draw. A handed-off row draws ✓ in the done tone once its send arrives or its open or copy works, and its label stays muted. A reply sent after the item closed settles with its Closed line's mark too. While what a row sent is on its way, its mark runs, as on the Status. While it is held for Undo, unconfirmed or refused, the mark is blank and keeps its place. An open row's mark runs while its Talk press reads "Explaining…" or another working label, so a long reply never looks like a stuck press. The terminal and omp draw it before the label, desktop and Codex in the mark column. Where each look draws it: see "Result marks" in Differences on purpose. The terminal and omp draw a settled label in the done tone only once nothing it sent is on its way. Desktop and Codex draw it as muted text after the title. A settled row's title takes a tint from how the row closed, from the press on, and holds then fades on the clock of a new row's tint, from when a look first draws the row closed (`hooks/arrivals.ts:closedTitleClock`), so it goes even while the row stays in place. A settled PR takes none. |
| Held rows: which closed rows stay in place while the person replies, what their reply sends, and which closed records a prune keeps | `hooks/timing.ts:heldReplies`, `hooks/view.ts:inboxView`, `hooks/rows.ts:fieldExit`, `hooks/timing.ts:keptDiscards`, `hooks/press-reducer.ts:applyPress`, `hooks/session-presses.ts:pruned` | All four looks. The mod passes its open field, drafts and discarded replies. The omp panel keeps its field and drafts in its ui state and passes them with each screen and press, and the host keeps drafts for later panels. The Codex tab sends its replies and discarded replies with each view and press. Every write in the mod, Codex and omp runs `hooks/session-presses.ts:pruned`. It keeps the closed records of the rows `heldRows` names, and of the rows closed or pressed since `shownSince`. So a row drawn in place keeps its record through more closes than `hooks/ledger-close.ts:MAX_CLOSED`. The mod's `hooks/register.tsx:changeSession` sets both fields at each write, from its drafts and its showing. A write to a conversation the pane does not draw clears both, since that conversation holds no rows and has no showing. The Codex server sets both at each view and press. Each view replaces the last, since Codex shows one tab per thread, as `tabSeenAt` also assumes. Codex is not told when a tab closes, so its showing lasts until the next view, and every close in between keeps its record. omp sets both from its panel ui at each press and when the panel shows another tab. It sets `shownSince` alone at open and `heldRows` at close. A press, a Codex view and an omp tab change set both through `hooks/session-presses.ts:withHolds`. |
| Feedback text | `hooks/feedback.ts:feedbackText`, `hooks/feedback.ts:feedbackOf`, `hooks/feedback.ts:markedFeedbackText` | Terminal and desktop through the pane, Codex through the tab, omp through the panel |
| Feedback tone: a press result's color on a row, a PR row or a PR tab line. A failed result is in the error color. A done result carries the ✓ that says the press was made, in its text or in its row's mark column, and draws in that ✓'s done color. Every other result is muted, as is an age after a result | `hooks/feedback.ts:feedbackTone` | All five looks. The terminal and desktop through `feedbackColor` and `withDoneText` in `hooks/pane-row-lines.tsx`, Codex through `tone-done` and `tone-error`, omp through the panel's tones, and Herdr through `feedbackEl` in `herdr/src/paint-blocks.ts` |
| Done labels | `hooks/feedback.ts:DONE_LABELS` | All four looks |
| Closed-row outcome labels | `hooks/rows.ts:outcomeLabel`, set on each closed entry by `hooks/view.ts:inboxView` | All four looks |
| Row content and reply intent | `hooks/rows.ts:RowView`, `hooks/rows.ts:rowTitle`, `hooks/rows.ts:replyHint`, `hooks/feedback.ts:rowFeedbackText` | All four looks |
| Action order, emphasis and icon kind | `hooks/rows.ts:ActionView`, `hooks/action-plan.ts:actionsOf`, `hooks/action-plan.ts:rowKeyPlan` | All four looks |
