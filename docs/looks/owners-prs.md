# Owners: PRs

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| PR readiness and prompts. A PR shows "Ready to merge" and its Merge button only while its view is fresh: a fetch read it within `PR_FRESH_MS` and no fetch failed since. Its other readiness, such as Blocked or Draft, shows either way. Requested changes block a PR only while something else waits on the person, and then read "Waiting on the reviewer". The status words name the host's agent, as in "sent to Codex". | `core/domain/prs.ts:readiness`, `core/view/pr-rows.ts:shownReadiness`, `core/domain/prs.ts:prNeedsYou`, `core/domain/prs.ts:prompts` | The mod, the Codex tab and the omp panel, each passing its agent's name |
| A question's or task's Open PR step (`named-pr-link`): one step that opens each PR the item's ask or context names and none of its steps links already. It names a PR by a GitHub PR link, as `owner/repo#12`, or as `#12`. A bare number is the one PR on the tab or the branch's PR with that number. Else, only after a PR word such as "PR", "merge" or "review", or in a list after one, it is that number in the session's repository: the branch PR's repository, else the folder's GitHub remote that gh would pick (`upstream`, then `github`, then `origin`). So "#333" as a color and "Option #1" offer nothing, and a bare number that a PR link in the text also names is that link's PR. A PR the session tracks reads "Open PR #12", including one the PRs tab leaves out. One it does not track reads "Open #12", or "Open repo#12" in another repository, since the number may be an issue's and GitHub sends a pull link of an issue to the issue. The press opens it as any link step does, with "Opening…" and then its result on the row. A step the agent or the inbox model gave as a link to a GitHub PR's or issue's own page takes the same name, whatever name it came with, as "Open PR #12", "Open #12" or "Open repo#12", since a name such as "PR" does not say which. A link to a page inside one, such as its diff or a comment, takes that name only when it has none. Such a link, as any link to a PR or issue of that number, counts as linking the PR, since issues and PRs share one set of numbers. Any other link with no name reads "Open" and its host, and a name that starts with "Open" loses that word, so "Open token page" reads "Open token page", not "Open Open token page". | `core/domain/pr-fetch.ts:sessionPrs`, `core/domain/help-steps.ts:stepsOf`, `core/domain/prs.ts:namedPrs`. Each host reads the remote with the branch through `core/domain/gh.ts:gitPlaceIn` and saves it as `Place.repo` through `core/runtime/session-turns.ts:placed`. | Every host, in views and press validation, so all five looks draw the step through `rowKeyPlan` as any other step. The mod reads the remote in `hooks/mod/mod-commands.ts:placeChange`, Codex in `codex/src/hook.ts` at the start and at Stop, omp in `omp/src/host-turns.ts`. |
| PR presses, which PRs the tab draws, which linked PRs it keeps, and how a PR is fetched | `core/view/pr-tab.ts:applyPrPress`, `core/view/pr-views.ts:drawnPrs`, `core/domain/prs.ts:isKeptPr`, `core/domain/pr-fetch.ts:isLeftOut`, `core/view/pr-views.ts:isViewKept`, `core/runtime/session-presses.ts:pruned`, `core/domain/pr-fetch.ts:fetchTracked`, `core/domain/pr-query.ts:prsQuery`, `core/domain/pr-query.ts:readPrNode`, `core/view/pr-press.ts:isPrReadFirstPress`, `core/runtime/host-press.ts:startPress` | The mod, the Codex server and omp's host. Each fetch runs through `core/runtime/host-prs.ts:fetchPrs`. It reads every tracked PR, with its threads, checks and author, in one GraphQL query per `PRS_PER_QUERY` of them, in any number of repos, and one more `gh pr view` run for the branch's PR when the tab shows. Each host polls through `core/runtime/host-prs.ts:isPrFetchDue`: the PRs are due again `PRS_REFRESH_MS` (2 minutes) after the last fetch while the session's PRs tab is shown, and `PRS_HIDDEN_REFRESH_MS` (10 minutes) after it while the tab is not, since every session spends from one GitHub budget and a hidden tab's PRs only feed the counts. Either way a press fetches at once, and an agent's reply or a new PR makes the PRs due 15 seconds after the last. A change that puts a PR on the tab, a link or a PR the agent's order ranks, fetches at once, by `core/runtime/host-prs.ts:addsTabPr`, since the Herdr look may never ask for a read. Every host checks it after a `record` or `order_prs` call, the mod and omp also when a reply ends, and omp after a command. The mod fetches for a command's link in `hooks/mod/mod-prs.ts:linkPrs`. In Codex, the hook process saves a reply's or a command's links and starts no fetch. In a Herdr app terminal the server watches the saved sessions, and fetches once for each tracked PR a save shows with no view and no `PrViews.unread` entry, until a save shows one (`codex/src/server-pr-links.ts:linkedPrReads`). A tracked PR is new while it has no view and no `PrViews.unread` entry, but none is while gh is missing. The mod's poll timer asks `isPrPollDue` every `PR_POLL_MS`; the Codex tab asks it on each view it polls, with its shown tab; omp's panel asks it when the PRs tab is shown and every `PR_POLL_MS` with its shown tab, and does not poll while the panel is closed. A merged PR is never read again. A closed one can be reopened, but rarely and never in a hurry, so it is read again every `CLOSED_PR_REFRESH_MS`, or when a press asks. A view another session of the same host read within `PR_SHARED_MS`, and since this session last read the PR, stands in for a read, unless a press asked. The mod shares through one engine store key (`hooks/mod/mod-pr-shared.ts:prSharedStore`), the Codex server and omp in their process, since each serves every chat or session. Each fetch keeps a shared view only for `PR_SHARED_MS` after its read. Nothing is shared across hosts: no store serves all three, and a new file would need an owner. A PR the query cannot find keeps its last view with the reason on it, as "not found on GitHub, or no access to acme/app", since GitHub answers NOT_FOUND for both; a tracked PR with no view yet is named in `PrViews.unread` with its reason or the whole fetch's. A check is its latest run on the head commit, by workflow and name, so a run that a passing re-run replaced does not offer Fix. `core/domain/prs.ts:checkKey` names a check by its workflow and name, as in "CI / test", or by its name alone when it has no workflow. A check's row id and its presses use that key, so a check named "test" in CI and one named "test" in Nightly are two rows. A read-first press, Resolve conflicts or a check's Fix or Re-run, first fetches the PRs through the host's `refreshPrs` while its row reads "Refreshing PR #12…". It applies only when the fetched view still shows the problem. Otherwise it reads the stale note, or, when the fetch did not read the PR, "Could not refresh PR #12" and why. While the press is out, the Codex tab draws that text from `core/view/pr-press.ts:prPressEffect` until a poll shows the server's record of the press. It then draws the record's text, as the other looks do, such as Re-run's "Starting a re-run of CI…" (`codex/src/tab-press.ts:outPending`). The tab keeps polling while a press is out, and the press's own reply replaces any view a poll read meanwhile. A session keeps a view while `isViewKept` keeps it: the tab tracks the PR, the PR is linked and left out, or the person dismissed it less than `core/view/pr-views.ts:DISMISSED_VIEW_KEPT_MS` (one minute) ago or during the writing look's showing that still lasts. The minute keeps the view for a look that presses through another host and saves no showing of its own, as Herdr does, and each look still draws the settled block only while its own showing lasts. Every host passes its clock to `core/runtime/session-presses.ts:pruned`, which drops each other view on every write, since no look draws it. That covers the view of a PR the tab stopped tracking, as when its link went or the branch changed, and a dismissed PR's view once both its minute and its showing end. |
| gh notices: gh missing, gh not signed in, or a cause that stopped the whole fetch: GitHub's limit, GitHub out of reach, gh timed out, or an error GitHub gave | `core/view/pr-rows.ts:ghNoticeOf`, `core/view/pr-rows.ts:GH_MISSING_TEXT`, `core/view/pr-rows.ts:GH_SIGNED_OUT_TEXT`, `core/view/pr-rows.ts:fetchFailureNotice`, `core/domain/pr-query.ts:runFailureOf`, `core/domain/pr-query.ts:asksForSignIn`, `core/domain/gh.ts:TIMED_OUT_CODE` | All four looks. Each draws the notice as the hint of an empty PRs tab, or as a banner above the PRs. A missing gh comes first, then a sign-in, then the fetch's cause. A cause that stopped the whole fetch is saved as `PrViews.failure` and shown once, at the top: the limit reads "GitHub's limit is used up. The PRs refresh after it resets at 4:46 PM.", with the reset from `gh api rate_limit`, which GitHub answers under a GraphQL limit. Every PR keeps its last view with no error of its own. A limit stops every session of the host from fetching until the reset, or for `LIMIT_RETRY_MS` when GitHub gave none, through the shared record `core/runtime/host-prs.ts:fetchPrs` reads; a press still reads, since GitHub's answer says whether the limit holds. The next fetch that reads the PRs clears the failure. The mod sets `PrViews.isGhMissing` when `gh --version` cannot start after a failed fetch. It runs `gh --version` in `/`, and every other gh run in the session's folder as `$.session.root()` gives it at that moment (`hooks/mod/mod-commands.ts:sessionFolder`), or in `/` when that folder is gone. macOS fails a run in a folder that is gone as if the program were missing, and the Claude app deletes the folder a new session starts in. The Codex server and omp set their own flag from `core/domain/gh.ts:ghFinder`, and look for gh again after a fetch where a gh run ended with code -1. A gh run still running at its timeout ends with code -2 in each host's run. `fetchPrs` does not look for gh again after it, and a `gh --version` that times out counts as found. The mod's engine rejects `$.process.run` with no code both when the command cannot start and when it times out. The mod reads a rejection that comes at or after the timeout, timed with `$.clock`, as a timeout, and a sooner one as a gh that cannot start. A timed-out run leaves the sign-in notice as it was, and says so at the top as a fetch failure, so the person knows the views are old and can press Refresh PRs. `core/runtime/host-prs.ts:fetchPrs` saves `PrViews.isGhSignedOut` from the fetch's own gh runs, with no extra run. It is true when a run exits 4, gh's code for no token, or fails with HTTP 401, as for an expired or revoked token. The next fetch that gets an answer from gh sets it again, so the notice leaves once gh is signed in. A PR that gh could not read for want of a sign-in keeps its last view, with no "Last refresh failed" line. The Codex tab and omp read the flag from the shared view's `prs.isGhSignedOut`, and the mod from its saved `PrViews`. |
| PR button order, labels, emphasis and icon kind | `core/view/pr-tab.ts:threadActions`, `core/view/pr-tab.ts:checkActions`, `core/view/pr-tab.ts:prBlockActions` | All four looks. A cancelled check offers Re-run in Fix's place, a Local press with key `a`. It offers only Open log when its details link names no GitHub Actions run, or when a failing check shares its run, since a failing job cancels the other jobs of its run and that run needs Fix first (`core/view/pr-press.ts:rerunEffect`). Re-run asks gh to re-run the check's workflow run, then fetches the PRs, whether or not gh started it. `core/view/pr-press.ts:rerunArgs` holds the command and `core/runtime/host-prs.ts:rerunRun` runs it through the host's gh. GitHub re-runs the run's failed and cancelled jobs and keeps the jobs that passed. It refuses while the run is still running, and `rerunRun` reads that refusal as started. Any other refusal shows gh's reason in red. The result shows on the check row, and on the PR block once no check row of the block holds it (`core/view/pr-rows.ts:isBlockPressShown`), because the fetch drops the row once the run is running. Until then the block draws no press line, so the rows under it do not move while the press is out. While one row's re-run is out, Re-run on the other rows of that run draws out and its press does nothing. |
| Refresh PRs, once, at the top of the tab, in the notice that gives its cause or else under the notices, while a PR could not be read: a cause stopped the whole fetch, or a PR of its own could not be read. | A finished PR settles on its own. When a fetch first finds a tab PR merged, or closed without a merge, the PR leaves the tab as Dismiss would take it: unlinked, and dismissed from the agent's order if it ranks it. While the look shows the PRs tab, its block settles in place as "Merged" with ✓, or "Closed" with the lapsed mark, and offers Undo for the settle window. Undo links it again, and the tab keeps it, since a later fetch finds it already finished. The branch's own PR stays while the branch has it. Once a fetch finds the branch has another PR or none, the old one settles the same way if it is finished and the tab still tracks it. A reply that names a PR whose last press is a Dismiss, by the person or by a fetch, does not link it again. | `core/view/pr-tab.ts:withFinishedPrsSettled`, which `core/runtime/session-presses.ts:withFetchedPrs` calls, `core/runtime/session-turns.ts:endTurn`, `core/view/pr-views.ts:drawnPrs`, `core/view/pr-views.ts:PR_MERGED_LABEL`, `core/view/pr-views.ts:PR_CLOSED_LABEL` | All four looks draw the settled block as a dismissed one, through `drawnPrs`. |
