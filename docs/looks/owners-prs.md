# Owners: PRs

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| PR readiness and prompts. Requested changes block a PR only while something else waits on the person, and then read "Waiting on the reviewer". The status words name the host's agent, as in "sent to Codex". | `hooks/prs.ts:readiness`, `hooks/prs.ts:prNeedsYou`, `hooks/prs.ts:prompts` | The mod, the Codex tab and the omp panel, each passing its agent's name |
| Linked-PR help steps: a task's Open PR step for any PR the session linked, including one the PRs tab leaves out | `hooks/pr-fetch.ts:itemPrSteps` | Every host, in views and press validation |
| PR presses, which PRs the tab draws, which linked PRs it keeps, and how a PR is fetched | `hooks/pr-tab.ts:applyPrPress`, `hooks/pr-views.ts:drawnPrs`, `hooks/prs.ts:isKeptPr`, `hooks/pr-fetch.ts:isLeftOut`, `hooks/pr-views.ts:isViewKept`, `hooks/session-presses.ts:pruned`, `hooks/pr-fetch.ts:fetchTracked`, `hooks/pr-query.ts:prsQuery`, `hooks/pr-query.ts:readPrNode`, `hooks/pr-press.ts:isPrReadFirstPress`, `hooks/host-press.ts:startPress` | The mod, the Codex server and omp's host. Each fetch runs through `hooks/host-prs.ts:fetchPrs`. It reads every tracked PR, with its threads, checks and author, in one GraphQL query per `PRS_PER_QUERY` of them, in any number of repos, and one more `gh pr view` run for the branch's PR when the tab shows. Each host polls through `hooks/host-prs.ts:isPrFetchDue`: the PRs are due again `PRS_REFRESH_MS` (2 minutes) after the last fetch while the session's PRs tab is shown, and `PRS_HIDDEN_REFRESH_MS` (10 minutes) after it while the tab is not, since every session spends from one GitHub budget and a hidden tab's PRs only feed the counts. A fetch after an agent's reply, 15 seconds after the last, and a press's fetch run the same either way. The mod's poll timer ticks every 2 minutes and asks that rule; the Codex tab asks it on each view it polls, with its shown tab; omp's panel asks it when the PRs tab is shown and every 2 minutes with its shown tab, and does not poll while the panel is closed. A merged PR is final and is never read again. A closed one can be reopened, but rarely and never in a hurry, so it is read again every `CLOSED_PR_REFRESH_MS`, or when a press asks. A view another session of the same host read within `PR_SHARED_MS`, and since this session last read the PR, stands in for a read, unless a press asked, so a session's own fetches read GitHub as they did before sharing: the mod shares through one engine store key (`hooks/mod-pr-shared.ts:prSharedStore`), the Codex server and omp in their process, since each serves every chat or session. Each fetch keeps a shared view only for `PR_SHARED_MS` after its read, since no fetch uses it after that. Nothing is shared across hosts: no store serves all three, and a new file would need an owner. A PR the query cannot find keeps its last view with the reason on it, as "not found on GitHub, or no access to acme/app", since GitHub answers NOT_FOUND for both; a tracked PR with no view yet is named in `PrViews.unread` with its reason. A check is its latest run on the head commit, by workflow and name, so a run that a passing re-run replaced does not offer Fix. `hooks/prs.ts:checkKey` names a check by its workflow and name, as in "CI / test", or by its name alone when it has no workflow. A check's row id and its presses use that key, so a check named "test" in CI and one named "test" in Nightly are two rows. A read-first press, Resolve conflicts or a check's Fix or Re-run, first fetches the PRs through the host's `refreshPrs` while its row reads "Refreshing PR #12…". It applies only when the fetched view still shows the problem. Otherwise it reads the stale note, or, when the fetch did not read the PR, "Could not refresh PR #12" and why. While the press is out, the Codex tab draws that text from `hooks/pr-press.ts:prPressEffect` until a poll shows the server's record of the press. It then draws the record's text, as the other looks do, such as Re-run's "Starting a re-run of CI…" (`codex/src/tab-press.ts:outPending`). The tab keeps polling while a press is out, and the press's own reply replaces any view a poll read meanwhile. A session keeps a view while `isViewKept` keeps it: the tab tracks the PR, the PR is linked and left out, or the person dismissed it during the showing that still lasts. Every write's `hooks/session-presses.ts:pruned` drops each other view, since no look draws it. That covers the view of a PR the tab stopped tracking, as when its link went or the branch changed, and a dismissed PR's view once its showing ends. |
| gh notices: gh missing, gh not signed in, or a cause that stopped the whole fetch: GitHub's limit, GitHub out of reach, gh timed out, or an error GitHub gave | `hooks/pr-rows.ts:ghNoticeOf`, `hooks/pr-rows.ts:GH_MISSING_TEXT`, `hooks/pr-rows.ts:GH_SIGNED_OUT_TEXT`, `hooks/pr-refresh.ts:fetchFailureNotice`, `hooks/pr-query.ts:runFailureOf`, `hooks/pr-query.ts:asksForSignIn`, `hooks/gh.ts:TIMED_OUT_CODE` | All four looks. Each draws the notice as the hint of an empty PRs tab, or as a banner above the PRs. A missing gh comes first, then a sign-in, then the fetch's cause. A cause that stopped the whole fetch is saved as `PrViews.failure` and shown once, at the top: the limit reads "GitHub's limit is used up. The PRs refresh after it resets at 4:46 PM.", with the reset from `gh api rate_limit`, which GitHub answers under a GraphQL limit. Every PR keeps its last view with no error of its own. A limit stops every session of the host from fetching until the reset, or for `LIMIT_RETRY_MS` when GitHub gave none, through the shared record `hooks/host-prs.ts:fetchPrs` reads; a press still reads, since GitHub's answer says whether the limit holds. The next fetch that reads the PRs clears the failure. The mod sets `PrViews.isGhMissing` when `gh --version` cannot start after a failed fetch. The Codex server and omp set their own flag from `hooks/gh.ts:ghFinder`, and look for gh again after a fetch where a gh run ended with code -1. A gh run still running at its timeout ends with code -2 in each host's run. `fetchPrs` does not look for gh again after it, and a `gh --version` that times out counts as found. The mod's engine rejects `$.process.run` with no code both when the command cannot start and when it times out. The mod reads a rejection that comes at or after the timeout, timed with `$.clock`, as a timeout, and a sooner one as a gh that cannot start. A timed-out run leaves the sign-in notice as it was, and says so at the top as a fetch failure, so the person knows the views are old and can press Refresh PRs. `hooks/host-prs.ts:fetchPrs` saves `PrViews.isGhSignedOut` from the fetch's own gh runs, with no extra run. It is true when a run exits 4, gh's code for no token, or fails with HTTP 401, as for an expired or revoked token. The next fetch that gets an answer from gh sets it again, so the notice leaves once gh is signed in. A PR that gh could not read for want of a sign-in keeps its last view, with no "Last refresh failed" line. The Codex tab and omp read the flag from the shared view's `prs.isGhSignedOut`, and the mod from its saved `PrViews`. |
| PR button order, labels, emphasis and icon kind | `hooks/pr-tab.ts:threadActions`, `hooks/pr-tab.ts:checkActions`, `hooks/pr-tab.ts:prBlockActions` | All four looks. A cancelled check offers Re-run in Fix's place, a Local press with key `a`. It offers only Open log when its details link names no GitHub Actions run, or when a failing check shares its run, since a failing job cancels the other jobs of its run and that run needs Fix first (`hooks/pr-press.ts:rerunEffect`). Re-run asks gh to re-run the check's workflow run, then fetches the PRs, whether or not gh started it. `hooks/pr-press.ts:rerunArgs` holds the command and `hooks/host-prs.ts:rerunRun` runs it through the host's gh. GitHub re-runs the run's failed and cancelled jobs and keeps the jobs that passed. It refuses while the run is still running, and `rerunRun` reads that refusal as started. Any other refusal shows gh's reason in red. The result shows on the check row, and on the PR block once no check row of the block holds it (`hooks/pr-rows.ts:isBlockPressShown`), because the fetch drops the row once the run is running. Until then the block draws no press line, so the rows under it do not move while the press is out. While one row's re-run is out, Re-run on the other rows of that run draws out and its press does nothing. |
| Refresh PRs, once, at the top of the tab, under the notices, while a PR could not be read: a cause stopped the whole fetch, or a PR of its own could not be read. The line names the PRs that could not be read, as "#12 could not be read" with its reason when no block shows it, or "#12 and #14 could not be read", and is bare under a notice, which already says the cause. Its press reads "Refreshing PRs…", then "✓ Refreshed PRs" only once every tracked PR was read, else in red why not, as "Could not refresh PRs: GitHub's limit resets at 4:46 PM" or "Could not refresh PRs: #12 could not be read". The line stays while the press is out or since the tab was shown, and goes once no PR fails to read and the press's status has faded. A PR whose own cause the fetch gave keeps its block, with "Last refresh failed: not found on GitHub, or no access to acme/app" under its title. | `hooks/pr-refresh.ts:prRefreshView`, `hooks/pr-refresh.ts:refreshProblem`, `hooks/pr-tab.ts:applyPrPress`, `hooks/host-press.ts:startPress`, `hooks/pr-rows.ts:PR_REFRESH_ID`, `hooks/pr-rows.ts:prRefreshFailedText` | All four looks, as Rank again's line is drawn: the terminal and desktop in `hooks/pane-prs.tsx`, the Codex tab in `codex/src/tab-prs.tsx`, and omp as a row the selection reaches, where Enter presses it (`omp/src/panel-entries.ts`). The press runs the `refresh-prs` effect through each host's `refreshPrs`, which fetches as a press asks, and its result is `refreshProblem` on the session after it. |
| A finished PR settles on its own. When a fetch first finds a tab PR merged, or closed without a merge, the PR leaves the tab as Dismiss would take it: unlinked, and dismissed from the agent's order if it ranks it. While the look shows the PRs tab, its block settles in place as "Merged" with ✓, or "Closed" with the lapsed mark, and offers Undo for the settle window. Undo links it again, and the tab keeps it, since a later fetch finds it already finished. The branch's own PR stays while the branch has it. Once a fetch finds the branch has another PR or none, the old one settles the same way if it is finished and the tab still tracks it. A reply that names a PR whose last press is a Dismiss, by the person or by a fetch, does not link it again. | `hooks/pr-tab.ts:withFinishedPrsSettled`, which `hooks/session-presses.ts:withFetchedPrs` calls, `hooks/session-turns.ts:endTurn`, `hooks/pr-views.ts:drawnPrs`, `hooks/pr-views.ts:PR_MERGED_LABEL`, `hooks/pr-views.ts:PR_CLOSED_LABEL` | All four looks draw the settled block as a dismissed one, through `drawnPrs`. |
| Clear merged and closed, at the top of the PRs tab: on a line of its own under the notices and the Refresh PRs line, and above the agent's order and the PR blocks, while the tab draws a merged or closed PR other than the branch's own. Refresh PRs sits on its own line above it, or inside the notice, so the two never share a line. Its key is `m`, from any row of the tab. It dismisses each merged or closed PR the tab tracks as the PR's own Dismiss does, so each block settles as "Dismissed" with its own Undo, and the button goes. It is stale once no such PR is left. It skips the branch's own PR, which has no Dismiss. | `hooks/pr-tab.ts:prClearActions`, which `hooks/session-view.ts:prTabOf` puts in the view as `prs.clear`, `hooks/pr-tab.ts:applyPrPress`, `hooks/pr-rows.ts:CLEAR_FINISHED_ID`, `hooks/pr-views.ts:prUndoBlockAfter` | Every look. The terminal draws it with `keyRow` and binds `m` with the row keys (`hooks/pane-prs.tsx:prClearLines`). In an inline pane, the press reveals the Undo of the last block it settled, as a single Dismiss reveals its own (`hooks/register.tsx:undoKeyAfterPress`). That is the Undo the undo key takes, never one an earlier press left. Desktop draws the native Button, which takes clicks only. The Codex tab draws it in `codex/src/tab-prs.tsx:Prs`, closes its line through the row states as it leaves (`codex/src/tab-pr-steps.ts:stepPrs`), and its keydown handler takes `m` before the selected row's keys. omp draws it as a line of its own that the selection reaches, where Enter presses it, and `handleKey` takes `m` from any row (`omp/src/panel-entries.ts:prEntries`). The Herdr panel draws it as a line block (`herdr/src/draw-prs.ts:clearLine`), whose `m` `keyMove` takes from any row, and its press reaches the host through a press file. |
| The agent's PR order. An `order_prs` call ranks PRs first to last. Each call replaces the order, and an empty list clears it. A new order keeps off the tab each PR it ranks whose last press is a Dismiss, by the person or by a fetch, or that the order it replaces had dismissed. The call links each PR it names that the session does not track yet. Ranked PRs do not count toward `MAX_PRS`, and an order ranks at most `MAX_ORDERED_PRS`. Open ranked PRs draw first, in rank order, and the rest follow in status order. A ranked PR that merges or closes leaves the ranking and joins its status group. Dismiss keeps a PR in the order, so Undo puts it back in place. The call needs `label`, what the person does with the order, and `why`, the agent's reason for it, and answers that it set nothing when either is missing. The tab draws the order's lines above the PR blocks: its title, as "Merge in this order · set by Claude 2m ago", and the reason, muted, under it. It draws "1." before each open ranked block's number. A dismissed block keeps its rank while it settles but draws no number, so the numbers after it do not change. A fetch runs at most `GH_RUNS_AT_ONCE` gh runs at once. | `hooks/tools.ts:orderPrs`, `hooks/prs.ts:inPrOrder`, `hooks/pr-fetch.ts:splitLinked`, `hooks/pr-views.ts:drawnPrs`, `hooks/pr-order.ts:prOrderText`, `hooks/pr-order.ts:prOrderView`, `hooks/pr-order.ts:prRankText`, `hooks/pr-fetch.ts:fetchTracked` | All four looks. Each host answers the call through `hooks/tools.ts:toolAnswer`. |
| The PR order's changed line and Rank again. | A PR row's mark, title and meta line, which PR rows wait, and which buttons are follow-ups | `hooks/pr-rows.ts:threadRowText`, `hooks/pr-rows.ts:checkRowText`, `hooks/help.ts:PR_MARKS`, `hooks/pr-rows.ts:prRowWaits`, `hooks/pr-rows.ts:splitFollowUps`, `hooks/pr-rows.ts:PR_QUOTE_CHARS` | All four looks. Once handed to the agent, its mark runs while the message is queued, is blank while it is unconfirmed, and is ✓ in the done tone once it arrived. A failing check draws ▲ in the error tone.
