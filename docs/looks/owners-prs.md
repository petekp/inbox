# Owners: PRs

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| PR readiness and prompts | `hooks/prs.ts:readiness`, `hooks/prs.ts:prompts` | The mod, the Codex tab and the omp panel |
| Linked-PR help steps: a task's Open PR step for any PR the session linked, including one the PRs tab leaves out | `hooks/pr-fetch.ts:itemPrSteps` | Every host, in views and press validation |
| PR presses, which PRs the tab draws, which linked PRs it keeps, and how a PR is fetched | `hooks/pr-tab.ts:applyPrPress`, `hooks/pr-views.ts:drawnPrs`, `hooks/prs.ts:isKeptPr`, `hooks/pr-fetch.ts:isLeftOut`, `hooks/pr-views.ts:isViewKept`, `hooks/session-presses.ts:pruned`, `hooks/pr-fetch.ts:fetchTracked`, `hooks/prs.ts:readView`, `hooks/pr-press.ts:isPrFixPress`, `hooks/session-host.ts:startPress` | The mod, the Codex server and omp's host. Each fetch runs through `hooks/session-host.ts:fetchPrs`. A check is its latest run on the head commit, by workflow and name, so a run that a passing re-run replaced does not offer Fix. A fix press, Resolve conflicts or a check's Fix, first fetches the PRs through the host's `refreshPrs` while its row reads "Refreshing PR #12…". It sends only when the fetched view still shows the problem. Otherwise it reads the stale note, or, when the fetch did not read the PR, "Could not refresh PR #12" and why. The Codex tab draws the same text while its press is out, from `hooks/pr-press.ts:prPressEffect`. A session keeps a view while `isViewKept` keeps it: the tab tracks the PR, the PR is linked and left out, or the person dismissed it during the showing that still lasts. Every write's `hooks/session-presses.ts:pruned` drops each other view, since no look draws it. That covers the view of a PR the tab stopped tracking, as when its link went or the branch changed, and a dismissed PR's view once its showing ends. |
| gh notices: gh missing, or gh not signed in | `hooks/pr-rows.ts:ghNoticeOf`, `hooks/pr-rows.ts:GH_MISSING_TEXT`, `hooks/pr-rows.ts:GH_SIGNED_OUT_TEXT`, `hooks/pr-fetch.ts:asksForSignIn`, `hooks/gh.ts:TIMED_OUT_CODE` | All four looks. Each draws the notice as the hint of an empty PRs tab, or as a banner above the PRs. A missing gh comes first. The mod sets `PrViews.isGhMissing` when `gh --version` cannot start after a failed fetch. The Codex server and omp set their own flag from `hooks/gh.ts:ghFinder`, and look for gh again after a fetch where a gh run ended with code -1. A gh run still running at its timeout ends with code -2 in each host's run. `fetchPrs` does not look for gh again after it, and a `gh --version` that times out counts as found. The mod's engine rejects `$.process.run` with no code both when the command cannot start and when it times out. The mod reads a rejection that comes at or after the timeout, timed with `$.clock`, as a timeout, and a sooner one as a gh that cannot start. A timed-out run leaves the sign-in notice as it was. Each PR it could not read keeps its last view, with "Last refresh failed: gh did not answer within 20 seconds", so the person knows the view is old and can press Refresh PRs. `hooks/session-host.ts:fetchPrs` saves `PrViews.isGhSignedOut` from the fetch's own gh runs, with no extra run. It is true when a run exits 4, gh's code for no token, or fails with HTTP 401, as for an expired or revoked token. The next fetch that gets an answer from gh sets it again, so the notice leaves once gh is signed in. A PR that gh could not read for want of a sign-in keeps its last view, with no "Last refresh failed" line. The Codex tab and omp read the flag from the shared view's `prs.isGhSignedOut`, and the mod from its saved `PrViews`. |
| PR button order, labels, emphasis and icon kind, including Refresh PRs under a failed refresh | `hooks/pr-tab.ts:threadActions`, `hooks/pr-tab.ts:checkActions`, `hooks/pr-tab.ts:prBlockActions` | All four looks. `hooks/session-host.ts:startPress` runs the press's `refresh-prs` effect through each host's `refreshPrs`. |
| The PRs tab's own buttons: Dismiss merged, after the PR blocks and before the older-PRs line, while the tab draws a merged PR other than the branch's own. Its key is `m`, from any row of the tab. It dismisses each merged PR the tab tracks as the PR's own Dismiss does, so each block settles with its own Undo. It is stale once no such PR is left. | `hooks/pr-tab.ts:prTabActions`, which `hooks/session-view.ts:prTabOf` puts in the view as `prs.tabActions`, `hooks/pr-tab.ts:applyPrPress`, `hooks/pr-rows.ts:DISMISS_MERGED_ID` | All four looks. The terminal draws it with `keyRow` and binds `m` with the row keys (`hooks/register.tsx:prTabButtons`). In an inline pane, the press reveals the Undo of the last block it settled, as a single Dismiss reveals its own (`hooks/register.tsx:undoKeyAfterPress`). Desktop draws the native Button, which takes clicks only. The Codex tab draws it in `codex/src/tab-prs.tsx:Prs`, and its keydown handler takes `m` before the selected row's keys. omp draws it as a line of its own that the selection reaches, where Enter presses it, and `handleKey` takes `m` from any row (`omp/src/panel-entries.ts:prEntries`). |
| The agent's PR order. An `order_prs` call ranks PRs first to last. Each call replaces the order, and an empty list clears it. The call links each PR it names that the session does not track yet. Ranked PRs do not count toward `MAX_PRS`, and an order ranks at most `MAX_ORDERED_PRS`. Open ranked PRs draw first, in rank order, and the rest follow in status order. A ranked PR that merges or closes leaves the ranking and joins its status group. Dismiss keeps a PR in the order, so Undo puts it back in place. The call needs `label`, what the person does with the order, and `why`, the agent's reason for it, and answers that it set nothing when either is missing. The tab draws the order's lines above the PR blocks: its title, as "Merge in this order · set by Claude 2m ago", and the reason, muted, under it. It draws "1." before each open ranked block's number. A dismissed block keeps its rank while it settles but draws no number, so the numbers after it do not change. A fetch runs at most `GH_RUNS_AT_ONCE` gh runs at once. | `hooks/tools.ts:orderPrs`, `hooks/prs.ts:inPrOrder`, `hooks/pr-fetch.ts:splitLinked`, `hooks/pr-views.ts:drawnPrs`, `hooks/pr-order.ts:prOrderText`, `hooks/pr-order.ts:prOrderView`, `hooks/pr-order.ts:prRankText`, `hooks/pr-fetch.ts:fetchTracked` | All four looks. The terminal and desktop draw the lines and the rank in `hooks/register.tsx:prOrderLines` and the PR block's title line, the Codex tab in `codex/src/tab-prs.tsx:PrOrderLines` and `PrBlock`, and omp in `omp/src/panel-entries.ts:orderEntries` and `prEntries`, with the rank dim before the PR's number. Each host answers the call through `hooks/tools.ts:toolAnswer`. |
| The PR order's changed line and Rank again. The order records each ranked open PR's status, waiting thread ids and failing check names when it is set, from the views the tab has, and at each PR's first fetch after. It never replaces a recorded status, and a new `order_prs` call starts a new record. A ranked open PR changed when its status differs, or it has a waiting thread or failing check the record lacks. A merged or closed PR leaves the ranking, so it does not count. The line under the reason reads "2 PRs changed since" while one has, with Rank again, a Talk press that sends the agent `prompts.rankAgain`. It reads "Ranking…" until the reply, then "✓ Ranked". Its label stays "Rank again" after a press, since it already says "again". The line stays while the press is out or was made since the tab was shown. It draws the press's status while the press is out, when the press came after the order was set, or, once the agent's new order replaced that one, until a ranked PR changes again. An order saved before the inbox kept statuses has none, and never draws the line. Its key is `g`, from any row of the tab. | `hooks/pr-order.ts:withOrderStatuses`, which `hooks/session-presses.ts:recorded` and `withFetchedPrs` call, `hooks/pr-order.ts:changedRankedPrs`, `hooks/pr-order.ts:prOrderView`, `hooks/pr-order.ts:prOrderActions`, `hooks/pr-tab.ts:applyPrPress`, `hooks/pr-rows.ts:RANK_AGAIN_ID`, `hooks/prs.ts:prompts`, `hooks/help.ts:helpKeys` | All four looks. Rank again's plan is `prOrderActions`, beside `prTabActions`, since it draws on the changed line above the PR blocks and Dismiss merged draws after them. The terminal draws it with `keyRow` and binds `g` with the row keys (`hooks/register.tsx:prOrderLines`). Desktop draws the native Button, which takes clicks only. The Codex tab draws it in `codex/src/tab-prs.tsx:PrOrderLines`, and its keydown handler takes `g` before the selected row's keys, as it takes `m`. omp draws the changed line as a row the selection reaches, where Enter presses Rank again, and `handleKey` takes `g` from any row (`omp/src/panel-entries.ts:orderEntries`). Help lists `g` and `m` on the PRs tab in the terminal, Codex and omp. |
| A PR row's mark, title and meta line, which PR rows wait, and which buttons are follow-ups | `hooks/pr-rows.ts:threadRowText`, `hooks/pr-rows.ts:checkRowText`, `hooks/help.ts:PR_MARKS`, `hooks/pr-rows.ts:prRowWaits`, `hooks/pr-rows.ts:splitFollowUps`, `hooks/pr-rows.ts:PR_QUOTE_CHARS` | All four looks. A review thread draws ◆ in the needs-you tone while it waits on the person. Once handed to the agent, its mark runs while the message is queued, is blank while it is unconfirmed, and is ✓ in the done tone once it arrived. A failing check draws ▲ in the error tone. A dismissed PR's settled block draws ✕ from `hooks/rows.ts:settledMark`, as a dismissed row does. Its title starts at an open PR title's edge, and its ✕ sits where the look draws a settled row's result mark. Where each look draws it: see "Result marks and the mark column" in Differences on purpose, and "Result marks" in the omp table. A PR's own row never waits, so the PRs tab opens on its first thread that waits. |
