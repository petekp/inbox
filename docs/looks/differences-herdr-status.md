# Differences on purpose: the Herdr look's Status page

Part of [the look map](../looks.md#differences-on-purpose).

This part of the Herdr look's table covers the Status page. Like [the rest of the table](differences-herdr.md), it compares the Herdr look with the Codex tab.

| Topic | Herdr look | Why | Where |
| --- | --- | --- | --- |
| Keys on the Status page | ← →, escape and the other keys Help lists work, but no key presses a Status button. Those take clicks. | The Status page selects no row, so no row's keys apply. | `herdr/src/keys.ts:keyMove` |
| What a look counts as seen | The Status counts as shown while the look draws it, the Herdr window has focus, the look's tab is the tab the shown space shows, and no other pane in that tab is zoomed. The look checks this once a second, and a look ends at the last check that found the Status shown. When a look of `LOOK_MIN_MS` or more ends, also as the pane closes, the look writes it to the session's press folder, and the host counts it as `lookReported` counts it. A row counts as on screen at a check once the list's blocks have kept the same measured places for the height spring's settle time, and only when its first line lies between the list's edge fades with the list scrolled both to its top and to its end. A row counts as shown when the host wrote the session file the look drew, at the latest. The look file also says when the host wrote the last file the look drew, and `lookReported` counts the look as seeing the Status only as it stood then. In a list that fits between the fades, every row counts. In a longer list, only rows in the middle count, and in a list taller than twice the distance between the fades less one line, none. The Codex tab counts each row whose top is in its window, wherever the list is scrolled. | gpui-kit tells a mod a box's size but not how far a list has scrolled, so the look can tell a row was on screen only when it would be at every scroll position. A subject counted as seen loses its was and merged lines for good, so the look counts too few rows rather than too many. The Herdr app does not say whether a window without focus is still in view, so the look counts no look then. The app does not tell a mod what it draws over a pane, such as a peek over the tab or an overlay window, so a Status under one still counts. Two more cases are unverified: whether `window().active` turns false while the display sleeps or the screen is locked with the Mac awake, and whether a layout command that hides the part of the window that holds the shown tab changes what `spaces()` reports. In either, a Status that is not in view could still count. A subject that changes after the file the look drew was written could count as seen before the look draws the change, so the look counts rows, and its whole look, as of that file's write time. | `herdr/src/status-look.ts:surelyShown`, `herdr/src/status-look.ts:isPaneShown`, `herdr/src/status-look.ts:StatusLook`, `hooks/status-children.ts:lookReported` |
| Tree lines on the Status | 1 px borders in the path line's color: a subject's from under its mark to its children, and a milestone's to its work, with the arms `TreeStroke` lists. An arm starts a pixel right of its column, and a column that ends at an arm takes the arm's row. A column that runs into a block is drawn across the block's space box too, and a column that runs past a block with none of its own there, such as the Later label as it leaves, is drawn across both of its boxes. Columns do not fade, and arms fade with their row. | gpui-kit draws borders. The theme's border color reads too faint here, so the look mixes the text color into the panel's background at 20% (`mixInto`), as the Codex tab's `--tree-line` does. The color is opaque, and at rest no two strokes cover the same pixel either. Each space springs its height, so a column drawn in its box stays joined at every frame of a glide. | `herdr/src/paint-space.ts:contentStrokeEls`, `herdr/src/paint-space.ts:passingOf`, `herdr/src/draw-status.ts:besidePath` |
| Mark colors | Every mark color is a slot of the person's theme: ◆ and a warning take ANSI 3, ▲ ANSI 1, ✦ ANSI 2, ● and ◐ the theme's text color, ✓ the color Herdr's sidebar gives a done agent, and a met goal's ✓ and "Goal met" label and a ready PR's status ANSI 2, as ✦ does. The Codex tab draws ✦, a met goal and a ready PR in one fixed green and ✓ in a fixed blue, from `hooks/tones.ts`. | A Herdr theme picks its own colors to read on its own background, and the look cannot add its own. So ✦ is as minty as the theme's green, and no theme is checked for 4.5:1. | `herdr/src/paint-theme.ts:TONE_COLORS`, `herdr/src/draw-status.ts:goalBlocks` |
| The goal's path | A 1 px left border in the tree lines' color, dashed into next, set at `PATH_X`, an estimate of the marks' middle. The word shows only when the whole name and the word fit on one line: an invisible copy of the name holds the space, and the word wraps out of view when it does not fit. A done milestone folded to its name draws its mark, the name and the chevron after it. A met goal's folded milestones draw their names at the text column with the chevron after and no mark, as the Codex tab does. | gpui-kit draws borders but cannot say where a line of text ends, so the look cannot place the word after a wrapped name's first line, as the Codex tab does. | `herdr/src/paint-space.ts:pathEls`, `herdr/src/paint-blocks.ts:wordEl` |
