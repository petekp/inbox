# Differences on purpose: omp's panel and keys

Part of [the look map](../looks.md#omp).

| Topic | omp | Why | Where |
| --- | --- | --- | --- |
| An open question's ◆ (`asks-tree`) while a press result mark shows | The ◆ stays in the lead before the title, and the running or settled mark draws after the title. | The panel's line has a lead for the ◆ and a separate place for the result mark, as it did for the Holds up ◆. | `omp/src/panel-lines.ts:lineOfRow`, `omp/src/panel-draw.ts:drawLine` |
| An answer option's button (`asks-tree`) | The option is a branch of the tree drawn as its button cell, " x label " with the key letter, then its note on the lines under it. The focused option draws inverse, the recommended one underlined. The tree is not a plain-text tree of note lines: the cells are the same ones the buttons under the tree use, so focus, ← and →, Enter and the key letters reach them in the plan's order. | A text line has no filled pill, so an option reads as a button by its key letter and its focus highlight. | `omp/src/panel-ask-tree.ts:askTreeLines`, `omp/src/panel-draw.ts:drawLine` |
| A collapsed row the cursor rests on | Keeps the ❯ cursor, and draws its line without the selected row's body and buttons. | `z` acts on the cursor row, so the panel keeps it visible. | `omp/src/panel-draw.ts:drawLine` |
| Recommended answer | The answer is underlined and ends "(recommended)". Where the button, focused, would not fit a line of its own, it reads the answer alone, still underlined. The terminal never drops the word and underlines nothing. | The panel wraps a button to the next line but never shortens one, and omp cuts each panel line at its width, so a label wider than a line would lose its end. The panel draws plain text with no button fill, so the underline marks the answer whether or not the word shows. | `omp/src/panel-draw.ts:labelMark`, `omp/src/panel-draw.ts:buttonCell`, `hooks/rows.ts:actionLabel` |
| Where an empty tab's text sits | At the top left, as in the inline terminal. | The panel is lines in the session's flow, sized to its tallest tab, so centred text would float between the conversation and the prompt. | `omp/src/panel-entries.ts:emptyEntries` |
| Reply while its send is out | The draft stays through the press, and is deleted once the press is confirmed and the draft is unedited, as in the Codex tab. | omp's send returns as soon as omp takes the message, so the draft is kept only for a moment. | `omp/src/controller.ts:createPanel`, `omp/src/host-send.ts:sendToAgent` |
| Pressing a button | A row opens with its recommended option focused. Enter presses the focused button, and ← and → move focus between a row's buttons. A button's key letter also presses it. Enter on a Closed line unfolds or folds it. A handed-off row draws as its one line even when selected, and Enter opens it again. | omp gives an overlay raw keys, so the panel keeps its own focus, and a selected row is the open row. | `omp/src/panel-keys.ts:handleKey`, `omp/src/panel-keys.ts:defaultFocus`, `omp/src/panel-keys.ts:afterHandOff` |
| Wrap-around | ← and → wrap at a row's first and last button. | The panel takes keys only, so wrapping saves presses. | `omp/src/panel-keys.ts:handleKey`, `hooks/action-plan.ts:steppedIndex` |
| Switching tabs | Tab and Shift+Tab move between tabs, wrapping at either end, and the number keys pick one. The terminal switches tabs only with the number keys. | The overlay owns every key, so Tab is free to switch tabs. | `omp/src/panel-keys.ts:handleKey` |
| Tab names (`tab-symbols`) | The tab line tries the words with `[1]` brackets around the keys, then without them, then the symbols with and then without them. Narrower than that, about 34 columns with the demo's counts, omp cuts the line's end. The terminal wraps its tabs instead. | Each panel line is one terminal line, and omp cuts a line wider than the panel. | `omp/src/panel-tabs.ts:tabBar`, `hooks/tabs.ts:fitTabs` |
| Failed press result on an open row | Follows the title, in the error color, like every finished result, on the row's first line. A long error is cut at the panel's width. | The panel draws a row's title and its press result on one line. | `omp/src/panel-draw.ts:drawLine` |
| Help (`help-page`) | `?` opens Help and closes it. The footer's hints end with `? help`. Escape closes Help first, and a second Escape closes the panel. ↑ and ↓ scroll Help when it is taller than the panel. | The panel takes keys only, so no button opens Help, and its tab line draws no Help tab. The tab line keeps the shown tab marked while Help shows. | `omp/src/panel-keys.ts:handleKey`, `omp/src/panel-entries.ts:helpEntries` |
| Keys with no terminal equivalent | Escape closes the panel, or leaves a reply field. Enter presses the focused button, or sends a reply. ↑ and ↓ move between rows, as do `k` and `j`. | The terminal's pane has no raw keys. The overlay takes keys only, so each action needs one. | `omp/src/panel-keys.ts:handleKey` |
| Separators and marks | The `·` between counts and hints, and a Closed list's › and v, use omp's `statusLineSep` theme color. The accent uses omp's `accent`. Status tones follow `hooks/tones.ts`. | They match omp's own status line, and follow the person's omp theme. | `omp/src/theme.ts:styleOf` |
| A selected done fold on the Status | Its chevron draws in the accent and its count in bold. Enter or `f` unfolds or folds it. | A selected Status row shows its selection on its focused button, and a fold draws no button: its line is the control. | `omp/src/panel-page.ts:drawPageRow` |
| A selected parent on the Status (`status-parent-fold`) | Its name draws bold and its chevron in the accent. `f` folds or opens it, and so does Enter when it draws no buttons. The footer's hints add `f fold` while one is selected. | As for a done fold: the panel takes keys only, and a parent with buttons keeps Enter for its focused button. | `omp/src/panel-page.ts:drawPageRow`, `omp/src/panel-keys.ts:handleKey`, `omp/src/panel-tabs.ts` |
| Result marks | A settled row's result mark starts its label on the title's line, as `Fade a glance…  ✓ Yes, fade it`. A Closed line and a handed-off row draw theirs the same way, before the outcome or the feedback. When a handed-off row's title and feedback do not fit on one line, the title wraps to two lines and the mark and feedback take lines of their own under it. An opened row whose status sits under its buttons starts that line with the mark. | omp keeps the whole settled row on one line, the height of the Closed line it folds into. | `omp/src/panel-draw.ts:drawLine`, `omp/src/panel-draw.ts:markText` |
| Panel and band | `/inbox` opens an overlay that replaces the band while it shows. The band reads "Nothing needed" when nothing waits, or "May be out of date" as `hooks/band.ts:noCountsText` says, and it names `/inbox` as the way to open the panel. | omp has no side pane or button above the prompt. | `omp/src/host.ts:openPanelUi`, `omp/src/panel.ts:bandLines` |
| Panel height | The panel opens at the height of its tallest tab, up to the terminal's rows less 4. While it stays open, it never gets shorter. It grows only when the shown tab's lines pass its height. Blank lines above the footer fill a shorter tab. Each `/inbox` measures again. | omp draws the panel in place of the prompt, so a change in its height moves the session above it. The terminal's inline pane always fills the room the engine gives it, a third of the space by default. omp's room is the terminal's rows less 4, so filling it would cover most of the session even with one row to show. | `omp/src/controller.ts:createPanel`, `omp/src/panel.ts:tallestTabHeight` |
| Spacing | The panel keeps the blank lines it drew before the shared scale in `hooks/layout.ts`. A group's title, its rows and its Closed fold sit flush, as in the inline terminal. The panel marks the selected row with `❯` and paints no background, so no highlight meets the title or the fold. A group's rows hang on a tree from its title's mark, as the terminal's do, and a selected row's `❯` sits before its arm. Status items sit flush, and a blank line comes only above a part, such as Other work. A question's option notes sit flush too, each at its own tree arm, and start under their button's label, after its key letter. The terminal look's docked Status puts a blank line between top-level items when either takes more than one line. | omp draws the panel in place of the prompt, so every line it adds moves the session above it. omp counts whole rows, so only `ITEM_GAP_PT` and larger steps could show, and each would cost a line of work. | `omp/src/panel-page.ts`, `omp/src/panel-entries.ts` |
| Press guard | None. | `PRESS_GUARD_MS` guards a click that lands as a row opens. The panel takes keys only. | `hooks/timing.ts:PRESS_GUARD_MS` |
| Pressed button while its press is out (`dim-pressed-button`) | The button's cell draws dim and its key does nothing. A follow-up such as Discuss already draws dim, so while its press is out it looks as it does at rest until it is focused. Focused, an out button draws dim in reverse video instead of bold. | The panel's buttons are ANSI text with one dim style, which a follow-up already uses. | `omp/src/panel-draw.ts:buttonCell`, `omp/src/panel-keys.ts:activate` |
| Banners | `╭─╮` box-drawing in the tone's border tint, filled with its tint in true color, from `hooks/tones.ts`. The demo banner sits above the tab line, and the others under it, as in the terminal. The stop is the stop's row inside an error box, so Resume keeps its focus and its key. The band keeps its stop line. The terminal draws a docked banner with Ink's `round` border, and the stop as a banner with Resume beside it. | The panel draws plain text lines and takes keys only, so a button lives on a row the panel can focus. omp cuts each line at the panel's width, so a box is drawn to fit it. | `omp/src/panel-draw.ts:bannerLines`, `omp/src/theme.ts:styleOf` |
| Review thread rows | A thread's row draws the comment's first line as its title. Selected, it draws the rest of the comment as plain text, up to 8 lines, then one detail line: where it is, the latest reply or the author, and a lines-changed note. The reply's full text is not drawn. Open comment opens it on GitHub. | The panel draws plain text lines, so it shows no Markdown, and it caps the comment so a long one does not push the row's buttons off the panel. | `omp/src/panel-entries.ts:prEntries`, `omp/src/panel-draw.ts:drawLine` |
| A record or close call | The call draws its label, "Inbox record" or "Inbox close", and the person's line under it. It draws no arguments. The terminal draws the call's arguments, then the line. A failed call draws its error under the label. | omp draws a tool's label alone when the tool draws its own result. The person's line says what the arguments did. | `omp/src/omp-messages.ts:shownLine` |
| A due row waits while the list is in use (`fold-waits-for-list-use`) | A row due to fold waits until no key for `FOLD_QUIET_MS`. | The panel takes keys only, so it knows no pointer. | `omp/src/controller.ts:createPanel`, `hooks/timing.ts:isSettledInPlace` |
| Refresh PRs under a notice | The button stays a row of its own under the notice, where Enter presses it. The other looks draw it at the notice's right end. | The panel takes keys only, and a banner is text that no selection reaches, so a button inside it could not be pressed. | `omp/src/panel-entries.ts:refreshEntries`, `omp/src/panel-draw.ts:bannerLines` |
| A row's title tint (`title-tint`) | The row's title, lead and mark take the key blue on a new row, or the tone of how it closed on a settled row, then holds and steps back toward the theme's text color in `NEW_STEPS` colors on the frame timer. | omp draws ANSI lines, which have no opacity, and omp has no reduced motion setting. | `omp/src/panel-draw.ts:drawLine`, `omp/src/theme.ts:styleOf` |
| Folding every fold of a tab (`fold-all`) | The `w` key folds every fold of the tab while any is open, and else opens them all. No click does. | The panel takes keys only. The other looks also take an Option-click on any fold. | `omp/src/panel-keys.ts:handleKey`, `hooks/fold-all.ts:foldAllOn` |
