# Differences on purpose: omp's panel and keys

Part of [the look map](../looks.md#omp).

| Topic | omp | Why | Where |
| --- | --- | --- | --- |
| Options fold | Every option shows, and there is no "All options" button. | The panel moves focus between buttons with the arrow keys, so a row with many options stays reachable. | `omp/src/panel-lines.ts:rowButtons`, `hooks/action-plan.ts:rowKeyPlan` |
| Recommended answer | The answer is underlined and ends "(recommended)". Where the button, focused, would not fit a line of its own, it reads the answer alone, still underlined. The terminal never drops the word and underlines nothing. | The panel wraps a button to the next line but never shortens one, and omp cuts each panel line at its width, so a label wider than a line would lose its end. The panel draws plain text with no button fill, so the underline marks the answer whether or not the word shows. | `omp/src/panel-draw.ts:labelMark`, `omp/src/panel-draw.ts:buttonCell`, `hooks/rows.ts:actionLabel` |
| Reply key | `r` opens the reply field. The shared plan gives Reply `t`. | The product chose `r`, which reads as Reply. | `omp/src/panel-lines.ts:REPLY_KEY` |
| Reply while its send is out | The draft stays through the press, and is deleted once the press is confirmed and the draft is unedited, as in the Codex tab. | omp's send returns as soon as omp takes the message, so the draft is kept only for a moment. | `omp/src/controller.ts:createPanel`, `omp/src/host.ts:sendToAgent` |
| Pressing a button | A row opens with its recommended option focused. Enter presses the focused button, and ← and → move focus between a row's buttons. A button's key letter also presses it. Enter on a Closed line unfolds or folds it. A handed-off row draws as its one line even when selected, and Enter opens it again. | omp gives an overlay raw keys, so the panel keeps its own focus, and a selected row is the open row. | `omp/src/panel-keys.ts:handleKey`, `omp/src/panel-keys.ts:defaultFocus`, `omp/src/panel-keys.ts:afterHandOff` |
| Wrap-around | ← and → wrap at a row's first and last button. ↑ and ↓, and `j` and `k`, wrap from the last row to the first. | The panel takes keys only, so wrapping saves presses. | `omp/src/panel-keys.ts:handleKey` |
| Switching tabs | Tab and Shift+Tab move between tabs, wrapping at either end, and the number keys pick one. The terminal switches tabs only with the number keys. | The overlay owns every key, so Tab is free to switch tabs. | `omp/src/panel-keys.ts:handleKey` |
| Tab names (`tab-symbols`) | The tab line tries the words with `[1]` brackets around the keys, then without them, then the symbols with and then without them. Narrower than that, about 34 columns with the demo's counts on a next build, omp cuts the line's end. The terminal wraps its tabs instead. | Each panel line is one terminal line, and omp cuts a line wider than the panel. | `omp/src/panel-tabs.ts:tabBar`, `hooks/tabs.ts:fitTabs` |
| Failed press result on an open row | Follows the title, in the error color, like every finished result, on the row's first line. A long error is cut at the panel's width. | The panel draws a row's title and its press result on one line. | `omp/src/panel-draw.ts:drawLine` |
| Help (`help-page`) | `?` opens Help and closes it. The footer's hints end with `? help`. Escape closes Help first, and a second Escape closes the panel. ↑ and ↓ scroll Help when it is taller than the panel. | The panel takes keys only, so no button opens Help. | `omp/src/panel-keys.ts:handleKey`, `omp/src/panel-entries.ts:helpEntries` |
| Keys with no terminal equivalent | `u` undoes the most recent closed row. Escape closes the panel, or leaves a reply field. Enter presses the focused button, or sends a reply. ↑ and ↓ move between rows, as do `k` and `j`. | The terminal has Undo only as a button, and its pane has no raw keys. The overlay takes keys only, so each action needs one. | `omp/src/panel-keys.ts:handleKey` |
| Separators and marks | The `·` between counts and hints, and a Closed list's ▸ and ▾, use omp's `statusLineSep` theme color. The accent uses omp's `accent`. Status tones follow `hooks/tones.ts`. | They match omp's own status line, and follow the person's omp theme. | `omp/src/theme.ts:styleOf` |
| Result marks | A settled row is one line, so its result mark starts its label on the title's line, as `Fade a glance…  ✓ Yes, fade it`. A Closed line and a handed-off row draw theirs the same way, before the outcome or the feedback. An opened row whose status sits under its buttons starts that line with the mark. | omp settles a row into one line cut to the panel's width, so nothing under it moves when Undo ends. | `omp/src/panel-draw.ts:drawLine`, `omp/src/panel-draw.ts:markText` |
| Panel and band | `/inbox` opens an overlay that replaces the band while it shows. The band reads "Nothing needed" when nothing waits, and it names `/inbox` as the way to open the panel. | omp has no side pane or button above the prompt. | `omp/src/host.ts:openPanelUi`, `omp/src/panel.ts:bandLines` |
| Panel height | The panel opens at the height of its tallest tab, up to the terminal's rows less 4. While it stays open, it never gets shorter. It grows only when the shown tab's lines pass its height. Blank lines above the footer fill a shorter tab. Each `/inbox` measures again. | omp draws the panel in place of the prompt, so a change in its height moves the session above it. The terminal's inline pane always fills the room the engine gives it, a third of the space by default. omp's room is the terminal's rows less 4, so filling it would cover most of the session even with one row to show. | `omp/src/controller.ts:createPanel`, `omp/src/panel.ts:tallestTabHeight` |
| Press guard | None. | `PRESS_GUARD_MS` guards a click that lands as a row opens. The panel takes keys only. | `hooks/timing.ts:PRESS_GUARD_MS` |
| Pressed button while its press is out (`dim-pressed-button`) | The button's cell draws dim and its key does nothing. A follow-up such as Discuss already draws dim, so while its press is out it looks as it does at rest until it is focused. Focused, an out button draws dim in reverse video instead of bold. | The panel's buttons are ANSI text with one dim style, which a follow-up already uses. | `omp/src/panel-draw.ts:buttonCell`, `omp/src/panel-keys.ts:activate` |
| Banners | `╭─╮` box-drawing in the tone's border tint, filled with its tint in true color, from `hooks/tones.ts`. The demo banner sits above the tab line, and the others under it, as in the terminal. The stop is the stop's row inside an error box, so Resume keeps its focus and its key. The band keeps its stop line. The terminal draws a docked banner with Ink's `round` border, and the stop as a banner with Resume beside it. | The panel draws plain text lines and takes keys only, so a button lives on a row the panel can focus. omp cuts each line at the panel's width, so a box is drawn to fit it. | `omp/src/panel-draw.ts:bannerLines`, `omp/src/theme.ts:styleOf` |
| Review thread rows | A thread's row draws the comment's first line as its title and one detail line: where it is, the latest reply or the author, and a lines-changed note. The rest of the comment and the reply's full text are not drawn. Open comment opens it on GitHub. | The panel draws each row as a title and one detail line, with no body. | `omp/src/panel-entries.ts:prEntries` |
| A record or close call | The call draws its label, "Inbox record" or "Inbox close", and the person's line under it. It draws no arguments. The terminal draws the call's arguments, then the line. A failed call draws its error under the label. | omp draws a tool's label alone when the tool draws its own result. The person's line says what the arguments did. | `omp/src/omp-messages.ts:shownLine` |
