# Differences on purpose: the Status page and marks

Part of [the look map](../looks.md#differences-on-purpose).

| Topic | Terminal | Desktop | Codex | Why | Where |
| --- | --- | --- | --- | --- | --- |
| Status head | The title, bold, in the column of the rows' marks, with the description muted on the line under it. A head with no description yet shows the title alone. The omp panel draws the same, with the description dim. | Same as terminal, in the row frame. | The title is 15 px semibold over 13 px rows, at the marks' left edge, with the description muted at 13 px under it. | The terminal has one text size, and desktop Text has no size prop, so those looks set the title apart by weight alone. | `hooks/register.tsx:statusHead`, `codex/src/tab-css/status-page.css:.status-head`, `omp/src/panel.ts:pageEntries` |
| The Seen line | "Last seen" in the middle of a dashed rule of `LOOK_DASH`, with the span of the rule above a row: from the text column to the end of the list's columns. The rules between rows stay solid. A blank line sits above it, and below it unless it ends the list. The inline pane draws no rules between rows, and draws the Seen line at that span. The omp panel draws the same, in its dim color. | "Last seen" between two dashed lines. Each is a row of filled Boxes 1 pt tall and 3 pt apart. Their count comes from the pane's width, and they grow to share their side, so each dash stays about 3 pt long. The line starts at the left edge of the rule above a row and runs to the pane's edge, as that rule does. It sits outside a row frame, because the frame's border would inset its right end. Its padding matches a row frame's padding and border. A Box `LOOK_GAP_PT` tall sits above it, and below it unless it ends the list. | "Last seen" between two 1 px dashed borders in `--soft`, from the text column to the tab's edge: the span and color of the rule above a row. A margin of `LOOK_GAP_PT` sits above it, and below it unless it ends the list. | A run of `─` or `LOOK_DASH` wraps in the desktop pane's proportional font, and a Box has no dashed border. A frame's border insets its content on both sides. The terminal and omp draw whole lines, so their space is a blank line. Desktop and Codex can draw less, so they leave half a line. | `hooks/register.tsx:statusLookLine`, `hooks/register.tsx:desktopDashes`, `codex/src/tab-css/status-page.css:.look-rule`, `omp/src/panel.ts:lookLines` |
| Running marks (`pending-answer-mark`) | A row's result mark runs while what the row sent is on its way, as an answer, a Done or a Fix. On the Status, a working subject's mark moves while this session's turn runs or a child under it still moves, unless an open item holds it up. A child's mark moves while it runs. A delegate that waits shows ◆ and a finished one ✓, neither moving. The mark cycles through ● ◉ ◎ ◉, one frame each `RUNNING_FRAME_MS`. One timer redraws the pane while it shows a running mark. The omp panel draws the same glyphs, from a timer that redraws only the panel. | The mark is an Svg dot, the size of the ● glyph, that fades and returns once each `RUNNING_PULSE_MS`. A pane redraw starts an Svg's animation again, so each dot begins at the clock's point in the pulse, and every dot moves together. | The mark fades and returns once each `RUNNING_PULSE_MS`, in CSS. Every mark's animation starts at the page's time origin, so all of them move together. With reduced motion, the mark stays still. | Terminal text has no opacity, so it changes the glyph. A pane redraw loop stops clicks on desktop, and an Svg animates without redraws. | `hooks/view.ts:runningMark`, `hooks/running-mark-timer.ts:animateRunningMarks`, `hooks/desktop-svg.ts:runningSvg`, `hooks/register.tsx:markGlyph`, `codex/src/tab.tsx:StatusLine`, `codex/src/tab.tsx:ResultMarkView`, `omp/src/panel.ts:drawPageRow`, `omp/src/panel.ts:markText`, `omp/src/controller.ts:createPanel` |
| Result marks and the mark column | An Asks or Finds row has no mark column: its title starts after the tree's arm. Its result mark, with a space, starts its result: the settled label on the line under the title, a Closed line's outcome, or a handed-off row's feedback. A blank mark keeps its two cells. A dismissed PR's block has no mark column either. Its title starts at an open PR title's edge, and its ✕ starts "✕ Dismissed" on the line under it. | The row's mark column stays, and the result mark is drawn in it, with the Svg dot while it runs. | Same as desktop, in the row's first grid track. | Only the terminal draws a tree, so only there did the column sit between the tree and the text. On desktop and in Codex the column is also the indent under the group title and the Status's mark track, so dropping it would put rows left of their group title. Desktop's row Client draws text only, so a running Svg cannot sit in its result text. | `hooks/register.tsx:columnsFor`, `hooks/register.tsx:resultLine`, `hooks/register.tsx:settledPrBlock`, `hooks/register.tsx:gutterMark`, `codex/src/tab.tsx:resultHandle`, `codex/src/tab-css/groups.css:.group-mark` |
| The cancelled mark | The font's ✗. | A row's result ✗ is an Svg of the ballot X from `cancelledMarkShape`, in the color of the text beside it. A dismissed row's ✕ stays text. The Status's ✗ for a dropped subject stays the font's. The Help legend draws them as rows do. | A row's result ✗ is an inline svg of the same shape, in the mark's color. A dismissed row's ✕ stays text. The Status's ✗ stays the font's. The Help legend draws them as rows do. | The system font draws ✗ the same as ✕, so a cancelled row would look dismissed. The Status draws no ✕, so its ✗ cannot be mistaken for one. The desktop pane's Text cannot choose a font, and its Svg cannot load the app's font. A drawn shape looks the same whatever fonts the system has. A terminal's and omp's monospace font draws ✗ as the ballot X. | `hooks/marks.ts:cancelledMarkShape`, `hooks/register.tsx:markGlyph`, `hooks/register.tsx:legendMark`, `codex/src/tab.tsx:MarkGlyph` |
| Tree lines on the Status | The Asks tree's glyphs, in the subject's mark column: `│` runs down from under the subject's mark, each row under it starts with `├─`, and the last with `└─`. A wrapped row keeps `│` beside each line while rows follow it. The omp panel draws the same glyphs. | Hairlines, each a 1 pt filled Box in the divider color, in the same places. Each row draws its part in its mark column, and each part reaches over the frame's padding and border to meet the next row's. | 1 px CSS lines in the same places, drawn by each row's `::before` and `::after`. | Desktop lines differ in height, so stacked glyphs break into separate bars, and a Box has no per-side border. A web page draws lines with CSS. | `hooks/register.tsx:statusTree`, `codex/src/tab-css/status-page.css:.has-children`, `omp/src/panel.ts:withTree` |
| Rules between Status rows | In the docked pane, a run of `─` in the divider color, from the text column to the end of the row. The inline pane draws none, as it draws none between Asks rows. The omp panel draws the same run in its dim color. | A 1 pt filled Box in the divider color, at the same left edge as the rules between sections. | A 1 px line in `--soft`, from the text column to the tab's edge, as between sections. | The inline pane leaves out dividers so a full tab fits without scrolling. Desktop text uses a proportional font, where a run of `─` sized in cells wraps onto a second line. A web page draws lines with CSS. | `hooks/register.tsx:statusRule`, `codex/src/tab-css/status-page.css:.status-rule`, `omp/src/panel.ts:pageRule` |
