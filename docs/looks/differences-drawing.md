# Differences on purpose: rows, tabs, banners and motion

Part of [the look map](../looks.md#differences-on-purpose).

| Topic | Terminal | Desktop | Codex | Why | Where |
| --- | --- | --- | --- | --- | --- |
| Motion and bars | Undo's fill drains by cells while Undo lasts. New rows have no bar. Rows don't move; a running mark changes its glyph. | Undo's fill drains while it lasts. Rows don't move. A running mark fades. New rows have no bar. | Rows enter, move and exit. New rows have no bar. | The pane has no opacity, transform or CSS. | `hooks/undo-client.tsx`, `codex/src/rows.ts:stepRow` |
| Scroll after a close with Undo | Inline panes reveal Undo beside the next selected row. If both do not fit, Undo takes priority until it expires. Manual scrolling cancels the expiry reveal. Selecting another row redirects it to that row. Docked panes retain their normal scroll. | Reveals the selected row with the least scrolling. | Reveals the selected row with the least scrolling, then checks again after its animation. | An inline terminal pane has a short window and a time-limited recovery action. | `hooks/register.tsx:openAfterClose`, `codex/src/tab-motion.ts:revealSelected` |
| Redraw and polling | Redraws in steps while Undo lasts. | Redraws once when Undo ends. A timer redraw loop made clicks fail. | The tab polls the server every 3 seconds. | Only the mod gets pushed events. | `hooks/register.tsx:redrawWhileUndoLasts`, `codex/src/settle.ts:POLL_MS` |
| Undo's time (`settle-window`) | Undo lasts `SETTLED_MS` from the close. After a typed message, a row with Undo folds when Undo ends. | Same as terminal. | The server offers Undo for `SETTLED_MS` plus two polls from the close. The tab draws Undo for `SETTLED_MS` from the first poll that lists the settled row or PR. After a typed message, a row with Undo folds at the tab's first poll after the server's Undo ends. That is up to three polls after the tab's Undo ended. | The tab only learns of a close at its next poll. | `codex/src/settle.ts:SETTLE_WINDOW_MS`, `codex/src/settle.ts:isUndoLeft` |
| Version label | `v<version>` in faint text at the bottom right of the footer, after the status, with ` · next` after it on a next build. | Finding path display | The file name, in Claude Code's inline-code color. | Same as terminal. The pane has no font props. | The file name in the mono font, on a soft chip. | Clipping | Inline bodies fit parsed display spans to a line budget. They retain their planned breaks, inline styles, link addresses and explicit newlines. | The adapter clips with a measured characters-per-cell estimate. | CSS wraps and truncates. | Shared text is never pre-shortened. | Row age | Side column. | A reserved side column keeps the age at narrow widths too. | Side column, at least as wide as "Sending…", which shows there while a press is out. | Each native drawing fits the same age in its own row. Codex reserves the width so a press does not wrap the title. | `hooks/register.tsx:rowClientProps`, `hooks/register.tsx:sideAge` |
| Row feedback while collapsed | Stays on the title line, after the title. | Same as terminal. | Feedback that has an age moves to the side column, before the age, cut at 11em. The full text shows when the row opens. | A collapsed Codex row stays one line, so the list scans fast. | `hooks/register.tsx:pressedAge`, `hooks/register.tsx:listRow`, `codex/src/tab-list.tsx:ListRow`, `codex/src/tab-css/rows.css:.side-label` |
| Colors | Host palette with shared status tones. | Native theme keys and shared SVG status tones. | Host style variables and shared status tones in CSS. | Each look uses its host's theme and drawing primitives. | `hooks/palettes.ts:paletteFor`, `hooks/tones.ts:toneColors`, `codex/src/tab-host.ts:applyHost` |
| Banner shape | Docked: a `round` border in a soft tone color, with the tint filled inside it and one blank line between banners. Inline: the tint alone, with no border and no gap. The dark, light and daltonized themes draw the tints in `hooks/tones.ts`. The ANSI themes, and a theme the mod does not know, draw the border alone, in a theme key. The band's stop line stays a line. | A `single` border in the tone at about a third, filled with the tone at a tenth. The border insets the text 17.6 pt on each side. `BANNER_PAD_Y_PT` above and below, `BANNER_GAP_PT` between banners. In a pane under `DESKTOP_WIDE_AT` columns, a banner's button sits under its text. The band's stop line stays a line. | A 1 px border at 30% of the tone, a 9% fill, a 10 px radius and 12 px at each side. `BANNER_PAD_Y_PT` above and below, `BANNER_GAP_PT` between banners. A notice mixes from the text color. | The terminal paints a Box's fill inside its border, not under it, and the inline pane leaves out space so a tab fits its height. Theme keys have no tint of each tone. The desktop border's inset is fixed, so in a narrow pane a button beside the text leaves too little room for a lead such as "Stopped · 3m ago". `--muted` is see-through in the Codex app. The band has one or two lines, too few for a box. | `hooks/register.tsx:banner`, `hooks/tones.ts:DARK_BANNER_TINTS`, `codex/src/tab-parts.tsx:Banner`, `codex/src/tab-css/base.css` |
| Tab placement | Inline when the pane body is at least 80 columns wide, a column at the pane's left beside the rows. Docked or narrower, a row above them. | A row above the rows. | A row above the rows. | Inline, a row of tabs lines up with the group titles under it and reads as one more title. Docked tabs have their own fill and line. A pane body narrower than 80 columns leaves the rows too little room beside a tab column. | `hooks/pane-sizes.ts:INLINE_RAIL_AT` |
| Tab names (`tab-symbols`) | The words where all the build's tabs fit on one line in one of the look's layouts, measured in cells with their counts. Otherwise each tab shows its symbol and its count, as "🔍 4". Inline at 80 columns and wider, the tab column always shows the words. Tabs that don't fit even by symbol wrap to a second line. | The same rule over the Client region's layouts. Symbols with counts of up to two digits fit on one line at the narrowest dock. Tabs that still don't fit wrap, and the Client region grows to hold them. | A container query on the tab bar shows the words from 316 px of bar, about a 340 px panel, and the symbols below that, whatever the counts. The word stays the tab's accessible name and its tooltip. The symbol has the full text color, so a tab that isn't shown does not fade it. The query is set for a next build's four tabs. A release build's three tabs need less room, so at some widths below 316 px they show their symbols where their words would fit. | The terminal and desktop lay out in cells, so each measures its tabs with their counts. A CSS query cannot read the counts, and measuring in script would need a second layout on each draw. The words with the demo's counts need 292 px of bar, and 316 px holds a second count digit on each row tab. | `hooks/view.ts:fitTabs`, `hooks/pane-sizes.ts:desktopTabSizes`, `hooks/tabs-client.tsx:tabLines`, `codex/src/tab-css/tab-bar.css` |
| Demo for a recording | `/inbox demo recording` shows the demo without its notice line, its "Demo:" prefix and Hide demo. | Same as terminal. | A build made with `INBOX_DEMO_RECORDING=1` shows Show demo, and its demo leaves out the notice line. | Codex has no command, and its demo is reachable only from Show demo, which a release build leaves out. | `hooks/register.tsx:setDemo`, `codex/build.mjs:isDemoRecording` |
| Look for mobile and VS Code | Used. | Not used. | Not used. | The engine's `surface` can be `mobile` or `vscode`, which nobody has checked. They get the terminal look. | `hooks/palettes.ts:lookOf` |
| PRs empty hint (`prs-empty-hint`) | "when this session opens or links one". | Same as terminal. | "when this chat opens or links one". | The Codex app calls a conversation a chat. | `hooks/pr-rows.ts:prsEmptyText`, `codex/src/tab-prs.tsx:Prs` |

A refused Done notification stays visible in its task's Closed entry as
"Done · Not sent: …", with Undo. The shared view decides whether recovery is
available. Terminal and Codex use buttons; desktop reuses its Undo Client
without a countdown so the first click reaches the action. The optional
`Closed.doneNotification` field records the attempt ID and refusal reason.
Every host's existing ledger upgrades preserve it; old records need no default.

Finding details preserve explicit newlines in all four looks. The Codex
adapter uses `pre-line` whitespace for the detail paragraph; its ordinary
spacing and inline formatting stay intact.
