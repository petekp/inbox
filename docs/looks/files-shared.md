# Files: shared modules

Part of [the look map](../looks.md#files).

| File | Role |
| --- | --- |
| `core/view/view.ts` | Shared module. `inboxView` builds the inbox view: the Asks order and count, each row's state, feedback and actions, and the closed rows. `footerError` is the failure text under the tabs. |
| `core/view/timing.ts` | Shared module. The timing constants: how long a row stays settled, the press guard, when a send reads Queued, and the running mark's frames. Which rows a look draws in place, and which replies and discards it holds. |
| `core/view/rows.ts` | Shared module. The `Look`, `RowView` and `RowState` types. Row handles, titles, reply hints and action labels, a closed row's state, outcome label and mark, and the labels of the closed folds. |
| `core/view/closed-line.ts` | Shared module. A Closed line's buttons and the view every look draws it from: its title, age's start, mark, outcome and buttons. |
| `core/view/row-motion.ts` | Shared module. The motion state machine for rows, how long each moving state lasts, each state's fade length, and the fade steps of a row's panel turned back from a close and of its close while still faint. |
| `core/view/springs.ts` | Shared module. The spring every box's height moves on, its frames for a look that plays them, and how long a height move can take to come to rest. |
| `core/view/feedback.ts` | Shared module. A press's feedback on its row: `feedbackOf`, its text in each look, the working and done labels, and whether the press is still out. |
| `core/view/held-line.ts` | Shared module. `stepHeldLine`: the status line a row with buttons keeps in its place while a press puts its status under them, and when that hold lets go, so the look fades the line out and closes its space. |
| `core/view/banners.ts` | Shared module. The banners under the tab bar, the stop texts and Continue, the sample and reading notices, the next build's version label, and the text an empty Asks tab shares with the band. |
| `core/view/empty-tab.ts` | Shared module. `emptyTab` decides when each tab is empty and returns its title, hint and what goes under them. The empty tabs' texts. |
| `core/view/dialog-row.ts` | Shared module. `withDialogRow` adds the agent's own open dialog to the view as the first Asks row, and `dialogTitle` is the one line that says what the dialog asks, which the Herdr sidebar line reads too. |
| `core/view/tabs.ts` | Shared module. The tabs each build shows, with their names, symbols and badges, how the tab bar fits them, and the `/inbox` command's description. |
| `core/view/action-plan.ts` | Shared module. A row's actions in order, from `actionsOf`, and the key plans `rowKeyPlan` and `statusKeyPlan`. `actionLines` wraps a row's buttons. `drawnLists` gives each tab's drawn rows, `rowAfterClose` the row that opens after a close, `openOnArrival` the row that opens when rows arrive, and `tabUndos` with `latestUndo` the Undo the undo key presses. A collapsed row never opens on its own. |
| `core/view/collapse.ts` | Shared module. Which rows and Status parents draw collapsed. `withCollapse` saves a row the person collapsed or expanded, and `collapsedRows` keeps it collapsed until something new arrives on it: a press, the agent recording it again, a finding a question gave back, a thread's new comment or a check's new failed run. A Status parent's fold also opens once something new under it waits on the person. A comment or run GitHub gave no time counts as new once its address differs from the one there at the collapse. |
| `core/view/fold-all.ts` | Shared module. Option-click or the `w` key on a fold folds every fold of the shown tab, or opens them all. `tabFolds` lists a tab's folds, `foldAllOn` gives the lists to save and the rows and parents that collapse. Each look applies the change to its own fold state. |
| `core/view/help.ts` | Shared module. The marks that rows and group titles draw, the Help legend, Help's labels, and the keys Help lists in each look. |
| `core/domain/presses.ts` | Shared module. The press types `RowPress` and `PrActionId`, and `isPrRowId`, which tells whether a row id is a PR row's. |
| `core/domain/press-labels.ts` | Shared module. `actionId` and `pressText`, the action id and label that a press records, and the `capitalized`, `ISSUE_LABEL` and `SHOW_EXPLANATION_LABEL` they use. It imports only types, so importing it loads no other module. |
| `core/domain/open-targets.ts` | Shared module. `openTarget`, which opens a row's link or path through a host's command runner, and `baseName`. |
| `core/domain/help-steps.ts` | Shared module. A row's help steps: each step's label and icon, the Open PR step for the PRs an item names, and the effects each step runs. |
| `core/domain/last-actions.ts` | Shared module. What a row's saved last action says: whether the row waits on a reply, was handed off or had its fix sent, and whether its press folds the row. Also `upgradeLastActions`, which converts the last actions an earlier build saved. |
| `core/view/press-reducer.ts` | Shared module. The press reducer `applyPress`, the `Effect` type, and the reducers that track a sent press's delivery. Also the done notifications, and whether a press's message is known to have reached the agent. |
| `core/runtime/press-effects.ts` | Shared module. Running a press's local effects and sends through a host's `EffectHost`, a local press's finished result, and the demo press. |
| `core/view/pressed.ts` | Shared module. What each row press does, in `pressed`, and the last action it records, in `recordPress`. Also a local press's pending result, whether a closed row offers Undo, and the press that Try again sends after a failed send. |
| `core/domain/press-messages.ts` | Shared module. `messages`, the text each press sends the agent, and the Compare request, which names the comparison page's template and says whether the host's parity record lets it run in the background. |
| `hooks/compare-page.html` | Shared file, generated by `scripts/build-compare-page.mjs` from `hooks/compare-page/`. The page template for a comparison. An agent appends its comparison as JSON after the file's last line, and the page draws it. The Codex and omp builds copy it to `codex/plugin/dist` and `omp/dist`. |
| `hooks/compare-page/` | Shared folder. The parts of the comparison page: `instructions.txt` (the comment the agent reads), `styles.css`, `script.js` and `body.html`. Edit a part, then run `node scripts/build-compare-page.mjs`. |
| `core/view/arrivals.ts` | Shared module. Which rows are new, and where a look moves for them. |
| `core/domain/ledger.ts` | Shared module. The empty ledger, how many sessions each host keeps, and the upgrade of a saved ledger. |
| `core/domain/reply-parse.ts` | Shared module. The parser that reads the inbox model's answer into an `Update`: its update lines, help steps, commands and todos. |
| `core/domain/ask-subject.ts` | Shared module. Whether an ask from the inbox model's answer names a subject, which a NEW or TODO line needs to add a question or task. |
| `core/domain/ask-match.ts` | Shared module. Whether two asks say the same thing, whether a new ask repeats an open or closed one, which option a recommendation names, and whether an answer is a question back. |
| `core/domain/ledger-close.ts` | Shared module. Closing and reopening items and findings, pruning closed records, and whether a closed record counts as handled, dismissed or lapsed. |
| `core/domain/ledger-update.ts` | Shared module. Applying a parsed update to the ledger, and adding findings and the items the agent records. |
| `core/domain/host-tasks.ts` | Shared module. The agent's own task list: how each host's tool calls become `Session.hostTasks`, and the `<tasks>` lines the Status call reads. |
| `core/domain/goal-press.ts` | Shared module. Remove, its Undo and a typed goal as presses on the id `goal`, for `pressed`. |
| `core/domain/children.ts` | Shared module. How each host's events become the Status tab's children: the task notice parser, the Herdr delegate steps, a delegate's name (its Herdr name in words, then the focus its session publishes), the delegate a child agent that works starts, the end of a delegate Herdr no longer shows working, the cut-off at a reload, and the gate that limits how often a child's activity is saved. |
| `core/domain/model-text.ts` | Shared module. The guidance `guidanceText` builds, the `close` tool's description that carries it, and the `Host` and `Told` types. Each host's `Host` names its agent, surface and the `record` and `close` tools. |
| `core/domain/ledger-prompt.ts` | Shared module. What the ledger call reads: `systemText`, and the prompt `buildPrompt` builds from the ledger and the new exchange. |
| `core/domain/catch-up-text.ts` | Shared module. The ledger call's catch-up prompts, and the activity lines that a turn's tool calls and dialogs add. |
| `core/runtime/call-record.ts` | Shared module. Sends one model call and notes what the host reported, and saves a call with no usable answer, or the first usable answer after one, in its call's record in `callFailures`. Saves each call's latest answer text, cut to `ANSWER_CHARS`, with the turn it answered, in `lastAnswers`, which the Herdr look's published copy leaves out. |
| `core/domain/inbox-text.ts` | Shared module. The `inbox:` texts beside a prompt, the state a new conversation starts with, and the question numbers a typed answer such as "1 yes" refers to. `screenText` tells the models whether the inbox is open, and on which tab. |
| `core/domain/session-version.ts` | Shared module. The version every host writes on a session it saves, and `checkVersion`, which Codex and omp run when they read one. |
| `core/view/session-files.ts` | Shared module. The empty session, a session's saved file name, which saved files may be deleted, and `upgradeSession`, which converts a session an earlier build saved to the current shape. |
| `core/domain/earlier-answers.ts` | Shared module. The search for an earlier answer: BM25 over each answered question's ask and answer, ranked against a new question's ask and options, with the relative floor `RELATIVE_FLOOR`. A match must share a term that holds a letter, so numbers alone never match. Also the earlier answer's line on an open row. |
| `core/domain/record-matches.ts` | Shared module. The lines the `record` answer adds after a new question that the person answered questions like before. |
| `core/domain/question-history.ts` | Shared module. The question history's file shape, its version, the answers it keeps and how long, the history folder, and the baseline week during which matches are stored and not drawn. |
| `core/runtime/history-store.ts` | Shared module. `historyStep`, which each host runs on a session it is about to save. It tags each added question with its best earlier answer and writes the session's history file when a question closed or reopened. Also `recordMatches`, the earlier answers a `record` call's answer lists. Each host supplies the file calls. |
| `core/view/saved-check-keys.ts` | Shared module. `withCheckKeys`, which `upgradeSession` runs to rename the checks an earlier build saved by name alone, in last actions, sent rows and a PR order's recorded statuses, to each check's `checkKey`. |
| `core/runtime/session-turns.ts` | Shared module. A turn's start and end, each prompt and the press that sent it, turn activity, and what a shell command's output shows. `endTurn` queues the turn's exchange, and `applied` applies the ledger call's answer to it. |
| `core/runtime/session-status.ts` | Shared module. Saving the Status call's answer or why it failed, and when a running turn's Status call is due. Whether an update or a catch-up is due, and `appliedCatchUp`, which applies a catch-up's answer. A forked conversation's ledger, and when a look at the Status starts and ends. |
| `core/runtime/session-presses.ts` | Shared module. `pressOn` applies a press to a session, and `completedAttempt` records the outcome of sending a press's message. `recorded` applies the agent's `record` and `close` calls. Also the rows a look holds in place, `pruned`, which cuts closed records before each save, and `withFetchedPrs`, which merges fetched PRs into the session. |
| `core/view/session-view.ts` | Shared module. `sessionView` builds the view each look draws, including the PRs tab. `showsRunningMark` says whether a text look draws a running mark. |
| `core/domain/conversation.ts` | Shared module. `flattenConversation` turns a conversation's `Turn`s into the text a catch-up reads, and clips it. Each host maps its own conversation to turns. |
| `core/runtime/session-host.ts` | Shared module. The `SessionHost` and `UpdateHost` types a host supplies, and the update flows that run on a host's store: `runUpdates`, `askOverConversation` and `reconcileUpdateStatus`. It also holds `exclusiveKeys` and `orderedKeys`, which keep runs of one key apart in a process. |
| `core/runtime/clipboard-commands.ts` | Shared module. The commands that put text on the clipboard on each platform, and the words for when none starts. The Codex server and omp run them. |
| `core/runtime/host-press.ts` | Shared module. `press` and `startPress`, which run a press on a host's store, and `wakeAfterSettle`, which sends what waited for the settle window: held answers and Fixes, then the Done message. |
| `core/runtime/held-sends.ts` | Shared module. `releaseHeldSends`, which sends each answer and Fix whose Undo window has passed, and marks one the host refused Not sent. |
| `core/runtime/host-prs.ts` | Shared module. `fetchPrs`, which fetches a session's PRs through the host's gh, reads the views and the limit the host's sessions share, and stops under a limit until it resets, and `isPrFetchDue`, `isPrPollDue`, `addsTabPr` and `prFetchTracker`, which say when to fetch again. `isPrPollDue` also waits while the mod's fetch runs. |
| `core/domain/pr-query.ts` | Shared module. The one GraphQL query that reads every tracked PR, `prsQuery`, and how its answer is read: `readPrsAnswer` finds each PR's node or its own error, `readPrNode` makes a view of a node, `runFailureOf` says why a whole gh run gave no PRs, and `limitResetOf` reads when GitHub's limit resets. |
| `core/view/pr-refresh.ts` | Shared module. The top of the PRs tab after a fetch that could not read every PR: `refreshProblem`, why the PRs are not all current, and `prRefreshView`, the line with Refresh PRs and its press status. |
| `core/domain/gh.ts` | Shared module. `ghFinder` finds a gh that starts, and `ghIn` runs it, over a host's command runner. `gitPlaceIn` reads a folder's git branch and its GitHub repository over the same runner. It picks the repository from the remotes the way gh does: `upstream`, then `github`, then `origin`, then any other remote on GitHub. |
| `core/domain/text.ts` | Shared module. Clipping, code-block formatting, relative ages and a turn's reply. |
| `core/domain/prs.ts` | Shared module. PR parsing, readiness and prompts. |
| `core/domain/pr-checks.ts` | Shared module. Which checks fail, which were cancelled, the GitHub Actions run a check belongs to, the failing check that cancelled another, and `blockingChecks`, the checks that wait on the person. |
| `core/view/pr-tab.ts` | Shared module. What each PR press does, in `applyPrPress`, and the PR button plans: `threadActions`, `checkActions`, `prBlockActions`, and `prClearActions` for Clear merged and closed. `withFinishedPrsSettled` settles a tab PR that a fetch first finds merged or closed, and the old branch PR once the branch has another PR or none. |
| `core/domain/pr-fetch.ts` | Shared module. Which linked PRs the tab tracks, the line that names the older ones it leaves out, the Open PR help step for any linked PR, and `fetchTracked`, which reads the tracked PRs through a host's gh runner in one query, skips merged and lately read ones, and names the cause when a whole fetch fails. |
| `core/view/pr-rows.ts` | Shared module. PR row ids, each PR row's mark, title and meta line, which PR rows wait on the person, the gh notices, including the one for a cause that stopped the whole fetch, and the tone of each PR status. |
| `core/view/pr-views.ts` | Shared module. The PR blocks a look draws and their order, which PR views a session keeps, and whether the person dismissed a PR. |
| `core/view/pr-order.ts` | Shared module. The agent's PR order: the order's lines above the PR blocks, the "Other PRs" line above the PRs it does not rank and the rule for when that line draws, the statuses it records, and its Rank again button. |
| `core/view/pr-press.ts` | Shared module. The PR press types, the open or refresh each press runs, the row each press records on, and the helpers the PR button plans share, which add "again" to a label, add Try again, and mark the button whose press is out. |
| `core/runtime/tools.ts` | Shared module. The record and close tools, and `agentTools`, the one list of their names, descriptions and schemas that every host and eval probe registers. Each call's answer holds the text the agent reads and the line the person sees under the call. |
| `core/runtime/tool-answer.ts` | Shared module. `ToolAnswer`, the answer to an agent tool call, and the helpers the tools share to read an argument and answer with no change. |
| `core/runtime/order-prs-tool.ts` | Shared module. The `order_prs` tool's description and the answer that sets, replaces or clears the PRs tab's order. |
| `core/domain/tool-schemas.ts` | Shared module. The input schemas of the record, close and order_prs tools, with the description of each argument the agent reads. Their tool fields: this build's in `TOOL_FIELDS`, 0.3.0's in `V0_3_TOOL_FIELDS`, and a session's in `sessionToolFields`. |
| `core/view/demo.ts` | Shared module. Sample data for `/inbox demo` and the Codex demo. |
| `core/view/demo-prs.ts` | Shared module. Sample PR views for the shared demo session. |
| `core/domain/demo-delegates.ts` | Shared module. Builds the finished delegates the demo session holds. |
| `core/domain/dialogs.ts` | Shared module. Notes the questions of a Codex dialog, or of a dialog the person answered or dismissed, and links each to the inbox question that copies it: a Codex dialog's link, the dialog's option descriptions, and the close of an answered dialog's copy with the person's answer. |
| `core/view/layout.ts` | Shared module. Sizes the desktop look and the Codex tab share. |
| `core/view/row-parts.ts` | Shared module. The parts of an open question, task or finding in order (`rowParts`), and the gap between two neighboring parts (`partGap`): its step of the scale and the docked terminal's blank rows. Every look spaces a row's parts from it. |
| `core/view/marks.ts` | Shared module. Shapes and glyphs for marks a font draws poorly: desktop draws its toned Svg marks from `markShape`, desktop and Codex draw ✗, ◌ and ⊘ from `mutedMarkShape`, and the terminal and omp draw ✗ as ⊘ from `textMark`. |
| `core/view/tones.ts` | Shared module. Status colors for native marks and terminal palettes. The Codex build writes them into CSS, and omp draws them as true color. Also the banner tints the terminal and omp draw, and the faint text level. |
| `core/view/inline.ts` | Shared module. Inline markdown in the agent's text, as spans each look draws. |
| `core/view/session-presentation.ts` | Shared module. Selects presentation state, excluding private commands, viewers and model answers. |
