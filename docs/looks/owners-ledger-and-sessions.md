# Owners: the ledger, sessions and model-read texts

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| Model-read texts | `hooks/model-text.ts:guidanceText`, `hooks/model-text.ts:systemText`, `hooks/model-text.ts:STATUS_SYSTEM`, `hooks/model-text.ts:statusPrompt`, `hooks/model-text.ts:inboxText`, `hooks/model-text.ts:promptNotes`, `hooks/tools.ts:recordDescription` | The mod, Codex and omp, each through its `Host` |
| The line under a `record` or `close` call: what the call changed, as "Question: …", "Task: …", "Issue: …", "Opportunity: …" or "Closed: …", and nothing for a call that changed nothing | `hooks/tools.ts:ToolAnswer`, from `hooks/tools.ts:recordItem` and `hooks/tools.ts:recordClose` | The terminal look through the mod's `ToolResult` render hook, `hooks/register.tsx:on('ui.render')` for `ToolResult`, and omp through the tools' `renderResult` and `describeResult` in `omp/src/omp-messages.ts:shownLine`. The desktop app draws a reopened session's calls without the hook, and Codex shows the agent's text: see `tool-result-line` in Differences on purpose. |
| Which features each host supports | `hooks/clients.ts:CLIENTS` | `scripts/structure/clients.mjs:checkClients`, which fails when a feature that is not `full` has no row in "Differences on purpose" |
| Saved state shapes and upgrades | `types/parts/session.d.ts:Session`, `hooks/session-version.ts:SESSION_VERSION`, `hooks/session-version.ts:checkVersion`, `hooks/session.ts:upgradeSession`, `hooks/ledger.ts:upgradeLedger`, `hooks/presses.ts:upgradeLastActions` | Every host. Each host writes `SESSION_VERSION` on every session it saves. Codex and omp refuse a session of another version through `checkVersion`. The mod does not check the version when it reads a session. The mod gathers the separate fields an earlier build kept into one session in `hooks/register.tsx:upgradeDrawn`, and upgrades its UI state in `hooks/register.tsx:upgradeState`. Codex and omp call `upgradeSession` from `codex/src/state.ts:upgraded` and `omp/src/state.ts:upgraded`. |
| Which per-reply update lines apply to an item the agent recorded, whether it expires, and when the agent may record a closed ask again | `types/parts/items.d.ts:Item`, `hooks/ledger.ts:applyUpdate`, `hooks/ledger.ts:addAgentItem`, `hooks/tools.ts:recordItem` | Every host, through the per-reply update, the catch-up and the `record` tool |
| Exchange application and activity | `hooks/ledger.ts:applyExchangeUpdate`, `hooks/model-text.ts:addActivity` | Every host; retry scheduling remains with the host |
| Catching up | `hooks/session.ts:needsCatchUp`, `hooks/session.ts:appliedCatchUp`, `hooks/session-host.ts:runUpdates`, `hooks/session-host.ts:askOverConversation` | Every host. A catch-up covers the exchanges pending when it began and the turns started then. One that gets no usable answer ends the run, and the next update tries again. A conversation a host cannot read runs the pending exchanges instead. A reply dropped after two failed updates keeps the "may be missing" warning (`presence.hasDroppedReply`) until a catch-up covers it. |
| Update-failed warning | `hooks/session.ts:sessionView`, `hooks/view.ts:perTurnStatus` | Every host. "Last update failed. Items from that reply may be missing." shows while the ledger is `failed` and no update runs. " It retries after your next message." follows when the host can catch up (`canCatchUp`) or an exchange is pending. Codex cannot catch up without a `transcriptPath`. Known gap: a Codex or omp conversation that cannot be read or parsed, with nothing pending, still shows the promise, because no flag records that the last catch-up found it unreadable. |
| Codex worker activity | `hooks/session-host.ts:reconcileUpdateStatus`, `codex/src/core.ts:viewOf` | The Codex server checks ownership before clearing abandoned activity. Pending exchanges alone do not imply an active worker. |
| Done notifications | `hooks/session-host.ts:wakeForDone`, `hooks/presses.ts:refuseDoneNotification` | Every host. Each batch's sent record is saved before the message goes out. A refusal keeps the task Done, reads Not sent and restores Undo. An unknown outcome stays unconfirmed in settled rows and Closed folds. Nothing is sent again on its own. A conversation switch keeps the result in its original session. Every host waits while the main agent's turn runs (`presence.isTurnRunning`). |
| Undo result | `hooks/presses.ts:applyPress`, `hooks/pr-tab.ts:applyPrPress` | Every host clears its closed-note acknowledgement when the result names an actual reopen |
| Arrival acknowledgement | `hooks/presses.ts:withArrival` | Every host; one bulk press can affect several rows |
| The comparison page template, and where each host finds it | `hooks/compare-page.html`, `hooks/presses.ts:compareRequest` | Every agent, through the Compare message, which names the template's absolute path. Each host passes the path as `SessionHost.comparePage`. The mod uses `hooks/compare-page.html` in `$.plugin.root` (`hooks/register.tsx:comparePagePath`). `codex/build.mjs` copies the template beside the handler bundle, to `codex/plugin/dist` and to `codex/.dev`, and `codex/src/server-handler.ts:createHandler` names the copy in its own folder. `omp/build.ts` copies it to `omp/dist`, and `omp/src/host.ts:defaultDeps` names the copy beside `dist/host.js`. Both builds' `--check` fail when a copy differs from the template. |
