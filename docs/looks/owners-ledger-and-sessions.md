# Owners: the ledger, sessions and model-read texts

Part of [the look map](../looks.md#who-owns-each-rule).

| Rule | Owner | Read by |
| --- | --- | --- |
| Model-read texts | `hooks/model-text.ts:guidanceText`, `hooks/ledger-prompt.ts:systemText`, `hooks/status-prompt.ts:STATUS_SYSTEM`, `hooks/status-prompt.ts:PARTS_STATUS_SYSTEM`, `hooks/status-prompt.ts:statusPrompt`, `hooks/inbox-text.ts:inboxText`, `hooks/inbox-text.ts:promptNotes`, `hooks/tools.ts:recordDescription` | The mod, Codex and omp, each through its `Host` |
| The line under a `record` or `close` call: what the call changed, as "Question: …", "Task: …", "Issue: …", "Opportunity: …" or "Closed: …", and nothing for a call that changed nothing | `hooks/tools.ts:ToolAnswer`, from `hooks/tools.ts:recordItem` and `hooks/tools.ts:recordClose` | The terminal look through the mod's `ToolResult` render hook, `hooks/register.tsx:on('ui.render')` for `ToolResult`, and omp through the tools' `renderResult` and `describeResult` in `omp/src/omp-messages.ts:shownLine`. The desktop app draws a reopened session's calls without the hook, and Codex shows the agent's text: see `tool-result-line` in Differences on purpose. |
| Which features each host supports | `hooks/clients.ts:CLIENTS` | `scripts/structure/clients.mjs:checkClients`, which fails when a feature that is not `full` has no row in "Differences on purpose" |
| Saved state shapes and upgrades | `types/parts/session.d.ts:Session`, `hooks/session-version.ts:SESSION_VERSION`, `hooks/session-version.ts:checkVersion`, `hooks/session-files.ts:upgradeSession`, `hooks/ledger.ts:upgradeLedger`, `hooks/last-actions.ts:upgradeLastActions` | Every host. Each host writes `SESSION_VERSION` on every session it saves. Codex and omp refuse a session of another version through `checkVersion`. The mod does not check the version when it reads a session. The mod gathers the separate fields an earlier build kept into one session in `hooks/register.tsx:upgradeDrawn`, and upgrades its UI state in `hooks/register.tsx:upgradeState`. Codex and omp call `upgradeSession` from `codex/src/state.ts:upgraded` and `omp/src/state.ts:upgraded`. |
| Which per-reply update lines apply to an item the agent recorded, whether it expires, and when the agent may record a closed ask again | `types/parts/items.d.ts:Item`, `hooks/ledger-update.ts:applyUpdate`, `hooks/ledger-update.ts:addAgentItem`, `hooks/tools.ts:recordItem` | Every host, through the per-reply update, the catch-up and the `record` tool |
| A question back: an answer to a question that ends with a question mark and starts with a question word or names no option, as "Why not Redis?" does and "Redis?" does not. It closes no question: the `close` tool refuses it and says to answer it in the reply, and a CLOSED line with one is skipped. A typed reply that is one goes to the agent as "About this question you asked me: …", with the ask and options quoted. | `hooks/ask-match.ts:isQuestionBack`, `hooks/tools.ts:recordClose`, `hooks/ledger-update.ts:applyUpdate`, `hooks/press-messages.ts:messages.answer` | Every host, through the `close` tool, the per-reply update and a typed reply. A Codex question linked to an open dialog sends its typed reply in the dialog's form instead; see `question-back-stays-open` in Differences on purpose. |
| Exchange application and activity | `hooks/ledger-update.ts:applyExchangeUpdate`, `hooks/catch-up-text.ts:addActivity` | Every host; retry scheduling remains with the host |
| A turn's reply for the inbox model: each text the agent wrote to the person in the turn, in order, a blank line apart | `hooks/text.ts:turnReply` | Every host at the turn's end. The mod passes each `turn.step`'s text (`hooks/register.tsx:on('turn.step')`). Codex passes the turn's agent messages from the rollout, and the Stop hook's `last_assistant_message`, which the rollout can lack at Stop (`codex/src/hook.ts:handleHook`). omp passes each assistant message's text from `message_end`, and the run's last message (`omp/src/host-turns.ts`). |
| Catching up | `hooks/session-status.ts:needsCatchUp`, `hooks/session-status.ts:appliedCatchUp`, `hooks/session-host.ts:runUpdates`, `hooks/session-host.ts:askOverConversation` | Every host. A catch-up covers the exchanges pending when it began and the turns started then. One that gets no usable answer ends the run, and the next update tries again. A conversation a host cannot read runs the pending exchanges instead. A reply dropped after two failed updates keeps the "may be missing" warning (`presence.hasDroppedReply`) until a catch-up covers it. |
| Update-failed warning | `hooks/session-view.ts:updateRecovery`, `hooks/view.ts:perTurnStatus` | Every host. While the ledger is `failed`, the warning says whether the inbox waits to retry, retries now, failed again, or could not read the conversation this time, from `presence.failedAttempts`, `presence.isConversationUnreadable` and the pending exchanges. Every host retries after the agent's next reply. A Codex chat saved with no `transcriptPath` gets one from that reply's Stop hook. `footerStatus` shows "Retrying the last update…" while a retry runs. |
| Codex worker activity | `hooks/session-host.ts:reconcileUpdateStatus`, `codex/src/core.ts:viewOf` | The Codex server checks ownership before clearing abandoned activity. Pending exchanges alone do not imply an active worker. |
| Held answers and Fixes: an option answer and a finding's Fix record their message as `held` until the settle window passes, and send nothing before. Undo in that window drops the press, and the question reopens or the finding reads open again. Once the window passes, the host's wake sends each held message as its press would have, without waiting for the turn to end. A refused send reads Not sent and reopens the question. A host that cannot prepare the send, as a Codex with no CLI, refuses it the same way. The ✓ of a held press shows only once its message arrives. | `hooks/pressed.ts:pressed`, `hooks/held-sends.ts:releaseHeldSends`, `hooks/host-press.ts:wakeAfterSettle` | Every host calls `wakeAfterSettle` the settle window after such a press: the mod from `runPress`, Codex from `onPress`, omp from `wakeLater`. Each also calls it at a turn's end, and Codex and omp when the inbox shows, so a held message from a session that quit inside the window sends then. |
| Done notifications | `hooks/host-press.ts:wakeAfterSettle`, `hooks/press-reducer.ts:refuseDoneNotification`, `hooks/press-reducer.ts:withFailure` | Every host. Each batch's sent record is saved before the message goes out. A refusal keeps the task Done, reads Not sent and restores Undo. It also marks the message failed on each row's last action, so a settled row folds once Undo ends, and a row that Undo reopens reads Not sent. An unknown outcome, including a send that throws, stays unconfirmed in settled rows and Closed folds. Nothing is sent again on its own. A conversation switch keeps the result in its original session. Every host waits while the main agent's turn runs (`presence.isTurnRunning`). |
| Undo result | `hooks/press-reducer.ts:applyPress`, `hooks/pr-tab.ts:applyPrPress` | Every host clears its closed-note acknowledgement when the result names an actual reopen |
| Arrival acknowledgement | `hooks/press-reducer.ts:withArrival` | Every host; one bulk press can affect several rows |
| The comparison page template, and where each host finds it | `hooks/compare-page.html`, `hooks/press-messages.ts:compareRequest` | Every agent, through the Compare message, which names the template's absolute path. Each host passes the path as `SessionHost.comparePage`. The mod uses `hooks/compare-page.html` in `$.plugin.root` (`hooks/register.tsx:comparePagePath`). `codex/build.mjs` copies the template beside the handler bundle, to `codex/plugin/dist` and to `codex/.dev`, and `codex/src/server-handler.ts:createHandler` names the copy in its own folder. `omp/build.ts` copies it to `omp/dist`, and `omp/src/host.ts:defaultDeps` names the copy beside `dist/host.js`. Both builds' `--check` fail when a copy differs from the template. |
