| A dialog's copy: the open question of the same turn that copies a dialog question, by options or by ask. A dismissed dialog's copy stays open and takes the dialog's option descriptions. It closes only a copy whose ask restates the dialog's question, since shared options such as Yes and No are not proof that two questions are one. | `core/domain/dialogs.ts:linkDialogs`, `core/domain/dialogs.ts:noteDialog`, `core/domain/dialogs.ts:noteAnsweredDialog` | The mod and omp, when a dialog that blocks the turn ends (`hooks/mod/mod-dialogs.ts`, `omp/src/host-activity.ts`), and every host after a `record` call (`core/runtime/session-presses.ts:recorded`). | Which per-reply update lines apply to an item the agent recorded, whether it expires, and when the agent may record a closed ask again | `types/parts/items.d.ts:Item`, `core/domain/ledger-update.ts:applyUpdate`, `core/domain/ledger-update.ts:addAgentItem`, `core/runtime/tools.ts:recordItem` | Every host, through the per-reply update, the catch-up and the `record` tool |
| A question back: an answer to a question that ends with a question mark and starts with a question word or names no option, as "Why not Redis?" does and "Redis?" does not. A typed reply that is one goes to the agent as "About this question you asked me: …", with the ask and options quoted. | `core/domain/ask-match.ts:isQuestionBack`, `core/runtime/tools.ts:recordClose`, `core/domain/ledger-update.ts:applyUpdate`, `core/domain/press-messages.ts:messages.answer` | Every host, through the `close` tool, the per-reply update and a typed reply. A Codex question linked to an open dialog sends its typed reply in the dialog's form instead; see `question-back-stays-open` in Differences on purpose. |
| The session registry (`session-registry`): one file per running session, `registry/<host>-<id>.json` under the question history's state folder, with its host, id, agent, project folder, pid, whether a turn runs, its counts, its version and its Herdr terminal. The title is null. A write that changes nothing in the saved entry besides its time is skipped. Each write then removes the entries of the same host whose pid no longer runs, and none when the host cannot tell which processes run. A reader treats an entry whose pid does not run as ended. | `core/runtime/session-registry.ts:writeRegistryEntry`, `core/runtime/session-registry.ts:removeRegistryEntry` | The mod on each publish, with its own pid from the one running Claude Code process whose file in its sessions folder names the conversation. It removes the entry as the conversation ends, and writes no entry for that conversation until another loads (`hooks/mod/mod-registry.ts`). Codex after each state written: the SessionStart hook with the Codex process above it, the server with its parent, and the update process only for an entry that exists (`codex/src/registry.ts:registryOnWrite`). Codex has no session end, so its entries go when a later write finds their pid ended. Under the Codex app, every chat's hook and server sit under the one app server, so each entry gives its pid and stays while the app server runs. omp on each change to the session it shows, removing the entry when it shows another or shuts down (`omp/src/host-sessions.ts`). |
| Exchange application and activity | `core/domain/ledger-update.ts:applyExchangeUpdate`, `core/domain/catch-up-text.ts:addActivity` | Every host; retry scheduling remains with the host |
| A reply ask that names no subject: a NEW or TODO line of the per-reply update or the catch-up adds no question or task when its ask names nothing the person could tell apart from another ask, as "Proceed?" or "Push the branch and open a draft PR?". An ask names a subject when it has a PR or issue number, a ticket key, a path, a file name, a link, quoted text, or a word outside a fixed list of filler words, stock actions and generic nouns. The `record` tool is not checked. | `core/domain/ask-subject.ts:namesSubject`, `core/domain/ledger-update.ts:applyUpdate` | Every host, through the per-reply update and the catch-up |
| A delegate session's asks (`delegate-asks`): a session whose Herdr app terminal has a parent, or a `fleet.domain` label, and no `fleet.role` label of `coordinator`. Findings are recorded as in any session. | `core/remote/hc-terminals.ts:delegateSession`, `core/remote/hc-terminals.ts:delegateReader`, `core/domain/ledger-update.ts:withoutNewAsks`, `core/runtime/tools.ts:delegateRefusal`, `core/runtime/tools.ts:toolAnswer` | Every host, each reading its own terminal at each `record` call and each update: the mod in `hooks/mod/mod-herdr.ts:modDelegate`, Codex's tool server in `codex/src/server-handler.ts` and its update process in `codex/src/update-main.ts`, and omp in `omp/src/host.ts`. Outside a Herdr app terminal no session is a delegate. |
| Earlier answers in the `record` answer (`record-earlier-answers`): after a new question, the answer gives the question's id and the person's up to 3 earlier answers most like it, each with its age and repository, and asks the agent to close the question with the reason "answered before: …" only when one settles it. | Catching up | `core/runtime/session-status.ts:needsCatchUp`, `core/runtime/session-status.ts:appliedCatchUp`, `core/runtime/session-host.ts:runUpdates`, `core/runtime/session-host.ts:askOverConversation` | Every host. | Held answers and Fixes: an option answer and a finding's Fix record their message as `held` until the settle window passes, and send nothing before. A host that cannot prepare the send, as a Codex with no CLI, refuses it the same way. | Done notifications | `core/runtime/host-press.ts:wakeAfterSettle`, `core/view/press-reducer.ts:refuseDoneNotification`, `core/view/press-reducer.ts:withFailure` | Every host. An unknown outcome, including a send that throws, stays unconfirmed in settled rows and Closed folds. Nothing is sent again on its own. A conversation switch keeps the result in its original session. Every host waits while the main agent's turn runs (`presence.isTurnRunning`). |
