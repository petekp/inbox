| Hooks need trust (`hooks-need-trust`) | None. | Rows that need a hook the guard skips | Where the guard loads, the permission row comes from `tool.check` instead of `classic.PermissionRequest`. The hook returns `next(e)` as it received it, and a `$.tool.check` query of the same call gives the verdict. An `ask` opens the row only if the call has not been allowed after `PERMISSION_FALLBACK_DELAY_MS`, which is 1.5 s. In manual mode the row appears 1.5 s after the dialog. The row clears, and is never drawn, once `tool.run` fires for the call, matched by `tool_use_id`. The engine raises `tool.run` only for an allowed call, after whoever settled the ask, so it also clears a row `classic.PermissionRequest` opened. A refused call clears its row when the call ends. A `ToolUse` row's `isRunning` cannot stand in for `tool.run`: in the desktop app it is true while the dialog is open. The query asks no PreToolUse hook, so an ask that only a PreToolUse hook makes draws no row. These checks ran while the row still cleared on a `ToolUse` row's `isRunning`, not on `tool.run`. Checked live on Claude Code 2.1.312, with no guard, a stand-in model server, and a stand-in mod ahead of the inbox that answers `classic.PermissionRequest` without calling `next`. Manual mode showed the row 1.5 s after the check and cleared it on answer. An allowed 5 s `sleep`, a call a deny rule refused, an `AskUserQuestion` call and a subagent's dialog drew none. On 2.1.308, a 10 s Bash call that the auto-mode classifier approved drew none, and a `ToolUse` row's `isRunning` stayed false during a dialog and turned true when the tool started. In the desktop app, app 6.28899.6 with engine 2.1.330 and no guard, a real dialog in Manual mode showed the row while it was open and cleared it when allowed. On Claude Code 2.1.330 with the guard loaded on a Team sign-in, a probe mod in the user tier received `tool.run` in `claude -p` for a call a rule allowed, and for a call the auto-mode classifier allowed 0.5 s after `tool.check` answered `ask`. Not checked live: a classifier slower than the delay (which would show the row, and list it in the Asks tab, with no dialog on screen until the call runs), auto mode on 2.1.312, and the desktop app with the guard seated. A `$.tool.check` query has no `tool_use_id`, so it never opens a row. Where `classic.PermissionRequest` runs, it is the only source. The stop row and the text of each step still arrive, through events the guard passes. Where `classic.StopFailure` runs, it sets the stop row with Claude Code's error code. Where the guard skips it, `turn.complete` with reason `error` sets it from the error text the transcript ends on, so the kind comes from the text and the code reads `unknown` where the text names none. The turn's reply is the answer of each `turn.step`, in order, so it holds a reply a Stop hook sent back. | Same as terminal. | No guard in Codex. | The guard skips a user mod's `classic.*` hooks. `turn.step` and `turn.complete` pass. `tool.check` passes and carries the `ask` verdict, but it also fires when the auto-mode classifier then approves the call, so it does not show that a dialog opened. The plugin directory accepts a permission hook only when it returns `next(e)` itself or a fixed `deny` or `ask`, so the hook does not read the verdict `next` resolves to. | `hooks/register.tsx:on('classic.PermissionRequest')`, `hooks/register.tsx:on('tool.check')`, `hooks/mod/mod-dialogs.ts:waitForPermission`, `hooks/register.tsx:on('tool.run')`, `hooks/mod/mod-dialogs.ts:callAllowed`, `core/view/timing.ts:PERMISSION_FALLBACK_DELAY_MS`, `hooks/register.tsx:on('classic.StopFailure')`, `hooks/register.tsx:on('turn.step')`, `hooks/mod/mod-turns.ts:setStopFromLastReply`, `hooks/mod/claude.ts:stopOfMessage` |
