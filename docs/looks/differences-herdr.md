# Differences on purpose: the Herdr look

Part of [the look map](../looks.md#differences-on-purpose).

This table compares the Herdr look with the Codex tab, the nearest look. The structure check reads the parts whose names start with `differences-herdr` as the Herdr look's table.

| Topic | Herdr look | Why | Where |
| --- | --- | --- | --- |
| Who draws | A Herdr app mod draws the inbox apart from the host, from the session file the host publishes under the app's home folder. | Herdr's mods run in Herdr's own process, so the look reaches the host's session only through a file. | `herdr/src/files.ts:readSession`, `hooks/herdr.ts:publishedSessionPath` |
| Following focus | Shows the session of the terminal last focused in the look's tab, and keeps it while the look itself has focus. Before anything in the tab had focus, it shows the first terminal with a session label. | One look pane can serve several agents in a tab. | `herdr/src/follow.ts:follow` |
| A terminal with no session | Draws a message in place of the tabs: no terminal in the tab, no inbox in the terminal with the program that runs there, or a session that ended. | The followed terminal can be any program, and a session can end while its terminal stays open. | `herdr/src/screen.ts:screenOf` |
| Presses | The look writes each press to a file under the app's home folder, then sets a label on the terminal the session file names, so the host reads it. While a row has a press out, every press button on it draws out, and the row reads "Sending…" or how the look's own opens went. While the press is out, that line goes where `isStatusUnderActions` puts it, even once the look's own open is done. The panel passes whether the row shows buttons, where the other looks pass whether it is open, so a settled row's press status also goes under its Undo. A press ends when a publish names it as the last press the host handled, or shows its row changed. A press the host found already changed gets the shared stale note. A press a host took reads as not confirmed when the host's last press is a later one, or 15 seconds after its file was written. One that no host took by then, the look takes back out of the folder, so it cannot apply later, and it reads as not applied. A press on a row with a press out, or with no session to send to, is not sent, and its row says why. | The look reaches the host only through files and terminal labels, so a press waits for the next publish. The panel draws a settled row's Undo as a button under its line, so a status above it would move it while its press is out. A host's apply can fail without a publish, so the look cannot know more than that the press was taken. | `herdr/src/press-queue.ts:PressQueue`, `herdr/src/out.ts:settleOuts`, `herdr/src/out.ts:drawOuts`, `herdr/src/paint-blocks.ts:rowEl` |
| Reply while its send is out | The draft stays through the press, as in the Codex tab, and after it until a publish shows the host finished the press. The look then deletes it if `isPressConfirmed` passes and its words are unchanged. If the row's field is open, the look waits until it closes. A later send on the row replaces an earlier one's answer. Reply on that row opens the kept words meanwhile. | The look learns how a press went only from the session the host publishes. `lastPress` names the press and says whether it was stale. The row's delivery says whether its send failed or went unconfirmed. A press that saved no new last press on its row was not sent. A mod host finishes a press only once its prompt enters, which can take a turn, so the draft can keep a closed row in place that long. | `herdr/src/out.ts:isSentConfirmed`, `herdr/src/press-queue.ts:PressQueue`, `herdr/src/keys.ts:withoutConfirmed` |
| Opens and copies | The look runs every copy, and every open of a link, an absolute path or a `~/` path, itself at once, and its row shows how it went. The press file carries what happened. It opens a relative path against the project folder the session file names, and sends it to the host when the file names none. | The person sees the result without waiting for a publish. A host leaves the project folder out when it has no absolute one. | `herdr/src/run-here.ts:isRunHere`, `herdr/src/run-here.ts:runHere` |
| A spent Undo | Once Undo ends, a settled row that offered it keeps Undo's place hidden until it folds. A row whose message is still queued `QUEUED_AFTER_MS` after Undo ended waits for the agent, so it drops that place then, and the look draws again at that moment. A PR's block keeps no place for a spent Undo. | The panel draws Undo on a line of its own under the row's status, where the Codex tab draws it beside the title. A hidden Undo is an empty line, and a row that waits for the agent can stay for minutes. The host sends an answer or Fix held for Undo when Undo ends, so a row the agent takes at once still folds in one move. | `herdr/src/draw.ts:undoButtons`, `herdr/src/draw.ts:undoPlaceEndsAt`, `herdr/src/screen.ts:screenOf` |
| Row motion | A row fades in as it enters and out as it leaves, over the shared enter and exit times, and keeps its height while it does. A leaving row stays after the nearest block above it that is still drawn. A newly shown tab, Help page or session draws its rows at rest. A block that takes a row's id, as a dismissed PR's block after Undo, is that row in another form, so it does not fade in and the row does not leave. Each fade's first draw sets the opacity it starts from, since gpui-kit animates only a later change. Rows always move. | gpui-kit transitions a height only between heights the mod sets, and the mod does not know a row's height, which depends on how its text wraps. The Herdr app tells a mod no reduced-motion setting. | `herdr/src/motion.ts:moveRows`, `herdr/src/paint-blocks.ts:blockEl` |
| Running marks | A running mark keeps its row's color and fades from 1 to 0.3 and back every `RUNNING_PULSE_MS`, as in the Codex tab. It always fades. | The Herdr app tells a mod no reduced-motion setting. | `herdr/src/paint-blocks.ts:markEl` |
| Keys on the Status page | ← →, escape and Help's other keys work, but no key presses a Status button. Those take clicks. | The Status page selects no row, so no row's keys apply. | `herdr/src/keys.ts:keyMove` |
| What a look counts as seen | The look reports no look at the Status yet, so in a session drawn only in the Herdr look no subject counts as seen. Finished rows stay unfolded and was lines stay. Each host already counts a look file in the press folder as `lookReported` counts it. | A subject counted as seen loses its was and merged lines for good. So the look must report only rows it can tell were on screen, and that needs a probe of the Herdr app's layout first. | `hooks/status-children.ts:lookReported`, `hooks/herdr-app.ts:applyHerdrFile` |
| Help | A "Help" button at the right end of the tab row, after the status line, opens Help in place of the tab, and reads "✕ Close help" while it shows. Help lists the keys and the marks, and no tab symbols. | Herdr draws the pane's header from the layout's header mod, and a mod pane cannot add a button to it. A footer would cost a row. The look always names its tabs in words. | `herdr/src/draw-help.ts:helpBlocks`, `herdr/src/paint-chrome.ts:tabsEl` |
| PR titles | A PR's title wraps in its own column, with its rank and number muted at the line's right end. In a pane under 280 px, the number leads the line under the title instead. Where the PR stands, with its reasons, goes on the line under the title. Each of its parts moves whole to the next line when it does not fit, so a wrapped line starts at the edge. The Codex tab runs the number, the title and where the PR stands as one paragraph. | gpui-kit has no inline text span, so the title cannot run into the next text the way a paragraph does, and the status line cannot wrap as one paragraph. A number at the right end lines up like an age without tabular figures, which gpui-kit lacks. | `herdr/src/paint-blocks.ts:prEl` |
| Type and layout | Every gap, padding and inset is a step of one scale: 4, 8, 12, 16, 24 and 32 px. The panel keeps 16 px on each side, and the tab row, banners, PR titles, ages, Help and rule ends sit on it. A mark sits at the start of a 24 px column that begins at that edge, so its left side lines up with the edge, and text after a mark starts at 40 px. A heading, the goal and the head start there too, in line with the rows under them. Text with no marks under it, such as a PR and the PR order, starts at the edge. A nested item's marks start where its parent's text does, 24 px in. A PR's threads and checks hang their marks at the edge under its title. A title's lines sit 4 px under it, and buttons 8 px under the text above them. A heading sits 12 px above what it heads. Status items sit 24 px apart at the top level and 12 px apart inside a group, so a subject's first child sits 12 px under the subject. Two one-line items in a row, such as a subject's later children or notes, sit 8 px apart. Rows on the other tabs keep 8 px inside their box, so they sit 16 apart. Sections sit 32 px apart, with a rule, where there is one, in the middle. The tab row keeps 8 px under its tabs. The list starts 16 px below that, so its first block sits 24 px under the tabs, and it ends with 32 px under its last block. A banner or the session note sits 24 px under the tabs too, and 16 px under a banner above it, where the shared `BANNER_GAP_PT` gives the other looks 8. A fold's arrow starts at 40 px, with its label 8 px after it. Headings and a PR's reasons use a plain " · ". Buttons and tabs are 28 px high, with 8 px between two buttons and between two wrapped lines of them. Quiet buttons have no side padding, and the goal's Edit and Remove have no dot between them. The Codex tab starts text at 44 px, marks at 18 px, and uses the shared `STATUS_ROW_PAD_PT`, `SECTION_GAP_PT` and `DOT`. | Pete picked the 40 px text column from the three systems in the panel's type study. He later asked for the tab row on the panel's own padding, for no empty mark column on the PRs tab, and for margins in proportion across the tabs. So every edge and gap comes from one scale. A banner takes the panel's 16 px so it lines up with the list under it. The shared sizes stay as the other looks use them. | `herdr/src/paint-theme.ts`, `herdr/src/paint-space.ts:spacedEls`, `herdr/src/paint-blocks.ts`, `herdr/src/paint-chrome.ts:tabsEl` |
| Scroll edges | The list fades into the pane's background over its top 16 px and its bottom 32 px. The fades always draw. At rest they lie over the list's empty padding, so they show only where rows scroll under an edge. The Codex tab draws no fade. | gpui-kit cannot tell a mod how far a list has scrolled, so a fade cannot switch on and off with the scroll. A mod has no CSS, so it draws each fade as a gradient path. | `herdr/src/paint-chrome.ts:scrollFadeEl` |
| A press that is out | A button whose press is out keeps its size, loses its fill and border, and draws its label muted at half strength. It shows no hover or pressed change and takes no click. The Codex tab draws the whole button at 40% opacity, so a filled button that is out reads as a grey block. | A filled button at 40% opacity drew the eye away from the buttons that still work. | `herdr/src/paint-blocks.ts:buttonEl` |
