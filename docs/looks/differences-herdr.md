# Differences on purpose: the Herdr look

Part of [the look map](../looks.md#differences-on-purpose).

This table compares the Herdr look with the Codex tab, the nearest look. The structure check reads the parts whose names start with `differences-herdr` as the Herdr look's table.

| Topic | Herdr look | Why | Where |
| --- | --- | --- | --- |
| A collapsed row the cursor rests on | Keeps the selected row's background, without its body and buttons. A click on the open row's title collapses it, and a click on a collapsed row expands it. The Codex tab draws the plain closed line. | `z` acts on the cursor row, so the panel keeps it visible. | `herdr/src/paint-blocks.ts:rowEl` |
| Who draws | A Herdr app mod draws the inbox apart from the host, from the session file the host publishes under the app's home folder. | Herdr's mods run in Herdr's own process, so the look reaches the host's session only through a file. | `herdr/src/files.ts:readSession`, `hooks/herdr.ts:publishedSessionPath` |
| Following focus | Shows the session of the terminal last focused in the look's tab, and keeps it while the look itself has focus. Before anything in the tab had focus, it shows the first terminal with a session label. A reply typed for one session waits with that session while the look follows another, and its row's Reply opens it again when the look comes back. | One look pane can serve several agents in a tab. | `herdr/src/follow.ts:follow`, `herdr/src/main.ts` |
| A terminal with no session | Draws a message in place of the tabs: no terminal in the tab, no inbox in the terminal with the program that runs there, or a session that ended. | The followed terminal can be any program, and a session can end while its terminal stays open. | `herdr/src/screen.ts:screenOf` |
| Presses | The look writes each press to a file under the app's home folder, then sets a label on the terminal the session file names, so the host reads it. While a row has a press out, every press button on it draws out, and the row reads "Sending…" or how the look's own opens went. While the press is out, that line goes where `isStatusUnderActions` puts it, even once the look's own open is done. A status line the row drew above its buttons, such as "Still open", stays there while a press under way puts the row's status under them, so the buttons keep their place. A failure line keeps its space there without its words, since the press retries what it says failed. The line stays after the press too, while the row's status stays under its buttons, as with "Not confirmed". A status that belongs above takes its place, and with no status the place stays empty. A held line that ends with its age, as a PR row's does, keeps counting it. A row that drew no line above its buttons when its press went out keeps its done status, such as "✓ Discussed", under them until the row closes or loses its buttons. The panel passes whether the row shows buttons, where the other looks pass whether it is open, so a settled row's press status also goes under its Undo. A press ends when a publish names it as the last press the host handled, or shows its row changed. A press the host found already changed gets the shared stale note. A press a host took reads as not confirmed when the host's last press is a later one, or 15 seconds after its file was written. One that no host took by then, the look takes back out of the folder, so it cannot apply later, and it reads as not applied. A press on a row with a press out, or with no session to send to, is not sent, and its row says why. | The look reaches the host only through files and terminal labels, so a press waits for the next publish. The panel draws a settled row's Undo as a button under its line, so a status above it would move it while its press is out. The panel draws a status that follows the title on its own line, where the other looks put one that is not a failure in the title's text. Dropping that line at a press, or adding one when it ends, would move the buttons. A host's apply can fail without a publish, so the look cannot know more than that the press was taken. | `herdr/src/press-queue.ts:PressQueue`, `herdr/src/out.ts:settleOuts`, `herdr/src/out.ts:drawOuts`, `herdr/src/held-line.ts:holdLinesAbove`, `herdr/src/paint-blocks.ts:rowEl` |
| Reply while its send is out | The draft stays through the press, as in the Codex tab, and after it until a publish shows the host finished the press. The look then deletes it if `isPressConfirmed` passes and its words are unchanged. If the row's field is open, the look waits until it closes. A later send on the row replaces an earlier one's answer. Reply on that row opens the kept words meanwhile. | The look learns how a press went only from the session the host publishes. `lastPress` names the press and says whether it was stale. The row's delivery says whether its send failed or went unconfirmed. A press that saved no new last press on its row was not sent. A mod host finishes a press only once its prompt enters, which can take a turn, so the draft can keep a closed row in place that long. | `herdr/src/out.ts:isSentConfirmed`, `herdr/src/press-queue.ts:PressQueue`, `herdr/src/keys.ts:withoutConfirmed` |
| Opens and copies | The look runs every copy, and every open of a link, an absolute path or a `~/` path, itself at once, and its row shows how it went. The press file carries what happened. It opens a relative path against the project folder the session file names, and sends it to the host when the file names none. | The person sees the result without waiting for a publish. A host leaves the project folder out when it has no absolute one. | `herdr/src/run-here.ts:isRunHere`, `herdr/src/run-here.ts:runHere` |
| A spent Undo | Once Undo ends, a settled row that offered it keeps Undo's place hidden until it folds. While the row's Undo press is still out, Undo stays drawn out there, since the shared plan drops it when its time ends. A row whose message is still queued `QUEUED_AFTER_MS` after Undo ended waits for the agent, so it drops that place then, and the look draws again at that moment. A PR's block keeps no place for a spent Undo. | The panel draws Undo on a line of its own under the row's status, where the Codex tab draws it beside the title. A hidden Undo is an empty line, and a row that waits for the agent can stay for minutes. The host sends an answer or Fix held for Undo when Undo ends, so a row the agent takes at once still folds in one move. | `herdr/src/draw.ts:undoButtons`, `herdr/src/draw.ts:undoPlaceEndsAt`, `herdr/src/out.ts:drawOuts`, `herdr/src/screen.ts:screenOf` |
| Motion | Every change of a block's height moves on a spring with no overshoot, `HEIGHT_SPRING` in `hooks/springs.ts`, and every fade runs over the shared lengths: a row opening or closing, a status line coming or going, buttons, the reply field, a PR's order lines. Each block's content sits in a box at its measured height. When the content changes, the box keeps its old height for one draw, while the size callback measures the new one, then glides to it. A row's panel, its body and buttons, fades in as it opens and out as it closes. A closing row keeps its last panel drawn without clicks while it fades, and its box leaves the panel's height out. A row's title sits in its own box, one line high unless the row is open, and the lines under the title glide with that box. As a row opens, its title wraps in the first frame and its box glides to the wrapped height. As a row closes, collapses or settles, its title drops to regular weight at once and keeps its wrap while the box glides to one line, clipping the lines under the first. The ellipsis replaces the wrap once the box rests, so only the end of the first line changes then. When the selection moves, the closing and the opening row start in the same draw, so the rows below them move once. Every block, a heading or a fold as much as a row, springs its height open and fades in over the shared enter time as it enters, and springs shut and fades out over the shared exit time as it leaves. A leaving block stays drawn until its spring comes to rest. A row selected as it enters keeps gliding to its open height. A fold's blocks enter as it opens and leave as it shuts. A leaving block stays after the nearest block above it that is still drawn. The space above each block is a box of its own whose height springs. It is measured from the last block above that is not shut, so a block that enters starts with no space and a block that leaves ends with none. A move that turns back goes from where it is. The tab bar, the banners and the trimmed-session note above the list glide the list down or up as they change height: a tab bar that wraps to another line in a narrow pane, or a banner that comes or goes. Their words appear and go with the height, without a fade. A newly shown tab, Help page or session draws at rest. A box whose height changed with its width, as when the pane is resized, takes its new height at once, even mid-move. A leaving block's buttons, text field and fold stay drawn but take no clicks. A block that takes another block's id, as a dismissed PR's block after Undo, is that block in another form, so it glides between the two forms. Motion always runs. | The Herdr app draws natively and has springs of its own, and a spring eases in and out where a fixed ease-out reads as stiff. It does not overshoot, since a box clips its content and an overshoot would show blank space under its last line. Opacity keeps the shared fades, since an opacity spring could overshoot past full. A spring has no fixed length, so a block stays drawn until its spring has come to rest, which `hooks/springs.ts` computes from the spring's numbers. gpui-kit animates only a later change of its target, and only between heights the mod sets, so every box draws at a height measured with the size callback, never at `auto` during a move. A fold's shut blocks are not drawn, so they are measured in the draw that opens the fold, not before: drawing them hidden would put them in the keys and the accessibility tree. A tab or Help page is a new page with nothing in common with the last one, so it draws at once, as the Codex tab draws a new tab. A width change rewraps every block at once, and a glide would make the text lag the pane. The banners are not list blocks, so they do not keep their last words while they go. A closing title drops its weight with the selection's background, so that the cut changes only the end of the first line. The Codex tab keeps a closing title semibold until its close ends. Padding cannot glide, so every distance that can change is the height of a box whose spring is declared in every draw: each space, each block's content and each row's title. A move that starts while another glides then starts where every box is drawn. The Herdr app tells a mod no reduced-motion setting. | `herdr/src/motion.ts:moveRows`, `herdr/src/paint-space.ts:spacedEls`, `herdr/src/paint-space.ts:fitEl`, `herdr/src/paint-blocks.ts:rowEl`, `herdr/src/heights.ts:Heights`, `hooks/springs.ts:HEIGHT_SPRING` |
| Tab widths | A tab whose count widens, or that gains or loses a count, takes its new width at once, and the tabs after it move sideways in the same draw. The Codex tab glides them. | gpui-kit animates only values the mod sets, and a tab's width is its text's width, which the mod does not set. | `herdr/src/paint-chrome.ts:tabsEl` |
| Running marks | A running mark keeps its row's color and fades from 1 to 0.3 and back every `RUNNING_PULSE_MS`, as in the Codex tab. It always fades. | The Herdr app tells a mod no reduced-motion setting. | `herdr/src/paint-blocks.ts:markEl` |
| Help | A circled question mark in a tab at the right end of the tab row, opposite the four tabs, opens Help in place of the tab. While Help shows, that tab is the selected one and the four tabs are not, and a press on it or on any tab leaves Help. Help lists the keys, then the marks, and no tab symbols. The inbox build the host published sits at the right end of the Keys title, in the theme's code font. A key or a mark sits in the left column and its words beside it, in a column every line shares. | Herdr draws the pane's header from the layout's header mod, and a mod pane cannot add a button to it. A footer would cost a row. The look always names its tabs in words. | `herdr/src/draw-help.ts:helpBlocks`, `herdr/src/paint-chrome.ts:tabsEl` |
| PR titles | A PR's title wraps in its own column, with its number muted at the line's right end. In a pane under 280 px, the number leads the line under the title instead. Where the PR stands, with its reasons, goes on the line under the title. Each of its parts moves whole to the next line when it does not fit, so a wrapped line starts at the edge. The Codex tab runs the number, the title and where the PR stands as one paragraph. | gpui-kit has no inline text span, so the title cannot run into the next text the way a paragraph does, and the status line cannot wrap as one paragraph. A number at the right end lines up like an age without tabular figures, which gpui-kit lacks. | `herdr/src/paint-blocks.ts:prEl` |
| Type and layout | Every gap, padding and inset comes from the shared scale in `hooks/layout.ts`, a 4 pt unit, as every look's does. The panel keeps `EDGE_PT` (16) on each side, and the tab row, banners, PR titles, ages, Help's section titles and rule ends sit on it. A mark sits at the start of a `MARK_PT` (24) column that begins at that edge, so text after a mark starts at 40 px. A Finds group's heading starts there too, after its mark, in line with the rows under it. A heading with no mark, such as a PR's group titles and Help's sections, starts at the edge. Questions and Tasks take a mark like Finds' groups do. Help lists keys and marks in one pair of columns: a key or a mark starts 24 px in from the edge (`HELP_INDENT`, one nested step), under its section's title, and its words start 36 px later (`HELP_COLUMN`: the widest key, about 28 px and allowed 32, plus 8 px), at 80 px. The Status tab's goal and head start at the edge. Text with no marks under it, such as a PR and the PR order, starts at the edge. A nested item's marks start where its parent's text does, 24 px in. A PR's threads and checks hang their marks at the edge under its title. A title's detail sits on the line under it, with no gap. Buttons sit `CONTROL_GAP_PT` (8) under the text above them. A heading sits `HEAD_GAP_PT` (8) above what it heads. Two one-line items sit `LIST_GAP_PT` (4) apart. Status items with more than one line sit `ITEM_GAP_PT` (12) apart at the top level and `CHILD_GAP_PT` (8) apart under one parent. A closed row or fold pads `ROW_PAD_PT` (2) inside its box, and an open row `OPEN_ROW_PAD_PT` (6). Sections sit `SECTION_GAP_PT` (24) apart, with a rule, where there is one, in the middle. The tab row keeps 8 px under its tabs. The list starts 16 px below that, so its first block sits 24 px under the tabs, and it ends with 32 px under its last block. A banner or the session note sits 24 px under the tabs too, and 16 px under a banner above it, where the shared `BANNER_GAP_PT` gives the other looks 8. A fold's label starts at 40 px, with its chevron 4 px after it. Headings and a PR's reasons use a plain " · ". Buttons and tabs are 28 px high, with 8 px between two buttons and between two wrapped lines of them. Quiet buttons have no side padding, and the goal's Edit and Remove have no dot between them. | Pete picked the 40 px text column from the three systems in the panel's type study, and the 4 pt scale from the spacing plan's three. He asked for the tab row on the panel's own padding, for no empty mark column on the PRs tab or beside the Status tab's goal, and for margins in proportion across the tabs. A banner takes the panel's 16 px between banners so it lines up with the list under it. | `hooks/layout.ts`, `herdr/src/paint-theme.ts`, `herdr/src/paint-space.ts:gapBetween`, `herdr/src/paint-blocks.ts`, `herdr/src/paint-chrome.ts:tabsEl` |
| Scroll edges | The list fades into the pane's background over its top 16 px and its bottom 32 px. The fades always draw. At rest they lie over the list's empty padding, so they show only where rows scroll under an edge. The Codex tab draws no fade. | gpui-kit cannot tell a mod how far a list has scrolled, so a fade cannot switch on and off with the scroll. A mod has no CSS, so it draws each fade as a gradient path. | `herdr/src/paint-chrome.ts:scrollFadeEl` |
| A press that is out | A button whose press is out keeps its size, loses its fill and border, and draws its label muted at half strength. It shows no hover or pressed change and takes no click. The Codex tab draws the whole button at 40% opacity, so a filled button that is out reads as a grey block. | A filled button at 40% opacity drew the eye away from the buttons that still work. | `herdr/src/paint-blocks.ts:buttonEl` |
| A question's earlier answer (`earlier-answers`) | The line draws in one muted tone, with the answer in the same weight as the rest. The Codex tab draws the answer bold, as an option's label. | gpui-kit has no inline text span, so one word of a line cannot take its own weight. | `herdr/src/draw.ts:rowBody` |
| A row's title tint (`title-tint`) | The row's title and mark take the theme's blue on a new row, or the tone of how it closed on a settled row, at `TITLE_TINT` of its strength, then steps back to its own color in `NEW_STEPS` colors, each mixed into the title's color as one opaque color. The look draws again at each step. The look finds new rows only in the tab it shows, so a row's clock starts when it arrives there, or when Help closes over it. Reduced motion is not read. | GPUI glides no text color and its types expose no reduced motion setting. The look keeps the rows of the tab it shows, and no other tab's. | `herdr/src/paint-title-tint.ts:titleColorOf`, `herdr/src/keys.ts:withDrawnRows` |
| A font weight change (`weight-transitions`) | The selected tab, an open row's title and a changed milestone's name take `font_semibold` in one draw. | gpui-kit's `font_weight(n)` changed nothing in the Herdr app: a label at 400, 450, 500, 550 and 600 measured 388, 387, 388, 387 and 388 px wide in a 3000 px capture, with the same glyphs, while `font_semibold()` draws semibold. So the look has no intermediate weight to step on its frame timer, as it steps a title's tint. Filed as [herdrdev/herdr#6037](https://github.com/herdrdev/herdr/issues/6037). `transition` and `spring` also take only `opacity`, `width`, `height`, `left` and `top`. | `herdr/src/paint-chrome.ts:tabsEl`, `herdr/src/paint-blocks.ts` |
| A question's Holds up line | Draws it only on the open row, as the last branch of the row's tree (`asks-tree`). A collapsed row draws one line, so its Holds up line does not show. | The Codex tab, the terminal and omp draw a collapsed row's Holds up line plain under its title. The Herdr pane draws a row's body only while the row is open, and a collapsed row stays one line high so its height can glide. | `herdr/src/draw.ts:rowBody` |
