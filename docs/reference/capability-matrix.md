Part of [Platform reference](README.md).

A cell says what the platform lets the inbox do in that client, by the sources. It is not what the inbox does today. Where today differs, a note says so. Each cell links to the section that backs it. The drawing cells for VS Code and phones follow the public docs. The engine types already define `vscode` and `mobile` surfaces with their own element tables, so those cells may change ([mods](claude-code-mods/disagreements-engine.md#where-sources-disagree-engine-and-api), row 3).

Notes:

1. Docs: "SSH sessions support permission modes, connectors, plugins, and MCP servers". Whether the mod's hooks run or draw there is unverified. The plugin must be installed on the remote host; the local `CLAUDE_CODE_PLUGIN_DIRS` does not apply.
2. A user-installed plugin does not reach a cloud session. Only server-managed or claude.ai-synced plugins do, and nothing a mod draws appears there.
3. Chat ignores plugin hooks, mods and local MCP servers. Cowork loads hooks and local MCP servers when it runs on the person's machine; whether it runs mod `modules` is unknown. A local MCP server in `claude_desktop_config.json` or a `.mcpb` extension reaches Claude mode.
4. Hooks run in the VS Code chat panel and nothing draws. Today the inbox's gate keeps it off there, so it makes no model call.
5. The mod runs in the session on the host machine and draws only in that machine's terminal. A phone or claude.ai viewer sees no band or pane. Prompts typed there arrive with origin `bridge`, which the inbox counts as the person's words.
6. Codex runs a plugin's hooks only after the person trusts them. Before 0.164.0, the trust covered each hook definition, and a changed definition was skipped until trusted again. From 0.164.0 it covers every file in the plugin, so after any update every hook fails with `plugin contents changed; hook approval required` until trusted again ([codex-plugins](codex-plugins/checked-0.164.md#checked-against-codex-01640), "Checked against Codex 0.164.0").
7. Claude: `$.model.complete` uses "the user's plan or API key", and `sonnet` resolves to Sonnet 5.5, 4.6 or 4.5 by provider. Codex: `codex exec` reuses the person's saved Codex sign-in; it measured 21.5k input tokens per call, 12.5k at best.
8. The inbox's cached call needs engine 2.1.292. The app's sessions ran 2.1.293; its 2.1.289 copy is older.
9. A pane docks beside the transcript in a fullscreen terminal from 110 columns. Otherwise it is a framed region above the prompt. A pane the mod opens on its own waits for 144 columns, or 110 once the person has opened that pane.
10. Live: the pane opens docked (`placement: 'dock'`) and the person can resize it. Its `bodyColumns` went from 36 to 69 in one session. The band's `maxRows` was 12.
11. The thread tab comes from the Codex-only key `_meta["openai/ui"].entrypoints`. It opened live from this repo's local plugin.
12. Live: native buttons draw and clicks work, but a `Button`'s `hotkey` does nothing in a focused desktop pane. So the inbox's hidden hotkey `Button`s and its j and k keys do nothing on desktop. Whether `keybindings.json` applies there is unchecked.
13. Not covered by any of the four files.
14. Live: `$.prompt.submit({ text, asUser: true })` starts a turn at once, with origin `plugin` and `asUser: true`. `$.prompt.read`, `fill` and `suggest` do nothing headless.
15. A press from the inbox server through `codex queue` arrived as a plain user message (live). A tab's own `ui/message` arrives wrapped as untrusted input. A press from the tab in the desktop app is not yet confirmed end to end.
16. Redraws are "Throttled to 10 a second, or 30 in the terminal for the visible pane, the expanded band, and the hint line under the prompt". Inference: 10 a second on desktop.
17. Model tool calls carry `x-codex-turn-metadata`, tab calls carry `_meta.thread_id`. In a forked chat, `sessionOf` reads the root's `session_id` first and may route a press to the wrong chat (inference, not checked).
18. Where: Claude clients write `$.store` to `~/.claude/plugins/store/<name>_<source>-<hash>.json`, one file per plugin id, shared by all sessions, 4 MiB cap, no atomic update. The Codex plugin keeps one JSON file per session under `~/.codex/plugins/data/inbox-inbox` with an mkdir lock. A Claude-mode view's own storage is per conversation, so state would live in the server.
19. The engine types mark `$.process` "CLI only", but in a local Code-mode session `git` and `gh` ran (live). `gh` used the keychain sign-in, and `PATH` matched the login shell's. The app passes only `PATH` and a fixed set of variables from the shell profile, so a profile-only `GH_TOKEN` may be missing. VS Code is unchecked.
20. The Anthropic-hosted GitHub proxy returns 403 to GraphQL, which the inbox's PR block uses.
21. A local stdio MCP server is an ordinary process on the Mac.
22. The inbox's MCP server runs `codex queue` and `codex exec` (live). Whether hooks and MCP servers run inside Codex's sandbox is undocumented.
23. Live: on desktop a mod turns on at `session.attach`, and the first prompt arrived 20 ms before the tool finished registering. The turn started 70 ms later, and Claude called the tool in it. One run, so the margin is not a guarantee. Where the guard loads and managed settings set `allowedMcpServers`, the guard's source refuses the inbox's `$.tool.register` calls in every client.
24. `default_tools_approval_mode: "approve"` in the plugin's `.mcp.json` skips approval (live). It is documented only for the person's own `config.toml`.
25. Inference: the terminal surface is wherever `claude` runs, so a terminal over SSH draws, and that machine's `~/.claude` holds the store.
26. URL connectors are called from Anthropic's cloud, so they cannot reach `localhost`. Only the desktop app runs a local server.
27. Cloud chats run on a remote environment without the person's local processes, so the local hooks and stdio server cannot run there.
28. `claude plugin test` runs with no session. It can mount a drawing for `desktop`, `vscode` or `mobile`, but it checks the tree, not how an app paints it. The repo's desktop tests assume prompt origin `sdk`, which is not an observed value.
29. ext-apps basic-host cannot run a stdio server. The MCP Inspector's Apps screen can spawn one, but its Apps examples are HTTP only.
30. The repo's own Codex tests run in `scripts/check.sh:codex tests`. No Codex host harness is documented; hook checks in this repo used live `codex exec` runs.
31. A local session, not WSL. In the desktop app's WSL sessions "plugins aren't available", so the inbox does not load there ([mods](claude-code-mods/surfaces.md#where-mods-run-and-draw)).
