# Live checks on omp 18.18.9

Checked on 2026-11-18 on the development Mac with omp 18.18.9 (the newest 18.18.x), installed with `bun add @oh-my-pi/pi-coding-agent@18.18.9` into a scratch folder. Each session ran in tmux as `env -i HOME=<fresh folder> PATH=<…> TERM=<…> XDG_STATE_HOME=<fresh folder> OPENROUTER_API_KEY=<token> omp --no-extensions --model openrouter/anthropic/claude-haiku-4.5 -e <event logger> -e omp/dist/host.js`. The event logger wrote `pi.events` frames and extension events to a file. The Mac has no Anthropic sign-in in omp, so the agent ran on Haiku 4.5 through OpenRouter. The inbox's own calls used the Sonnet that omp offered through OpenRouter. This answers issue #367.

The OpenRouter key refused some concurrent subagent requests with a 402 for credits. Those subagents ended `failed`, which still exercised the lifecycle frames.

## Results

- **A subagent that `/restart` continues shows as running, and ends when it finishes.** Two subagents ran `sleep 90`. `/restart` sent each an `aborted` lifecycle frame, then a new `started` frame for the same id. The inbox's saved rows read running after the restart, with a new start time, and ended with `completed` at about 91 seconds. No row stayed ended while its subagent ran. `omp --restore` was not run.
- **Subagent rows start, progress and end with `task.workerThreads` at its default and at 0.** With the default of 4, three concurrent subagents sent `started`, many `progress` and `completed` or `failed` frames, and each row got a start and an end time. With `task: { workerThreads: 0 }` in `config.yml` the same held.
- **Enter on an empty editor forces a queued press, and the text reaches the agent once.** An Explain press was queued during a foreground `sleep 100`. Enter ended the held run after 26 seconds: the bash call returned, `agent_end` fired, and `before_agent_start` and `agent_start` ran for the press text, once. This differs from 18.12.3, where a queued follow-up ran in the same run. The saved state read `turnsStarted: 3`, `turnsApplied: 3`, `ledgerState: current`, the press's delivery `arrived`, no call failure and no `overviewFailure`. The ledger and Status calls both ran.
- **A fork and a resume carry the state over once.** `/fork` sent one `session_switch` with reason `fork`. The new session's saved state matched the old one: same PRs, same six children, same turn. `/resume <id>` followed 0.5 seconds later by `/fork` sent one `session_switch` each, and made one more saved state with no repeated rows. A normal prompt after a recorded question reached the agent with one hidden `inbox` message, so a custom message still reaches `before_agent_start`.
- **`cd <dir>; cmd` is not hoisted in what extensions see.** `tool_execution_start` and `tool_result` both carried `cd src; echo gh pr create https://github.com/…/pull/1` and `cd src; herdr agent wait scout` unchanged, and `cd src && gh pr view 1 …` too. The PR linked as `petekp/inbox#1`. A fake `herdr` that slept 12 seconds gave a delegate row with start and end times 12 seconds apart.

Not seen: the Esc cancel during a press, `omp --restore`, a narrow width, the light theme, and a subagent that stays running across `omp` quitting.
