# Constraints, open questions and disagreements

Part of [Platform reference](README.md).

## Facts that most constrain the architecture and UI

1. Only the terminal and desktop Code mode draw a mod: "Drawing is narrower: only the terminal and the Desktop app show a mod's panes, bands, and replaced rows" ([mods](claude-code-mods/surfaces.md#where-mods-run-and-draw)).
2. Desktop Code mode runs the engine headless as an SDK host (live process arguments). Live: `session.start` fires with `isInteractive: false` and no surfaces, then `session.attach` with `surface: 'desktop'` about 0.1 s later. A typed prompt can arrive right after the attach, before setup there finishes. No public doc says how a desktop session starts ([desktop](claude-desktop-app/how-it-runs.md#how-the-app-runs-claude-code), [mods](claude-code-mods/surfaces.md#how-the-desktop-app-runs-a-code-mode-session-live-types-repo)).
3. Engine versions differ by client (terminal 2.1.295, desktop 2.1.293 and 2.1.289). The inbox's cached model call needs 2.1.292, and `plugin.json` has no minimum-engine field ([desktop](claude-desktop-app/how-it-runs.md#engine-versions-and-updates), [mods](claude-code-mods/plugins.md#manifest-facts-that-matter-to-the-inbox)).
4. On desktop, the render sites `ToolProgress`, `TurnDuration` and `InfoNotice` and the elements `Raster` and `Image` do not work. `$.ui.copy` works there (live), although one types comment says "a remote surface has no path yet". A `Link` is live only for `https:`; the docs also allow `http://localhost`, the types do not ([desktop](claude-desktop-app/what-desktop-draws-layout.md#what-draws-on-the-desktop), [mods](claude-code-mods/disagreements-engine.md#where-sources-disagree-engine-and-api) row 112).
5. No MCP Apps host gives a view a persistent place: the modes are `inline`, `fullscreen` and `pip`, and Codex's thread tab is a Codex-only key ([mcp-apps](mcp-apps.md#facts-that-most-constrain-the-inbox)).
6. Claude Code in the terminal does not render MCP Apps: "Claude Code calls the tool as text and doesn't render the UI" ([mcp-apps](mcp-apps/sdk-and-hosts.md#which-hosts-support-it)).
7. Nothing pushes updates into an MCP App view in any host, so every view polls; the Codex tab polls every 3 s ([codex](codex-plugins/plugin-ui-resources.md#live-updates)).
8. Claude gives an MCP server no conversation id ("Neither `hostContext` nor the tool-call arguments include a Claude-provided conversation ID"), so the Codex server's `sessionOf` would fail every call there ([mcp-apps](mcp-apps/claude-hosts.md#identity-and-instances)).
9. Each model tool call in Claude mounts a new live view and old ones stay, so presses need a server-checked target ([mcp-apps](mcp-apps/claude-hosts.md#identity-and-instances)).
10. Claude mode reaches local state only through `claude_desktop_config.json` or a `.mcpb` extension; Chat ignores plugin hooks, mods and local MCP servers ([mcp-apps](mcp-apps/claude-hosts.md#routes-into-claude-mode)).
11. Codex wraps a tab's `ui/message` as untrusted input, so presses depend on the undocumented, `#[experimental]` `codex queue` and `thread/queue/add` ([codex](codex-plugins/sessions-and-presses.md#sending-a-press-codex-queue-and-threadqueue)).
12. Codex skips plugin hooks until the person trusts each definition, and a plugin with hooks cannot be listed in the public directory ([codex](codex-plugins/hooks-running-and-trust.md#where-codex-finds-hooks-and-trust), [codex](codex-plugins/distribution.md#public-directory-and-submission)).
13. Codex's `Stop` hook cannot add model context, and hook context is capped near 2,500 tokens by default ([codex](codex-plugins/hooks-events-and-io.md#output)).
14. Codex calls its transcript format and app-server unstable, and the inbox depends on both ([codex](codex-plugins/exec-and-transcripts.md#transcripts), [codex](codex-plugins/mcp-servers.md#app-server)).
15. The per-turn update bills the person in both clients, and `sonnet` is a different model per provider ([mods](claude-code-mods/costs.md#what-the-inboxs-model-calls-cost), [codex](codex-plugins/exec-and-transcripts.md#codex-exec-the-per-reply-update)).
16. `$.store` is one JSON file per plugin id (`inbox@inline` today), shared by all sessions, with a 4 MiB cap and no atomic update. Inference: a marketplace install would be `inbox@<marketplace>` and get a separate file ([mods](claude-code-mods/api.md#store-and-state)).
17. `/clear`, `/resume` and `/branch` switch the conversation without a new `session.start`. All `session.end` work shares one bound, 1.5 s by default ([mods](claude-code-mods/lifecycle-and-events.md#lifecycle-what-fires-and-what-resets), [mods](claude-code-mods/headless-and-sdk.md#shutdown-and-the-15-second-end-bound)).
18. On Team or Enterprise sign-ins and managed machines, the guard's public source skips user mods on `prompt.compose`, `prompt.context` and `classic.*`. The inbox uses neither prompt hook: its guidance is in the `close` tool's description through `tool.describe`, and its carry card goes with the first prompt through `prompt.submit`. The guard skips its `classic.SessionStart` reload, so the mod reloads at the first prompt after `/clear` or `/resume`. When managed settings set `allowedMcpServers`, the same source refuses `$.tool.register`, so `record` and `close` would not exist while the band still draws. This is from the guard's main branch at `684800b` ([mods](claude-code-mods/admin-policy.md#what-the-guards-source-skips-not-in-the-docs)). Live on desktop 3.6556.2 with a managed settings file, the guard skipped only `classic.SessionStart` on a build with main's code, and `record`, `close` and a pane press worked ([desktop](claude-desktop-app/live-checks.md#live-checks-on-desktop-365562)). `allowedMcpServers` was not tested.
19. Every platform already shows which session waits on the person (Claude's agent view and `claude agents --json`, the desktop app's Projects, Codex's Activity view), so the inbox's distinct value is item level ([mods](claude-code-mods/sessions-across-apps.md#claude-agents---json-the-supported-session-list), [codex](codex-plugins/exec-and-transcripts.md#the-desktop-apps-own-attention-features)).
20. Orgs can turn the inbox off. A plugin installed from GitHub "counts as a user's, even when managed `enabledPlugins` enables it". So managed `allowManagedModsOnly`, `allowManagedHooksOnly` or `disableAllHooks` stops it. Only a directory marketplace that device management copies to every machine counts as the org's ([mods](claude-code-mods/admin-policy.md#what-counts-as-the-organizations-mod), [mods](claude-code-mods/security-and-settings.md#what-can-turn-the-inbox-off)).
21. The inbox can vanish, and the person sees only a missing band. Causes: three hooks-worker crashes, which unload every non-built-in mod until `/reload-plugins`; `--safe-mode` or `--bare`; an untrusted folder; Anthropic's remote rollout switch; and the org policies in 20. For an installed mod, only the worker-crash line reaches the transcript. Other reasons go to the debug log only, and a guard refusal follows a `loaded` line for the same mod. `claude plugin test` in an empty folder reports whether mods can load, but exits 1 even when they can (live) ([mods](claude-code-mods/testing-and-debugging.md#the-hooks-worker), [mods](claude-code-mods/admin-policy.md#how-a-refusal-shows), [mods](claude-code-mods/testing-and-debugging.md#troubleshooting-and-the-debug-log)).
22. The band is shared. A mod's band tree "replaces what the mods after yours draw there" unless it includes `await next(e)`, and the inbox's band does not (`hooks/register.tsx:on('ui.render', AbovePrompt)`). The built-in `cc-plugin-you-should-know`, off by default, also "shows you a note above the prompt" and spends model calls. How the two share the band is unknown ([mods](claude-code-mods/what-a-mod-is.md#built-in-mods), [mods](claude-code-mods/drawing.md#drawing-render-sites)).
23. Desktop Code mode has no `/plugin install`, so a desktop user installs from a shell at user scope, which the app's local sessions read. With no `version` in `plugin.json`, the installed version is a commit SHA, so commits that touch only `codex/` likely count as updates too. Auto-update is off by default for a custom marketplace ([mods](claude-code-mods/plugins.md#install-by-app), [mods](claude-code-mods/plugin-updates-and-controls.md#versions-updates-and-the-cache)).
